## 2. 契约（逐条可对照）

下列细则是本卡补充裁决，不声称 SAD 已逐字规定实现。遵守 C01/C06/C07/C08/C10/C12/C13：领域纯函数；模型不控制中断；无新依赖；gate 节点无文件 / DB / 审计副作用。

### 2.1 现有端点与三态响应

复用带令牌的 `POST /api/v1/meetings/{id}/gate/{gate}/decide`，gate 只接受 G2/G3（延续大小写兼容）。请求：

```json
{"decision":"edit","operator":"刘秘书","checkpoint_id":"ckpt-current","payload":{"topics":[{"title":"三季度预算执行情况","refs":[]}]},"comment":"修正议题名称"}
```

此例仅示字段形状；真实编辑保留当前条目的其他字段与 refs，不以空 refs 覆盖已有证据。checkpoint_id 为新增请求字段，来自现有 GET meeting 的 pending_gate 中补出的字段；**这是既有响应增补，不是新端点或 PipelineState 字段**。后续 HTTP 调用必须携带；缺失、gate 不匹配、无登记记录的过期请求均报统一信封 `ok=false, code=E4001`，在校验失败时不推进、不写成功决策。禁止偷偷用“当前检查点”代替客户端令牌，否则无法防旧请求。已有登记的重复请求按 §2.5 现状返回。

成功 data 保留现有键，增补 from_checkpoint 与 transition_state：

```json
{"resumed":true,"from_checkpoint":"ckpt-current","transition_state":"generating","next_state":"G3_awaiting","status_label":"待审定纪要","rerun_nodes":[],"pending_gate":{"gate":"G3","checkpoint_id":"ckpt-next","payload":{},"risk":"medium","evidence":[]}}
```

pending_gate 沿用现有其他字段，终态为 null。SAD 示例 next_state=generating 是逻辑迁移；当前同步 runner 跑到下一中断，故 **next_state 保留实际停点**，transition_state 明示瞬间目标：G2 approve/edit→generating、reject→extracting；G3 approve/edit→exporting、reject→assembling。不为复制示例引入异步任务或撒谎返回运行态。

`rerun_nodes` 定义为**返工的已完成业务节点**，不含 gate 重放、不含首次执行的下游。approve/edit 恒为 []；G2 reject 为 ["extract"]，G3 reject 为 ["assemble"]（到达重做上限而未执行目标时不得伪造成功）。普通生成校验重试另行观测，不当成用户驳回返工。

计数证据必须来自真实 on_node 回调，不能硬编码数组冒充计数：同一 runner 的 resume 前后快照断言 transcribe/extract 差为 0；API 每次新建 runner，断言本次实际 transcribe/extract 调用为 0，再独立检查响应。另用真实图 U-ST-04 证明 reject 的 extract +1、transcribe 不变；G3 reject 的 assemble +1、extract/transcribe 不变。允许下游首次执行，不能为制造 [] 跳过成文。

### 2.2 edit 的载荷、校验与 reject 区别

- approve 不注入载荷；为兼容现有行为，非 edit 的 payload 忽略。reject 清理目标及下游旧产物后按既有 redo 边执行；不接受“先写入编辑再 reject”的混合操作。
- edit 外层 payload 必须非空对象，仅含该 gate 白名单字段。**在服务入口用 Pydantic 校验**（离线现有依赖），未知顶层键报 E4001，不再静默丢弃；内部已知只读条目元数据允许随整条回传，但必须与基准相等。校验须在 resume 前完成，图内保留防御检查。
- G2 允许 topics/resolutions/action_items 的非空子集；每个值必须 list[dict]，传入列表整体替换对应列表，未传列表保持原值；不按数组位置合并部分对象。允许列表清空，但最终三列表不能全部空，否则 E4003、不恢复。条目形状以当前图为准：topics 的 title（非空字符串）/discussion/readings，事项的 text（非空字符串）/owner/deadline 可编辑；readings 必须 list[str]，其余可编辑文本必须 str（deadline 可沿已有数据保留 null）。owner 空白规范为「暂无」。无 id 的条目以本检查点数组索引定位；已有 id 不许更改、重复或删除。
- 最小方案只修正、整闸口确认既有条目；不新增 / 删除 / 重排条目，不改 topic 关联。Electron 提交完整的被改列表并保留未改项。refs/source_refs/source_quote、时间戳、confidence、risk、内部路径、验证问题只读，不许把证据洗成更高置信；未知已有元数据原样保留、不得新增。SAD 示例 name→title 的输入适配必须显式，禁止同时接受两个名字却默默任选一个。若事项以 topic 标题字符串关联，改标题时服务按本轮原索引 / id 同步重写原来精确匹配该标题的关联字符串；不让用户改归属、不运行 extract。原标题重复或关联有歧义则 E4001 要求人工核对，不猜测迁移。
- G3 仅允许 minutes_markdown 非空字符串；不允许修改 topics、minutes_structured 或 validation_issues。编辑只换措辞并直接进入 export；结构化版本同步、完整后置校验仍属 T2-04 / 阶段 D，不假称已有。
- 同一内容的 edit 可作为确认（changed_keys=[]），仍应记录 decision=edit；不得变成 reject。参数错误不计入成功审批，且保留原 checkpoint 可供修正后重提。

### 2.3 四要素、低置信与“只显示待确认项”

后端负责权威状态、证据取值与可编辑字段校验；Electron 负责展示、草稿、筛选和输入体验，不能靠 CSS 隐藏就宣称数据已确认。

复用 GET `/meetings/{id}/topics` 三列表，服务层给 topics 添加展示投影（仍在既有 list[dict] 内，不新增 PipelineState 顶层键）：title、extracted（议题及关联事项的确定性展示）、raw_text、basis（含来源 segment_id/start_ms）、risk、confidence、confirmed。refs 用图引用关联现有转写分段，时间以 ms 为唯一事实、页面转成 HH:MM:SS；无依据明确显示“暂无出处，请核对”，不编造。risk 使用已有风险字段，缺失按 gate risk 兜底，缺置信标为“未提供”；有置信时 `< cfg.thresholds.asr.low_confidence` 标低置信（等于不标），提示此值是来源转写置信而非新造的抽取置信。

confirmed 必须严格布尔：现有缺省为 false；有效 G2 approve/edit 由服务层将本轮全部项写为 true，reject 后新一轮重新为 false。展示投影不回写为抽取正文，服务器写 confirmed 的状态增量仍走现有 topics 键；新字段不列入用户编辑白名单。

最小方案维持**整闸口提交**：逐条“已核对”只存在 Electron 草稿，明显标注“尚未提交”，与后端 confirmed 分开保存。过滤 predicate 为 `!(serverConfirmed || draftReviewed)`；切回“全部”能看到这些条目并继续修改。提交 approve/edit 后才成为服务器确认，刷新未提交草稿回到待确认；不声称已有跨重启逐条审批持久化。D11 已裁决不做逐条持久审批，不能用 gate decide 暗中推进整个图。

### 2.4 差异视图：算法有了，审阅对象仍需补齐

后端 `diff_versions(approved, edited)` 返回 unchanged(lines[,elided]) / changed(old,new) / removed(old) / added(new)，按空行分段，CRLF 归一；summary 四键齐全。既有 GET /diff 的 base/compare 是 **record/vN.md 的版本号**，comparable=false 表示没有基准，不是“已经比较过且无变化”。不更改其默认语义。

按 D11 新增带令牌的 **POST `/api/v1/meetings/{id}/gate/{gate}/diff`**，请求体 `{checkpoint_id, payload}`（payload 结构与 edit 相同），复用 §2.2 编辑校验并匹配当前 gate / checkpoint；错误沿用统一信封。服务端取本轮不可变系统稿投影为 base、合并 payload 后的草稿为 edited，调用现有 `diff_versions`，成功 data 返回 segments/summary。端点无状态，不写快照、决策、审计、task_state 或图状态，不 resume。G2 以固定顺序投影 title/discussion/readings 和关联事项文本，G3 直接用 minutes_markdown；不比较原始 JSON 字段顺序、不拿记录稿冒充系统纪要。

Electron 调用此端点展示“系统生成版 / 人工修改版”，不移植 JS diff 算法；只对 changed/added/removed 着色，unchanged 灰显并可折叠，默认聚焦变化段。检查点变更立即作废旧草稿，提示重新载入。服务端测试覆盖 CRLF、多行段落、新增、删除、长未变折叠，Electron 静态契约验证端点调用与渲染接线。本机无 Node，不能交付未经验证的 JS 算法移植。

为后续导出追查，提交决策时图外保存本轮基准与最终编辑快照及指纹（§2.5）；不将正文放审计。SAD §9.1 端点清单和 `tools/accept_t1_17.py` 计数在 C5 同步加 1，注明来源为本卡 D11 / Claude 规则 9 裁决；历史查询不在本卡范围。

### 2.5 超时自动拒绝、后台巡检与幂等恢复

**执行位置与节拍固定**：在 `main.py:create_app` 的 FastAPI lifespan 启动一个标准库 `threading.Thread`；由 `threading.Event.wait(60)` 每 **60 秒**巡检，启动后立即巡检一次，退出置 Event 并 join。路由构造需支持注入同一个 Runtime，lifespan 与 HTTP 共用 meeting_lock；每次任务在当前线程新建 runner / SQLite 连接，finally close，不共享连接。同步图不能堵塞事件循环。无 APScheduler、无新依赖；只支持一个后端进程，测试可注入时钟与单次 tick，禁止真实睡 72 小时。

**等待持久化**：图外服务在 start/resume 返回中断后，用 snapshot.config 的 checkpoint_id（不是临时 runner id）标识一轮；等待起点只写现有 `task_state.awaiting_since`，同步已有 status/current_node/awaiting_actor，不写 wait.json。首次时间取该中断检查点的 created_at（UTC），同轮 status/GET/tick 不刷新。重启枚举会议与持久化检查点，字段缺失时用当前检查点 created_at 补上；不能只查询 task_state awaiting，否则当前缺失数据永远扫不到。无法确定时间则保留待人工、记录运行告警，不用 now 无限续期、更不自动通过。

**到期定义**：`cfg.thresholds.gate.approval_timeout_hours` 必须为正数，当前 72；`now - awaiting_since >= 72h` 到期，UTC 比较，最大正常检测延迟约 60 秒加处理队列时间。人未访问也执行。tick 发现候选后拿 meeting_lock，重新读当前 gate/checkpoint/时间，仍匹配且未决定才提交 `decision=reject, operator=system, auto=true, reason=timeout`。不直接 UPDATE status 伪造退回、不使用 approve 兜底。G2 实际执行 extract 并重新到 G2，G3 实际执行 assemble 并重新到 G3；验收观察 extracting/assembling 过渡或节点回调，不能要求同步调用结束仍停在 extracting。

**持久化决策防重（人工与巡检共用一个服务）**：

1. 在 meeting_lock 内读取当前 gate/checkpoint 及已有登记决策；无记录时先校验请求与当前检查点。将编辑前后快照、字段路径、指纹及自由 comment 写入会议目录 `gate/<checkpoint>/snapshot.json`（checkpoint 由内部 ID 安全编码），临时文件 + 原子替换即可，不需 fsync。快照先写，DB 事务后提交；残留孤儿快照无害，不据其恢复或认定决策成功。
2. 幂等键使用现有 `make_idempotency_key(task_id, "gate_decision", {"gate":gate,"checkpoint_id":checkpoint_id})`，**不含 decision/operator**，保证同轮人工和系统争用同一个键。在 infra 使用同一 SQLite 写事务唯一 INSERT idempotency_record（result_ref 存规范化决策的 JSON）与 INSERT gate_decision 审计链行一并提交；沿用链哈希与 safety 校验。现有 AuditLogger.log + put 分开调用不满足原子性，不能原样照抄；不加表、列或索引，不建 intent / 结果文件。
3. 本轮获胜者用登记决策执行 `Command(resume=...)`。重复请求按当前现状返回，不再登记、写审计或把旧决定发给新 checkpoint；不承诺重放原响应。仍挂在同一 gate/checkpoint 且已有登记时，走下一步恢复；冲突决定报 E4001，无记录的旧 checkpoint 报过期。
4. 恢复仅处理“已登记但未 resume”：当前闸口仍挂在登记的同一个 checkpoint 上，就用已登记决策 resume。若 checkpoint 已前进则什么都不做，不向新闸口发送旧决定，不补结果文件，不引入 invoke(None) 续跑机制。文件、DB、LangGraph 不在同一事务，其余崩溃窗口不承诺 exactly-once（§5）。

审计 success 的精确定义为“本轮有效决定已持久化接受”，与图是否完成下游分开；下游失败依然保留获胜登记决策，不能为了重试插第二条成功决策。审计写失败则不 resume、不算成功。审核链写事务需与所有现有审计写入遵循同一串行机制，不能仅靠每会议锁保护全局链。

**重复超时告警**：查该 meeting 全历史 `gate_decision` 中 `auto=true && reason=timeout && result=success` 的不同 checkpoint 数；第 **2 次及以后**提示“同一会议多次审批超时，建议检查流程设计”，不受重启归零影响。将累计次数、flow_design_warning=true 记入本次既有 gate_decision detail，并输出 warning 日志；不抛异常杀巡检线程、不新增 action。保留现有 MAX_GATE_REJECTS=3 的失败兜底，达到上限必须人工介入，不能变成自动 approve。该计数现为共享 `_gate_rejects`，本卡不擅改为分 gate 新状态。

### 2.6 审计 exact detail（F4.5 与 AUD-05 同时满足）

每轮有效三态决定仅一条 `action=gate_decision, target_type=meeting, target_id=meeting_id, result=success`；谁 / 何时取 audit 行 operator/created_at，不信任客户端时间。detail 固定形状如下（例为 edit）：

```json
{
  "decision":"edit","meeting_id":"m-001","gate":"G2",
  "checkpoint_id":"ckpt-current","from_node":"gate_g2","to_node":"generate",
  "auto":false,"reason":"human",
  "changed_keys":["topics[0].title"],
  "changed":{"topics[0].title":{"op":"replace","old_sha256":"<64 hex>","new_sha256":"<64 hex>","old_chars":6,"new_chars":10}},
  "before_sha256":"<64 hex>","after_sha256":"<64 hex>",
  "snapshot_ref":"gate/<encoded-checkpoint>/snapshot.json",
  "comment_present":true,"comment_sha256":"<64 hex>",
  "timeout_count":0,"flow_design_warning":false
}
```

- changed_keys 按字段路径排序；changed 同键。G2 从规范化前后条目逐字段比较，只列实际修改；G3 路径 minutes_markdown；不因 server confirmed 改动而伪称用户改正文。approve/reject 的 changed_keys=[]、changed={}；before/after 是决策载荷前后快照的规范化 JSON SHA-256，reject 不将清空下游算成人工编辑。
- 摘要值仅含 op、前后指纹及规范化 JSON 字符数（old_chars/new_chars），**不含旧新正文、转写原文、source_quote、自由 comment**。comment 只记存在性和指纹，全文随受控快照保存；不能截短正文后冒充摘要。用于 diff 与人工追溯的快照包含原值、新值和字段路径，沿用会议目录访问和保留规则，不作为审计明文导出。这样可定位“改了哪个字段、是否变更、改前改后对应哪份”，而不违反 AUD-05。
- timeout 使用 decision=reject、auto=true、reason=timeout、operator=system；另增 `approval_timeout_hours/awaiting_since/decided_at`（UTC ISO 字符串）及 timeout_count/flow_design_warning。人决策 reason=human，timeout_count 是已发生超时累计值。
- 禁止随意新增 gate_timeout/flow_warning action：ACTIONS 已有 gate_decision。helper 当前会省略空 changed/false auto，且无上述全部字段，后续需扩展或统一服务构造 exact detail，经 safety 检查后入链；不能声称 helper 现状已满足本文。
- AUD-01/02 触发器、AUD-03 链校验、AUD-04/08 真流程覆盖、AUD-05 无正文、AUD-06 导出完整性、AUD-07 时间/人员/类型检索全部沿用。不为“修正日志”开放 UPDATE/DELETE。

## 4. 验收标准（原 6 项，逐项编号）

1. **三个按钮功能正确，edit 响应 rerun_nodes=[]（F4.1 / V5）**：真 HTTP 分别完成 G2/G3 approve/edit/reject；检查响应 from_checkpoint、实际 next_state 与过渡状态，编辑白名单生效、错误不推进。approve/edit 返回 []，reject 只列目标；非当前 gate、旧 checkpoint 不得影响新一轮。Electron 按 §3 静态 + 人工分开报告。
2. **edit 的 transcribe/extract 执行计数不变（U-ST-02/03/04、IT-04/05）**：真实回调统计 G2 approve/edit 前后差为 0，edit 修改进入最终稿；G2 reject extract 恰 +1、transcribe 不变；G3 edit assemble 不重跑，G3 reject 仅 assemble 返工。不得只看数组为空或 mock 掉节点。
3. **差异只高亮变化段落、未变灰显（F4.3）**：系统稿与人工草稿使用同一 checkpoint；新无状态 POST diff 复用 Python 算法，空行段落、CRLF、多行、增删改、长未变均有确定性向量且不写数据；旧 /diff 记录稿契约回归通过。Electron 静态证明渲染接线，实际高亮 / 灰显 / 折叠人工确认；没有 UI 实测不能标全项完成。
4. **只显示待确认项，已确认隐藏（F4.2/F4.4）**：混合 confirmed=true/false 的权威数据及未提交 draftReviewed 数据验证 predicate，关闭恢复全部；默认开启、低置信区分、四要素来源与时间戳正确。刷新不把草稿当已提交；D11 已裁决不做逐条持久审批。后端数据断言、Electron 静态与人工三类证据分别列出。
5. **超时自动退回并留审计（F4.6 / IT-16）**：无请求 tick 即可触发；72h 边界、进程重启仍保留原等待时间；G2 观察 extracting 过渡及 extract +1，随后可重到 G2；G3 对称。人工与 tick 并发只接受一个决定，同 checkpoint 唯一登记、审计一条，已登记未 resume 按 §2.5 恢复；第二次超时告警按审计计数可恢复；审计含 auto/reason/时间/阈值。任何错误或上限均不得自动 approve。
6. **每次有效决策审计可看出改动（F4.5 / AUD）**：真实三态 / timeout 流程各有 gate_decision，重复提交恰一条；操作者与时间可查，edit detail 精确符合 §2.6，changed_keys/指纹对应受控前后快照；无正文 / 自由 comment 泄漏，导出可校验链及筛选。故障注入验证快照先写、登记与审计同事务及“已登记但未 resume”恢复，checkpoint 前进后不动作，其余窗口不承诺 exactly-once；不能以 helper 单测替代流程留痕。

验收脚本逐项给出自动结论、命令、计数、人工待办与 Claude 已裁决记录；六项未全部闭环前不宣称 V5 完成。上游 AUD 全套沿既有相关文件定向验证，全量测试交给外部检查循环运行。

## 7. 常见坑

1. **把 edit 当 reject**：approve/edit 显式 continue；reject 显式 redo；用真实计数及最终稿联证，不用提示词代替状态机。
2. **只排除 gate 就计算 rerun_nodes**：新下游节点不是返工；当前接口正有这个偏差。数组正确与执行计数正确要分别证明。
3. **有锁就认定没有重复决策**：锁后必须复读 gate/checkpoint；下一轮 G2 与当前 G3 都不能吃旧请求。幂等键不能包含 decision，否则人 approve 和系统 reject 各赢一次。
4. **仅访问时检查超时或重启重计 72h**：必须后台巡检，等待起点持久化且可由检查点恢复；安全默认只能 reject，重做上限也不能改成 approve。
5. **在 gate 节点里写审计 / 文件 / 时间**：interrupt 会重放；副作用放图外统一服务，并处理审计与图不在同一事务的窗口。
6. **审计只有 edit 标签，或把 before/after 全文写入 detail**：必须有字段路径、指纹和快照引用，正文留受控会议文件；不新增未登记 action。
7. **拿记录稿 /diff 冒充纪要编辑差异**：必须明确审阅对象和基准 checkpoint；按段落比较，未变灰显 / 折叠，不做全文字符红绿墙。
8. **过滤可运行就说逐条审批已落地**：confirmed 必须有权威赋值；本地已核对草稿必须标未提交，刷新语义明确。四标签出现也不能证明原文和时间戳接通。
9. **按示例字典方式读取配置或引入 APScheduler**：实际是 cfg.thresholds.gate.approval_timeout_hours；只用标准库线程 / Event，生命周期与同一 Runtime 接线。
10. **静态检查全绿就宣布 Electron 已验收，或顺手改状态 / 路由 / schema**：人工清单单列；D10～D12 已由 Claude 按规则 9 裁决，按既定边界实施（不改 PipelineState / schema，仅新增无状态 gate diff 端点）。
