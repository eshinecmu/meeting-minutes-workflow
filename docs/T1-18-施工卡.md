## 1. 目标（做完能干什么）

1. **双击 `mmwf.exe` 就能出窗口** —— 目标机不装 Python、不装 Node、不联网。
2. 交付目录的层级与部署手册 §10 附录 A 对得上（见下表）。
3. 内嵌运行时随目录走，`config/` 可外部修改（N5.2）。
4. 出一份**手工检查指引**，让非技术背景的人能自己逐条验。

### 1.1 目录映射（本卡的核心契约）

部署手册写的是 `C:/mmwf/{app, runtime, desktop, config, data}`。
Electron 的固定布局是 `<exe 同级>/resources/`，所以：

| 部署手册 | 交付目录 |
|:---|:---|
| `C:/mmwf/app` | `resources/app` |
| `C:/mmwf/runtime` | `resources/python` |
| `C:/mmwf/config` | `resources/config` |
| `C:/mmwf/data` | `resources/data`（首次启动自动创建） |
| `C:/mmwf/desktop/mmwf.exe` | `win-unpacked/mmwf.exe` |

⚠️ **`config` 必须落在 `resources/config`，不能落 `resources/app/config`。**
`settings.py::_find_config_dir` 默认取 `parents[2]/config`；应用在
`resources/app/mmwf/` 时 `parents[2]` 就是 `resources/`。
放错的表现是启动即报"缺少 config/app.yaml"，**且报错不会告诉你是层级错了**。

## 2. 关键骨架

```
tools/build_portable.py        组装脚本（两条路径）
  ├─ stage_runtime()           python 基座 + .venv/Lib/site-packages
  ├─ stage_app() / stage_tools()
  ├─ run_builder()             electron-builder 路径（常规机器用这条）
  └─ assemble_direct()         直拼路径（只复制、不删除，见 §6 坑 2）
tools/probe_electron_flags.py  打包产物启动健康度探测
tools/cdp_probe.py             用 DevTools 协议核实"界面真的渲染了吗"
src/desktop/main.js            启动参数 + 窗口沙箱（本卡唯一改动的产品代码）
src/desktop/electron-builder.yml
```

### 2.1 `main.js` 的最终启动配置（★ 本卡结论）

```js
const STRICT_SANDBOX = envFlag('MMWF_STRICT_SANDBOX');

if (!envFlag('MMWF_ENABLE_GPU')) {
  app.disableHardwareAcceleration();
  app.commandLine.appendSwitch('disable-gpu');
  app.commandLine.appendSwitch('disable-gpu-compositing');
  if (!STRICT_SANDBOX) {
    app.commandLine.appendSwitch('disable-gpu-sandbox');
  }
}
// createWindow(): webPreferences.sandbox = STRICT_SANDBOX   // 默认 false
```

（`envFlag` 是示意写法；源码里直接读进程环境变量。）

## 4. 安全取舍（必须写明，不能含糊）

本版本默认关闭了 **GPU 子进程沙箱** 与 **渲染层沙箱**。

- **为什么不用 `--no-sandbox`**：那会把**所有**子进程（含网络服务、
  utility）的沙箱一起关掉。本项目只需放开**这一个窗口的渲染层**；
  网络栈只连 127.0.0.1 回环、页面只加载本地打包文件，
  没有理由把网络服务那层也一起关。**能窄就不宽。**
- **可恢复**：设 `MMWF_STRICT_SANDBOX=1` 恢复沙箱（仅限沙箱能用的机器）。
- **依据**：本应用界面是纯表单（投递/确认/闸口/导出），无 3D / WebGL /
  远程内容，硬件加速零收益，却引入"启动即死且无提示"的失败路径。

## 5. 与 electron-builder 产物的差异（直拼路径）

| 项 | electron-builder | `assemble_direct` |
|:---|:---|:---|
| `resources/{app,config,python}` | 有 | 有 |
| `resources/app.asar` | 有 | 有（asar CLI 打包） |
| `default_app.asar` | 删除 | 不复制 |
| exe 版本资源/图标 | 已改写 | 仍是 Electron 默认 |
| 代码签名 | 未签名 | 未签名 |

内网分发按部署手册 §9.1 的哈希清单流程自行校验，因此 exe 元数据差异
不影响交付；窗口标题由 `main.js` 控制，不受影响。

## 6. 常见坑（本卡实测新增，前 8 条见 T2-01 施工卡）

### 坑 1 · 「进程活着」≠「界面渲染了」★ 最贵的一课

`--disable-gpu-sandbox` 与 `--in-process-gpu` 都能让 `mmwf.exe` **活着**、
窗口标题也查得到，但**渲染进程从未解析 HTML**（`document.title` 为空、
连 `1+1` 都算不出来）。只看进程数会得出"已经修好了"的**错误结论**。

**正确判据**：用 DevTools 协议问 DOM（`tools/cdp_probe.py`），
`Page.captureScreenshot` 拿真实合成像素。
⚠️ 注意：用 BitBlt / PrintWindow 截 Chromium 窗口**常常只截到背景色**，
不能据此判断白屏 —— 我在这上面误判过一次。

### 坑 2 · 本环境的批量删除闸门会打断打包，且**整轮粘滞**

`shutil.rmtree` 与 `fs.rm` 都会被拦（单次删除超阈值即抛错）。
electron-builder 打包前要 `rm` 输出目录、解包 Electron 时又要 `rm` 临时目录，
动辄数千文件 → 在 `extractArchive` 处硬失败。

⚠️ 更要命的是**粘滞**：一旦本轮记录过一次拒绝，**之后本轮所有删除**
（哪怕只删 1 个文件）都会回放同一个拒绝负载。
所以"那我删一个小文件绕过去"是行不通的，**必须换一轮或改用只复制的路径**。

**对策**：`assemble_direct()` 全程只复制/改名，不需要任何删除权限。
常规机器仍用 electron-builder。

### 坑 3 · 沙箱起不来是根因，不是"GPU 坏了"

第一版判断停在"GPU 子进程崩了"，打的 `disable-gpu` 一串开关**完全没用**。
真实根因是 **Chromium 的 Windows 沙箱无法初始化**：
GPU 子进程与渲染子进程都起不来。实测矩阵（12 组）见
`docs/T1-18-交付目录手工检查指引.md` §5。

### 坑 4 · `ELECTRON_RUN_AS_NODE=1` 会让 Electron 变成纯 Node

环境里若带着这个变量，`electron --version` 会返回它自带的 Node 版本，
窗口永远不出现。启动前必须 `unset`。

### 坑 5 · `directories.buildResources: build` 与 stage 目录同名区

本项目的 stage 在 `build/stage`，而 electron-builder 默认把 `build`
当 buildResources。两者混在一处会让排查时误判"是谁删了 stage"。
（实测：改成独立目录**并没有**解决问题，坑 2 才是真因；但目录仍建议分开。）

### 坑 6 · 打包产物里不要留 `default_app.asar`

它是 Electron 自带的欢迎页应用，只在 `resources/` 下**既无 `app.asar`
也无 `app/`** 时才被加载。正常轮不到它，但留着就是歧义：
万一 `app.asar` 没打成功，界面会变成 Electron 默认页**而不是报错**，
排查方向会被带偏。

### 坑 7 · 写文件工具报备份超时时，用内联脚本兜底

本环境出现过 `ModifyBackup failed: sandbox.backup.modify_backup`
（写文件工具的备份服务超时），此时改用内联 Python 脚本写文件即可。
⚠️ 但内联脚本里若出现命令行外壳的变量写法（美元符号后接大括号、或 env 冒号），
会被安全策略误判而整条拦截 —— 文档里要举这类例子时，
写成"占位符 + 文字说明"的形式。
