## 0. 参考：开发 Mac 上的实测情况（2026-10-15）

| 项 | 结果 |
|:--|:--|

## Windows 说明

以下命令在仓库根目录执行。Windows 的虚拟环境在 `.venv\Scripts\`：cmd 可用
`.venv\Scripts\activate`，PowerShell 用 `.\.venv\Scripts\Activate.ps1`，Git Bash 用
`source .venv/Scripts/activate`。也可直接调用 `.venv\Scripts\python.exe`，无需激活。
本文其余 `.venv/bin/python` 命令在 Windows 上都换成这个解释器。

PowerShell 启动后端：
```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -m mmwf.main
```

另开 PowerShell 读取 `%LOCALAPPDATA%\mmwf\port` 和 `session.token`：
```powershell
$PORT = (Get-Content "$env:LOCALAPPDATA\mmwf\port" -Raw).Trim()
$TOK = (Get-Content "$env:LOCALAPPDATA\mmwf\session.token" -Raw).Trim()
$B = "http://127.0.0.1:$PORT/api/v1"
$H = "X-MMWF-Token: $TOK"
curl.exe -s -H "$H" "$B/system/selfcheck"
netstat -ano | Select-String ":$PORT\s"
```
`netstat -ano` 最后一列是 PID，按后端 PID 核对监听和连接；应只监听 127.0.0.1。
令牌只在本机读取，不要粘贴到验收记录里。

A 节的 curl 示例采用 Git Bash 语法（`$()`、单引号包 JSON）；在 Git Bash 中改用：
```bash
PYTHONPATH=src .venv/Scripts/python.exe -m mmwf.main
# 另开 Git Bash：
PORT=$(cat "$LOCALAPPDATA/mmwf/port"); TOK=$(cat "$LOCALAPPDATA/mmwf/session.token")
B="http://127.0.0.1:$PORT/api/v1"; H="X-MMWF-Token: $TOK"
curl -s -H "$H" -H 'Content-Type: application/json' -d '{"title":"测试会","record_markdown":"测试记录"}' "$B/meetings"
```

PowerShell 使用 `curl.exe`，避免 Windows PowerShell 的 `curl` 别名。
不要直接照搬 Bash 的变量赋值或 JSON 引号：不同 PowerShell 版本给原生程序传递
双引号的方式不同。JSON 请求可先写成无 BOM 的 UTF-8 文件，再传给 curl：
```powershell
$json = '{"title":"测试会","record_markdown":"测试记录"}'
[System.IO.File]::WriteAllText((Join-Path $PWD 'meeting.json'), $json, [System.Text.UTF8Encoding]::new($false))
curl.exe -s -H "$H" -H 'Content-Type: application/json' --data-binary '@meeting.json' "$B/meetings"
```

开发测试安装依赖时，部分 pip 镜像（如清华镜像）可能缺少 `imageio-ffmpeg`。
在允许联网的准备环境中单独使用官方源：
```powershell
.\.venv\Scripts\python.exe -m pip install imageio-ffmpeg -i https://pypi.org/simple
```
离线目标机应使用预先准备的受控安装包；`imageio-ffmpeg` 不含 ffprobe，正式交付仍按部署手册配置 FFmpeg。

LibreOffice 定位只检查配置路径或 PATH；PDF 真转换验收的 `--version` 探测限时 15 秒，
实际 DOC/PDF 转换仍限时 180 秒。未找到程序时 DOC 返回 skipped、PDF 返回 E5003；
转换超时走 DOC failed / PDF E5003。验收中已找到程序但版本探测超时，仍记失败并保留异常，不能计作通过。

## A. 只要能跑后端就能验证（不需要额外安装）

### A0. 启动后端（每次验证前做一次）
```bash
cd <仓库目录>
PYTHONPATH=src .venv/bin/python -m mmwf.main
```
另开一个终端，设置变量：
```bash
# macOS/Linux：令牌和端口在 ~/mmwf/（设置了 LOCALAPPDATA 时在 $LOCALAPPDATA/mmwf/）
# Windows：在 %LOCALAPPDATA%\mmwf\ 下的 port 和 session.token
PORT=$(cat ~/mmwf/port); TOK=$(cat ~/mmwf/session.token)
B=http://127.0.0.1:$PORT/api/v1; H="X-MMWF-Token: $TOK"
```

### A1. 文字记录稿 → 纪要 → DOCX 全流程（V5 的 API 部分；V7 的非音频部分）
1. 建会：`curl -s -H "$H" -H 'Content-Type: application/json' -d '{"title":"测试会","record_markdown":"[00:00:01] 张三：关于预算，会议决定由财务处负责核算设备采购，下周五前完成。"}' $B/meetings`，记下返回的 `meeting_id`（下面记作 MID）
2. `curl -s -X POST -H "$H" $B/meetings/MID/start`，应该停在 `G2_awaiting`
3. 取检查点：`curl -s -H "$H" $B/meetings/MID`，在 `data.run.pending_gate.checkpoint_id` 里
4. G2 分别试三种决定（每种用一个新会议）：
   - approve：`rerun_nodes=[]`，进入 G3
   - edit：在 payload 里改 topics 的 title，`rerun_nodes=[]`，改动要进入最终稿
   - reject：`rerun_nodes=["extract"]`，回到 G2
5. G3 approve：状态变成 `archived`
6. 导出：`curl -s -X POST -H "$H" -H 'Content-Type: application/json' -d '{}' $B/meetings/MID/export`，文件在 `data/store/MID/export/`。用 `qlmanage -p 文件名.docx` 预览正文内容。**这只能看内容，不算版式验收**
7. 重复导出：提示"文件已存在，未重复生成"，sha256 不变
8. 用过期的 checkpoint_id 再提交一次：返回 E4001

### A2. 问题清单（T2-04）
`curl -s -H "$H" "$B/meetings/MID/issues?format=text"`：核对级别、路径、中文说明是否看得懂；JSON 版和文本版的条目要一一对应。

### A3. 审计（V8 / AUD；IT-17）
- `.venv/bin/python tools/verify_audit_chain.py --db data/mmwf.db` → 校验通过
- 篡改测试**请在副本上做**：`cp data/mmwf.db <临时目录>/a.db && sqlite3 <临时目录>/a.db "UPDATE audit_log SET operator='x' WHERE rowid=1;"` → 应该被触发器拒绝
- 审计里不能出现正文：`sqlite3 data/mmwf.db "SELECT detail FROM audit_log ORDER BY rowid DESC LIMIT 5;"` → 只有指纹和路径，没有纪要正文

### A4. 离线（M3 / V9 的后端部分；SEC-03 的本机版）
1. 关闭 Wi-Fi，并拔掉网线 → 重做 A1 → 应该全部成功
2. 运行期间：`lsof -nP -i -a -p $(pgrep -f mmwf.main)` → 只能看到 127.0.0.1 上的监听和回环连接（Windows 用 `netstat -ano` 按后端 PID 过滤）
3. `curl -s -H "$H" $B/system/selfcheck` → `outbound_connections` 为 0

> 这一项只能证明程序本身离线。目标机上的断网和整机抓包仍然要另外做。

### A5. 访问控制（IT-15 / SEC-05 / SEC-09 的部分）
- 后端已经在跑时再启动一次 → 应该提示被占用（E9003，或会话锁提示）
- 去掉令牌请求 → E6001
- 从同一局域网的另一台设备（比如手机浏览器）访问 `http://<Mac 的局域网 IP>:$PORT/api/v1/meetings` → 应该连不上（只监听回环）

### A6. 稳定性（STAB-01 / STAB-02，后端部分）
- STAB-01：照 A1 连续跑 10 个会议，用 `ps -o rss= -p $(pgrep -f mmwf.main)` 每个会议记一次 → 内存曲线应该平稳
- STAB-02：后端闲置 8 小时后再做一次 A1 → 应该正常响应

> 这一项不能代表目标机型的结果。

### A7. 影子模式工具（用合成数据练手）
```bash
.venv/bin/python tools/shadow_run.py --manifest tests/fixtures/shadow/synthetic/manifest.json --output <临时目录>/shadow/batch
.venv/bin/python tools/shadow_report.py --batch <临时目录>/shadow/batch --scores tests/fixtures/shadow/synthetic/scores.json --thresholds tests/fixtures/shadow/synthetic/thresholds.json --output <临时目录>/shadow/report
```
看 `report.md` 是否易读，确认标了 SYNTHETIC 和 PENDING。目的是让评分人熟悉评分模板（`docs/templates/T2-05-*`）。

## C. 必须在目标机型、目标系统或使用单位做

- **性能**：PERF-01/02/03/05/06（在目标机型上计时；有没有独显）
- **Windows 相关**：T1-18 打包后双击能启动、Chromium 沙箱、Word COM 验证（M1/M2/M6 原来就是在 Windows 上验的）、Windows 上的 DR-07 文件占用
- **信创 OS 适配**
- **真实数据**：在受控环境里跑影子模式 ≥ 20 场，第三方评分；R-5；V3 要素齐备率；V4 随机抽 10 条（需要真实时间戳和真实音频）；Q2/Q3/Q4 的真实使用记录；待办误降级率和规则误报率的评估
- **目标机上的历史明文数据迁移/重新加密**（只要目标机上已经存有真实数据就要做）
- **真正的物理断网和整机抓包**（SEC-01/03 的正式证据），SEC-09 跨机拒绝的正式记录
- **使用单位确认**：E 节的全部内容（待确认 A/B、审计核查项、五维阈值、密级和设备性质、说话人分离做不做）

## 建议顺序

1. 先做 A1~A5（大约 30~60 分钟，不用装任何东西）
2. 装好 Node 和 LibreOffice（约 1.5 GB）后，就能覆盖 C 节界面项和 PDF，这是收益最大的一批
3. Ollama 和 FunASR 体积大，而且 Mac 上的性能数据不作数，建议直接放到目标机上做
