## 2. 契约（逐条可对照）

### 2.1 CLI、输入与安全边界

固定命令（已实现；real 只由使用单位在受控目标机运行）：

```sh
.venv/bin/python tools/shadow_run.py --manifest <manifest.json> --output <新批次目录>
.venv/bin/python tools/shadow_report.py --batch <批次目录> --scores <scores.json> --thresholds <thresholds.json> --output <报告目录>
.venv/bin/python tools/accept_t2_05.py
```

`manifest.json` v1 必填 `format_version=1,batch_id,dataset_kind=synthetic|real,meetings`。会议必填唯一 `meeting_id,name,meeting_kind,duration_seconds,record_path,segments_path,meeting_meta,template_snapshot_path,source_version`。meeting_kind 与模板快照一致；覆盖检查按四个 builtin 类型 party_group（党组会）、special_topic（专题会）、coordination（协调会）、regular_meeting（例会）或单位约定的映射，不把现有自由文本类型收紧成全局枚举。时长为正整数秒，会议类型和长/短分类（单位给定秒数分界）随批次记录。模型配置、模型标识/版本、提示词/示例库指纹、代码版本、模板 id/version/内容指纹、源文件指纹和运行耗时进入运行元信息，未取到的真实信息标 unknown 并列缺口，不编造。

工具只读显式输入，不隐式扫描 `data/`、不连接生产 DB、不修改原稿；manifest 路径以其目录解析，输出必须为新目录且不得与输入、正式数据目录重叠（含符号链接解析）。每会议单独子目录，拒绝重复 id、路径穿越和覆盖已有批次。real 必填 `controlled_environment_confirmed=true` 及操作人声明；这只是单位作业声明，**不是自动保密认证**，本机不运行 real。所有影子草稿/评分/报告均按原会议敏感级别在受控目录管理，不纳入 git 或上传；synthetic 输出也带标识。既有本地适配器只访问受控本机服务，测试禁出站，不加云端或新依赖。

批次输出 `run.json`、每会议 `candidate.json,candidate.md,issues.json,score.template.json`，以及批次 `records.template.csv,records.template.json`。draft 首页与 JSON 均标“影子生成，禁止交付”；synthetic 另标 **SYNTHETIC / 合成数据，非真实验收结果**。这些是工具作业文件，不是业务纪要版本/正式 export artifact；无 export/archive/final 产物。

### 2.2 影子生成流水线

1. 预检 manifest、权威源、模板和模式。real 使用既有本地 LLM 适配器 + `make_llm_extractor`，不允许模型失败后静默回退；synthetic 显式 Fake，`dataset_kind` 在所有下游文件保持一致。
2. 从核对记录稿和权威分段生成丰富 minutes/issues，复用 `upgrade_legacy_state` 形成与生产一致的元信息和三列表映射。模板内容快照固定一次，不中途热读；不提供人工定稿给模型。
3. 依次复用 `normalize_granularity`、`apply_template`、`post_validate`，保留抽取/粒度 issues、修正历史和源引用。参照生产 validate 的 `verify_references` 回填真实段 refs，再应用模板重建 sections；与相同输入的生产 G3 前结果做 synthetic 联证，不能只用 naive 成稿冒充实际模型链。
4. 复用 `route_after_validate` 的 blocked 优先与有限重试判据；不复制放宽策略。硬阻断停止本会议，保留 issues/失败原因，`candidate.md` 不生成可用成稿；无阻断时 `validate_hard` 复检后用 `render_template_markdown` 渲染，绝不调用带 save_draft 的生产 assemble。记录实际重试/处理步骤；不中断其他会议的诊断收集。
5. 每会议结果为工具文件的 `generated|blocked|failed`，**不是新增 PipelineState 状态**。批次必须保留所有计划会议和失败记录，任一未生成不能删行、换分母或宣称完整通过；driver 非零退出。整批重跑使用新 batch_id，禁止挑选同会“最好一稿”覆盖旧结果。

G2/G3 的正式审批和版本写入完全不在影子链内；影子输入直接进入生成子流程，不产生伪批准记录。阶段 0 的 ASR、人工核对、音频计时证据需单位另附。

### 2.3 03 §6.4 记录表与文件模板

CSV 为 UTF-8、标准 CSV 引号转义、固定英文列名；JSON 为同字段的类型化记录数组，外包装 `format_version,batch_id,dataset_kind,records`。JSON 是完整人工评分的投影，CSV 只承载可比对表及审查定位，**汇总以 scores.json 为权威**；投影不符报错，不凭手工改 CSV 改判。未评分字段 JSON 用 null、CSV 空单元格，不能默认 0/true；汇总行仅报告生成，不能作为第 21 场读入。

| 03 §6.4 列 | 固定字段 / 类型 | 说明 |
|:---|:---|:---|
| 序号、会议名称、类型、时长 | `sequence:int,meeting_name:str,meeting_kind:str,duration_seconds:int` | 对应 manifest，不允许评分人换会议 |
| 要素齐备 | `elements_complete:bool|null` | 所有约定必填项均存在才 true |
| 议题召回 | `topics_matched:int|null,topics_human:int|null` | 展示为 3/4，保留原整数 |
| 议定召回 | `resolutions_matched:int|null,resolutions_human:int|null` | 展示为 5/6 |
| 无依据 | `ungrounded_count:int|null,statement_count:int|null` | 原表命中条数扩展总条数，支持 §6.2 计算 |
| 结构合规 | `structure_compliant:bool|null` | 第三方按固定模板核对 |
| 分歧类型 | `divergence_classes:list[str]|null` | CSV 用 JSON 数组单元格；允许一会多类，无分歧为 [] |
| 备注 | `notes:str` | 失败/阻断及待补证原因 |
| 扩展定位 | `meeting_id,batch_id,dataset_kind,score_path` | 关联唯一评分文件，防混批 |

空模板由 driver 生成；实现还须交付 `docs/templates/T2-05-records.template.csv`（表头、零数据行）、`T2-05-records.template.json` 与 `T2-05-score.template.json`。JSON 模板的未填项为 null，不能作可通过的样本。唯一演示数据放 synthetic fixtures，不在空模板放“20 场达标”。

### 2.4 人工逐会议评分输入

`scores.json` v1 包含 `batch_id,dataset_kind,scores`。每条评分必填会议 id、候选稿/源/模板指纹、人工定稿指纹、`reviewer,author,reviewed_at` 和 `author_blind_to_candidate=true`。按 03 §6.1，人工照常撰写且不看系统稿，第三方评分人不得是撰写人；声明缺失/二者相同即评分不完整。指纹绑定版本，改稿必须重新评分。内部用 frozen dataclass 接收验证后的数据，领域层不读文件。

| 字段 | 人工输入与验证合同 |
|:---|:---|
| `required_elements,element_presence` | 前者为本批次按模板约定的非空必填项清单；后者逐项 true/false，键集必须一致；脚本只据此求 all，不做 NLP |
| `human_topic_ids,topic_matches` | 人工稿议题唯一 id 列表；交集由人工填写 human_id/candidate_id 配对及证据定位；human_id 不得重复计数、引用须存在，多个系统条目对应同一人工议题只算一次 |
| `human_resolution_ids,resolution_matches` | 同上，议定事项口径固定，不把 pending_decisions 混作决议；交集 ≤ 人工总数 |
| `statements` | 人工对系统稿全部实质陈述划定唯一 id、候选稿定位、源证据定位、`supported:bool`、理由；supported=false 可无源但须写核查理由。覆盖全稿声明必填；标题/编号等非实质项排除口径在批次固定。引用真实但语义不支持仍 false |
| `structure_compliant,structure_evidence` | 人工布尔结论与模板核对依据，不能用“模板规则没报问题”自动填 true |
| `divergences` | 每个分歧有 id、定位、理由及 `class=更保守|更激进|系统错误`。报告可显示“系统更保守/系统更激进”；无分歧须显式 [] 并声明核对完成，不拿 null 当零 |
| `issue_reviews` | 对 issues.json 的稳定 issue_id 填 `verdict=true_positive|false_positive|uncertain`、理由；降级项另填 `false_downgrade:bool|null`。只记录人的判断，不从文案推断 |
| `supplementary` | 可填真实待办总数及降级对应关系、返工轮次、人工投入分钟、姓名/数字/机构的抽检分子分母与溯源结论、抽取召回/耗时独立证据链接；未提供记 PENDING |

人工议题/议定条目可由评分人录入；候选项、statement 和源定位必须能回到文件。脚本校验存在性、唯一性、整数范围、指纹与覆盖声明，不据此判断语义是否正确。无依据判定和分歧分类分别输入；即使有源支持、但系统比人工多写也可人工标更激进，不将二者机械互换。

### 2.5 五维聚合、阈值与放开判据

只对**同一完整批次**汇总，分母不剔除失败/漏评分会议；这类批次整体 INCOMPLETE，不计算可放开结论。禁止逐会议百分比取平均代替下表 micro 汇总。输出保留分子/分母与未舍入数值，展示可四舍五入，判定用原整数比值。

| 维度 | 精确计算 | 03 §6.2 建议阈值 |
|:---|:---|:---|
| 要素齐备率 | 全部必填项存在的会议份数 / manifest 总份数 | ≥0.95 |
| 议题召回率 | Σ人工确认议题交集数 / Σ人工稿议题数 | ≥0.90 |
| 议定事项召回率 | Σ人工确认议定交集数 / Σ人工稿议定数 | ≥0.85 |
| 无依据陈述率 | Σsupported=false 陈述数 / Σ人工划定系统实质陈述数 | **=0** |
| 结构合规率 | 人工确认合规份数 / manifest 总份数 | **=1.00** |

`thresholds.json` 是工具输入文件，非项目配置变更；固定字段 `format_version,required_elements_min,topic_recall_min,resolution_recall_min,ungrounded_max,structure_min,agreement`。比例合法范围 [0,1]；红线/强制值 `ungrounded_max=0,structure_min=1` 不得放宽，前 3 项可配置但**须与使用单位约定**。agreement 记录约定编号/日期/责任人及必填项、四类覆盖、长短会分界；默认建议值可用于 synthetic 验算，未确认约定的 real 批次不得给出可放开结论。报告原样列有效阈值与约定，不偷偷使用本机默认配置。

单会议人工议题/议定数可为 0，此行召回为 N/A，原始 0 仍参与求和；**批次总分母为 0、总陈述为 0 或总会议为 0 均为 NOT_EVALUABLE，不能当 100%/0% 或五维全通过**。缺失、负数、交集大于总数、重复/额外/混批 id、未审陈述、错指纹、缺 issue 审查均不得默认为通过。按约定边界用分数比较，0.94999 不得因显示 95% 通过。

`quality_pass = 五维全部可计算且全部达标 AND 更激进条数=0 AND 系统错误条数=0`。两类按**分歧条数**计，还需给出受影响会议数；更保守允许存在，剩余分歧只能是更保守，无分歧也可通过，不强迫造分歧。

`eligible_for_stage2 = quality_pass AND 数据/评分完整 AND dataset_kind=real AND 真实唯一会议数≥20 AND 四类会议及长短会覆盖 AND 阈值已约定`。结果只为“建议进入阶段 2 / 不满足 / 待验”，**不自动修改授权、配置或正式交付能力**。synthetic 无论质量数字多高，始终 `eligible_for_stage2=false,real_run_status=PENDING,real_meetings_counted=0`。任一无依据陈述出现即不放开，并提示回到阶段 1 整改后重新验证；保留原失败批次，不能删错样本后复算。

### 2.6 T2-04 风险附加统计

读取本批次原始 issues.json 并复用 `aggregate_issues` 去重，以规范 JSON `(source,code,target,evidence)` 的哈希作工具 issue_id，保留完整四元组供核对；跨会议不合并，历史重复恢复不重复计数。人工标签必须引用这个 id，不能凭 message 匹配。

- **待办误降级率**：人工判为误降级的 ACTION_DOWNGRADED 事件数 / 全部已明确审查的 ACTION_DOWNGRADED 事件数；另报总降级数、已审数、uncertain/未审数、覆盖率。若单位提供真实待办全集，再单列“受误降级真实待办数 / 人工真实待办总数”，两种分母不得混用。零降级为 N/A，不伪报 0% 已验证；有未审/uncertain 不给完整风险结论。
- **规则误报率**：人工 false_positive 数 / (true_positive+false_positive)，按 source/code 和总体报告；规则集合为 source 属于 template、consistency、granularity 的 issues，降级项仍可在本组计数，但两项风险率不相加。报告未审/uncertain 与覆盖率；零可判标签为 N/A，不把无告警称为无误报/无漏报。
- 以上是风险观测，不是五维第六/第七项；上游未给合格阈值，本卡不发明阈值或自动阻断业务。未审使报告审查不完整；全审后即使出现误报也如实提示人工处理，不能通过过滤 issues 美化结果。

## 4. 验收标准（逐项编号）

1. **批量生成但不交付**：至少两个显式 synthetic 会议走实际抽取/Fake→领域链，模板/源指纹和 issues 不丢；与生产 G3 前合成结果一致。export/archive/MinutesService/MinutesStore 写入次数均 0，正式 DB、输入文件、版本行与输出目录快照不变，无 final、DOCX、archive。该项不代表真实 20 场完成。
2. **安全失败与隔离**：无依据阻断不渲染可用成稿；缺源、坏模型响应、模型不可用、路径穿越/符号链接重叠、重复 id、重用输出目录均明确失败；计划会议无删行，批次失败非零；真模型模式禁止 naive/Fake 回退，禁 socket 出站仍可完成 synthetic 工具测试。
3. **人工评分与记录表**：03 §6.4 十一列逐一映射到 CSV/JSON、空模板与运行时格式一致；完整逐会议人工输入能读，null 不当 0；人工撰写/第三方身份与盲写声明、版本指纹、源定位、交集和逐陈述覆盖有校验。脚本只校验输入和算数，无自动语义评分。
4. **五维与建议阈值**：可手算的非等量会议合成向量证明 micro 汇总；95%/90%/85%/0/100% 边界及一侧反例；配置约定回显，未约定 real 不放开、红线不能放宽；所有零分母/缺失为不可评估。结构/要素按会议，召回/无依据按条目，不能调换分母。
5. **放开与渐进授权**：五维全过仍有一条更激进或系统错误则失败；更保守可存在，无分歧允许。合成 20 场甚至全部满分仍 real_count=0、PENDING、不建议放开；real 的 ≥20 唯一会议/四类/长短覆盖与约定条件用合成元数据做逻辑单测，须标“条件计算测试”，不形成真实证据。阶段 0～3、Q2/Q3/Q4 与 R-5 依赖明确，无自动批准或授权修改。
6. **附加风险计数**：从 issues 而非日志抓取 ACTION_DOWNGRADED，人工标记误降级；重复清单只算一次、原项可追；规则误报按 source/code 输出 true/false/uncertain、分母和覆盖。零告警=N/A，未审不能称零风险；附加指标不伪装已有上线阈值。
7. **报告可复核**：Markdown + JSON + records CSV/JSON 同一批次、逐行一致，含完整失败/缺口/阈值/原始计数/合成标识；改稿旧评分拒绝，输出失败不保留成功旧结论。Q1/Q5 与真实影子证据、Q2～Q4 人工补证、R-5 联证分别列账，工具完成不能勾全质量/红线通过。
8. **验收脚本可信**：每项列精确命令、执行/通过/失败/错误/跳过数和完整输出；八项中任何失败、零执行、收集错误或 skip 均非零退出；`--only` 不伪称全 8 项通过。独立反例破坏放开 AND、去掉 synthetic 拦截、绕过副作用防线时对应项必须 FAIL。无条件打印“真实 ≥20 场：PENDING；本机未运行真实会议；计入真实验收 0；须使用单位受控环境人工比对”，此 pending 不计自动 passed，也不使工具标准本身伪 FAIL；脚本退出 0 的标签必须是 TOOLING_PASS，不能是 RELEASE_PASS。

上游原验收四项（真实 ≥20、五维报告达标、无依据严格为 0、激进归零）仍由单位执行；本卡八项只验其工具支撑。03 比 02 更明确要求**系统错误也为 0**，按 03 §6.3 与交付签字表执行，不省略。

## 7. 常见坑

1. 把 20 个合成 fixture 当 20 份真实历史会议：synthetic 在每一层传播并硬挡放开，验收脚本始终单列真实 PENDING/0。
2. 直接运行生产图到 G3 后自动 approve，或复用 assemble 包装器：会触发版本/导出/归档；独立组合生成领域链，副作用用调用计数和文件/DB 快照证明为零。
3. 模型不可用偷偷回落 naive/Fake，或本机下载 LLM/真实资料补验收：real 明确失败；单位受控目标机才跑真实影子作业。
4. 让人工撰写人先看系统稿，或同一个人写稿和最终比对：产生锚定；独立盲写和第三方评分声明与证据必须留存。
5. 用字符串相似度/LLM 自动算交集、语义支持或分歧：违反人工评判边界；脚本只校验格式和汇总人的判定。
6. 召回率先逐场取百分比再平均，零分母算满分，漏评/失败会直接删行：全部违反本卡统计口径；完整批次、原始计数、不可评估明确报出。
7. 五维全过却漏了“激进=0 AND 错误=0”，或四舍五入后过线：严格 AND、未舍入比值，并保留全部分歧证据。
8. 引用命中就自动填无依据=0，或只审 issues 命中的陈述：语义支持需逐陈述人工核对，R-5 仍联证 DR-05/06。
9. 把所有降级都当误降级、把未审算正确、用待办总数混作告警分母：保留两种口径、标签覆盖和 N/A；误报率不证明漏报率。
10. 五维通过等于 Q1～Q5/全部红线/阶段 3 已通过：Q2/Q3/Q4 有独立实测要求，阶段 2 建议仍由单位决定，无依据出现退回阶段 1。
11. 改过稿还复用旧评分、择优覆盖同场失败结果，或工具输出写进生产 data/：指纹绑定、新 batch_id、显式目录隔离；失败证据不能抹去。
12. 仅脚本存在/退出 0 就宣布上线：TOOLING_PASS 与真实影子结果分账，skip/零执行不能过自动项，真实运行未发生永远不计入通过。
