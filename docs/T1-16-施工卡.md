### 2.1 端点一览（5 条）

**实施前实测的基线（`build_router(cfg)` 直接调用，25 条）**：

```
POST   /system/handshake          GET    /meetings                POST  /meetings/{id}/audio
POST   /meetings                  GET    /meetings/{id}           GET   /meetings/{id}/transcript
POST   /meetings/{id}/start       GET    /meetings/{id}/topics    PATCH /segments/{seg_id}
```

**本卡新增 5 条**：

| # | 方法 | 路径 | 用途 | 需求 | 档 |
|:--|:---|:---|:---|:---|:---|
| 1 | `GET` | `/templates` | 模板列表（可按 `meeting_kind` 筛） | F7.2 | B |
| 2 | `POST` | `/templates` | 新建模板（写表 + 留痕） | F7.2 | B |
| 3 | `PUT` | `/templates/{template_id}` | 改模板（**版本自增**） | F7.2 | B |
| 4 | `GET` | `/meetings/{id}/diff` | 两版记录稿段落级差异 | F4.3 | B |
| 5 | `GET` | `/meetings/{id}/export/{file}` | 下载导出文件 | F5.1 | A |

**25 + 5 = 30**。`API_PREFIX = "/api/v1"`（`main.py:60`），
清单用 `build_router(cfg)` 取（它**不加前缀**，前缀在 `main.py:380` 的
`include_router(prefix=API_PREFIX)` 那步 —— 见坑 9）。

> ⚠️ `POST /meetings/{id}/export/undo` 在清单里位于 `/export/{file}` **之前**，
> 新加的 `GET /export/{file}` 若声明顺序不当，FastAPI 可能把 `undo`
> 当成 `{file}` 的值匹配掉。**必须把 `/export/{file}` 声明在 `/export/undo` 之后**
> （FastAPI 按声明顺序匹配，`undo` 是字面量、优先于路径参数）。

> ★★ **实施后的更正（见坑 14，原文保留在上）**：上面那句"声明顺序"
> **不是**这个坑的真因 —— `undo` 那条路由**只声明了 `POST`**，
> 而 `{file}` 是 `GET`，**两者不在同一方法空间**，
> 所以"声明在之后"根本救不了。真解法是**补一条 `GET .../export/undo`
> 占位路由**（声明在 `{file}` 之前）。
> 顺序只决定"同方法下谁先匹配"，管不了"这个方法有没有别的候选"。

**记账口径（三个数，别混）**：

| 口径 | 数值 | 说明 |
|:---|:---|:---|
| **SAD §9.1** | **30 条** | method+path。表里 24 行，`/glossary` 与 `/templates` 两行是 4/3 个方法合写；展开 + 表里没列但 F7.1 要求的 `/glossary/export` = 30。**这是进度对照的权威口径** |
| **本卡完成后路由表** | **31 条** | SAD 的 30 + **1 条方法守卫** `GET .../export/undo`（坑 14） |
| **去重后的路径数** | **26 条** | 供与 SAD 的 30 对照时参考 |

> ⚠️ **施工阶段我把"基线 25"当成了路径数**，但它实际是 **method+path 对数**
> （把上面那段清单逐行数一遍就是 25）。所以"25 + 5 = 30"里的 30
> **只在 method+path 口径下成立**，而在"路径数"口径下是 25 → 26。
> 两个口径都不错，但**混用会让结论错**：本卡验收时我一度

### 2.2 `GET /templates` —— 模板列表

```jsonc
// 响应 data
{
  "templates": [
    {
      "template_id": "tpl-regular-meeting-v1",
      "name": "工作例会议纪要",
      "meeting_kind": "regular_meeting",
      "version_no": 1,
      "enabled": true,
      "source": "builtin",          // ★ builtin | db（见裁决 D1）
      "required_elements": [ {...} ],
      "section_order": ["会议基本情况", ...],
      "style": { "readings_allowed": [...], "readings_forbidden": [...] },
      "updated_at": "2026-09-29T..."
    }
  ],
  "counts": { "total": 4, "builtin": 4, "db": 0 }
}
```

- 查询参数：`meeting_kind`（可选）、`include_disabled`（默认 `false`）。
- **`source` 字段是本卡的关键设计**（裁决 D1）：
  内置模板来自 `config/templates/*.yaml`，自建模板来自 `template` 表。
  两者**合并返回**、用 `source` 区分，而不是"表为空就自动灌库"——
  灌库会让"改一行 yaml 即生效"（N5.2）失效。
- 空列表 → `message` 提示「还没有模板」（但内置 4 个在，一般不为空）。

### 2.3 `POST /templates` / `PUT /templates/{template_id}`

**`POST` 请求体**

```jsonc
{
  "template_id": "tpl-standup-v1",        // 可选，不填则生成
  "name": "站会议纪要",
  "meeting_kind": "regular_meeting",
  "required_elements": [ { "key": "title", "label": "标题", "pattern": "^.{4,30}$" } ],
  "section_order": ["会议基本情况", "议定事项"],
  "style": { "readings_allowed": [...], "readings_forbidden": [...] }
}
```

**`PUT` 请求体**：同上但**忽略 `template_id`**（以路径参数为准）。

**两条硬规则**：

| 规则 | 为什么 |
|:---|:---|
| **`version_no` 由服务端自增，客户端传的一律忽略** | F7.2「修改后 version 递增，历史版本可查」。让客户端传 = 允许它把版本改回去 |
| **内置模板不允许被改**（`source=builtin` → E1003） | 内置模板的"代码外置、热改生效"是 N5.2 的核心卖点；允许 API 覆盖它，用户会遇到"我改了 yaml 没反应"（因为被表里的行盖住了）——**这比报错更难排查** |

**校验**（`domain/template.py`，失败一律 E1001，**不抛 E9001**，见坑 1）：

| 字段 | 规则 |
|:---|:---|
| `name` | 非空，≤ 50 字 |
| `meeting_kind` | 非空 |
| `required_elements` | 非空数组；每项必有 `key` 与 `label`；`key` 不重复 |
| `section_order` | 非空字符串数组 |
| `style` | 可缺省；给了就必须是 dict |

**写操作留痕**：`template_change`（已在 `infra/audit.ACTIONS` 里登记，
所以 `AuditLogger.log()` 不会抛 `AuditError` —— 但这条**必须实测**，见坑 2）。

### 2.4 `GET /meetings/{id}/diff` —— 版本差异

**裁决 D2 —— 输入取自哪里？**

| 候选 | 可用性 | 裁决 |
|:---|:---|:---|
| `minutes_version` 表 | **0 写 0 读**，没有任何代码往里写 | ✗ 排除。为它接端点 = 端点永远返回空 |
| 磁盘 `record/v{N}.md` | `review` 真写、`export.latest_record_version()` 真读 | ✓ **采用** |

**契约**

```
GET /meetings/{id}/diff?base=v2&compare=v3
```

| 参数 | 说明 |
|:---|:---|
| `base` | 基准版本（可选，默认 = `compare - 1`） |
| `compare` | 对比版本（可选，默认 = 最新版本） |

```jsonc
// 响应 data
{
  "meeting_id": "m-xxx",
  "base_version": 2,
  "compare_version": 3,
  "segments": [                                  // ★ 段落级，不是行级
    { "type": "unchanged", "lines": ["会议基本情况", "..."] },
    { "type": "changed",   "old": ["原句"], "new": ["改后句"] },
    { "type": "removed",   "old": ["删掉的一段"] },
    { "type": "added",     "new": ["新增的一段"] }
  ],
  "summary": { "unchanged": 12, "changed": 2, "removed": 1, "added": 1 }
}
```

- **段落粒度**：`type` 四值（`unchanged / changed / removed / added`）与
  施工文档 §T2-03 的 `diff_versions()` **逐字对齐** —— 前端将来直接渲染，
  不要自创第五种。
- **`unchanged` 段要返回，但只返回"连贯的一段"**，不是逐行罗列。
  极长的不变区间要**折叠**（裁决 D3）：超过 `MAX_UNCHANGED_LINES`（=40）
  时截断，并在段里带 `"elided": N` 表示省了多少行。
  否则一份 500 段的记录稿，diff 响应 99% 是没变的内容。
- 版本不存在 → E1002（不是 E9001，不是 500）。
- 只有 1 个版本（无对比对象）→ **200 + 空 segments + message 说明**
  （裁决 D4：这不是错误，是"还没有第二版"）。

### 2.5 `GET /meetings/{id}/export/{file}` —— 下载

**这是唯一真正的 A 档（接线）**，但**接线里藏着一个安全红线**。

```jsonc
// 正常：200 + 文件字节流
// 头部：Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document
//       Content-Disposition: attachment; filename="..."; filename*=UTF-8''...
```

**三条硬规则**：

| 规则 | 为什么 |
|:---|:---|
| ★ **`file` 参数必须拒绝路径穿越** | `file="../../keystore/master.key"` 能把**解密密钥**down 出去。这是本卡**唯一的安全红线**，验收里有专门一项 |
| 只允许下载 `export/` 区内的文件 | 别的区是**加密区**，`filestore.read()` 会解密 —— 等于绕过"明文区只有 export"的设计 |
| `meeting_id` 与会话必须匹配 | 防"改个 id 下别人的文件"。走 `_require_meeting` |

**防穿越的做法**（裁决 D5）：

```python
# ✅ 这样做：先取 basename，再要求"拼出来的路径必须落在 export 目录内"
safe_name = Path(file).name                       # 去掉所有目录成分
if safe_name != file or safe_name in {"", ".", ".."}:
    raise MmwfError(code="E1001", ...)            # 带 ../ 或子路径的，直接拒
rel = f"export/{safe_name}"                        # 文件名 → 会议内相对路径
```

> ⚠️ **不要**只做 `if ".." in file` 的黑名单 —— 它挡不住
> `..%2f`（URL 编码，FastAPI 会解开）、`....//`、Windows 的 `..\`。
> **白名单（`Path(file).name == file`）才是唯一稳的**。

文件的**组织方式**：`export/` 区按会议分目录
（`data/store/{m_id}/export/{meeting_id}-v2.docx`，
`EXPORT_NAME_TEMPLATE = "{meeting_id}-v{version}.docx"`）。
所以 `file` 就是那个**文件名**，端点自己拼 `export/{file}`。

### 2.6 分层约束（本卡必须一次做对）

| 层 | 新增文件 | 关键约束 |
|:---|:---|:---|
| `domain/` | `template.py`、`minutes/validator.py` 加 `diff_versions` | **不许 import `sqlite3` / `yaml` 之外的 IO**；`difflib` 是标准库，**允许** |
| `infra/` | `template_store.py` | 只有这层能碰 `template` 表（同 `transcript_store.py` 的理由） |
| `api/` | `routes.py` 加 5 端点 | ★ **`sqlite3` 是 `FORBIDDEN_IN_API` 成员** → 模板读取必须经 `template_store` |

> ⚠️ 一个**容易踩的细节**：`yaml` **不在** `FORBIDDEN_IN_DOMAIN` 里，
> 所以可以在 `domain/template.py` 里 `import yaml`。
> 但**读文件**（`open()`）属于 IO —— 领域层应只接受"已读到的文本"，
> 由 `infra` 或 `app` 负责读盘。**本卡的取法**：`infra/template_store.py`
> 负责读 yaml 文件 + 读表，`domain/template.py` 只做"文本 → 领域对象 + 校验"。

> 而不是"功能对不对"。

## 4. 常见坑

### 坑 1 ★★ 「底层不存在」的端点，第一版一定会变成 E9001

`template` 表 0 读写。**第一版很容易这样写**：

```python
rows = conn.execute("SELECT * FROM template")   # 表在，但没数据 → 空
```

空表不报错，但**建表 ≠ 有数据**，于是"模板列表恒为空"。
更糟的是**直接 `import sqlite3` 访问** —— 那是分层违规（2.6），
`check_layers.py` 会拦，但如果先跑端到端测试、后跑静态检查，
就会先看到"端点跑通了"的假象。

**做法**：先落 `template_store.py`，再写端点。**顺序不能反。**

### 坑 2 ★ `AuditLogger.log()` 对**未登记**的动作抛 `AuditError`

`infra/audit.ACTIONS` 里有 `template_change`（T1-14 时就登记了）。
但**"名字在集合里"和"调用签名对"是两件事** ——
写留痕时**必须**核对 `AuditLogger` 上到底有没有对应方法、
参数顺序是不是 `(operator, ...)`。

**教训（T1-14 踩过）**：验收脚本里用过一次 `meeting_create`，
它不在 `ACTIONS` 里 → 直接抛 `AuditError`。
**动作名必须取自 `ACTIONS`，不能按语义自己起。**

### 坑 3 ★★ 路径穿越：黑名单挡不住，白名单才挡得住

见 2.5。具体三种绕过：

| 输入 | 黑名单 `".." in file` | 白名单 `Path(file).name == file` |
|:---|:---|:---|
| `../x` | ✓ 拦住 | ✓ 拦住 |
| `..%2f..%2fx` | **✗ 漏**（FastAPI 解码后才含 `..`，但**在参数校验之后**） | ✓ 拦住 |
| `....//x` | **✗ 漏**（不含连续两点） | ✓ 拦住 |
| `a/../../x` | ✓ 拦住 | ✓ 拦住（`name != file`） |

**本卡用白名单。** 并且**验收要真的喂这四种**（标准 7），不是只喂 `../x`。

### 坑 4 ★ `export/` 是**明文区**，但别的区不是 —— 别下错区

`filestore.PLAINTEXT_AREAS = {"export"}`。若端点允许 `file` 带上区名
（如 `file="record/v1.md"`），`filestore.read()` 会**透明解密**并返回明文 ——
等于给了一个"读任意加密内容"的口子。

**做法**：端点自己把区名写死为 `export`，`file` 只当**文件名**用（同坑 3）。

### 坑 5 ★ diff 的"段落"定义：`splitlines()` 还是 `split("\n\n")`

施工文档给的参考实现是 `splitlines()`（行级）。但 F4.3 的目标写的是
**"按段落粒度，且只显示变化段落"**（施工文档 §T2-03 常见坑第三条）。
两者**不一致**。

**裁决**：**按空行切段**（`split("\n\n")` 再保留段内换行），
因为 Markdown 的记录稿里"一段"就是"一个逻辑块"，而 `splitlines()` 会把
一个段落的软换行拆成多行，导致 diff 噪声极大（改一个字 → 两行都标红）。

**这条要写进测试**：构造"只改一个字"的用例，断言 `changed` 段**只有 1 段**。

### 坑 6 ★ `unchanged` 段太长会淹掉响应（裁决 D3 的由来）

一份 500 段记录稿，若只改了 1 段，响应体 99% 是没变的内容。
**折叠**：连续 `unchanged` 超过 40 行 → 截断成"前 20 + 后 20"，
带 `elided: N`。

**验收要构造超长 unchanged**（标准 6 的一部分），否则这个分支永远测不到。

### 坑 7 ★ 只有 1 版时的 diff 语义（裁决 D4）

`base` 默认 = `compare - 1`。**只有 v1 时，`base=0` 不存在** ——
这不是 E1002。第一版很容易在这里抛"版本 0 不存在"。

**裁决**：`compare` 版本存在但 `base` 不存在（或 `base < 1`）→
**200 + 空 segments + message「这是第一版，没有可对比的上一版」**。

### 坑 8 ★ 「内置模板不可改」的**返回码**要选对

用 **E1003**（不是 E1001）。语义差别：
`E1001` = "你填的东西不合格式"，`E1003` = "这个对象不允许这样操作"。
用户填对了、但操作被规则拒绝 —— 属于后者。
**这样前端的提示也不同**："请检查填写内容" vs "这是内置模板，不能改；请另存为新模板"。

### 坑 9 ★ 本环境的端点清单**不能**从 `app.routes` 反查（T1-15 坑 9 复现）

FastAPI 把 `include_router` 结果包成 `_IncludedRouter`，**没有 `.path`**。
**做法**：直接 `build_router(cfg)`，前缀自己拼 `API_PREFIX`。

### 坑 10 ★★ 改了行为要同步改**旧断言**（T1-15 缺陷 24 的直接延续）

T1-15 收官时，全量回归唯一的红点就是"我改了行为、旧单测没跟上"。
本卡会**新增 5 个端点**，必然触发 `test_api.py` 的两条清单断言：

- `test_all_protected_endpoints_reject_without_token`（参数化路径 **+6**）
- `test_protected_endpoint_list_matches_router`（`declared` **+6**，`len(actual) == 31`，
  并新增 `sad_expected` 30 条**逐条点名**核对 + `extra == KNOWN_EXTRA` 白名单）

**这两条不是"顺手改一下"** —— 它们是"新端点漏挂鉴权"的**唯一防线**。
改的时候要**逐个端点确认它真被 `require_token` 覆盖**（路由级依赖，
所以只要挂在同一个 router 上就自动覆盖），而不是把数字改成 30 了事。

### 坑 11 验收脚本"每项标准一个独立子目录"（T1-15 坑 18 复现）

### 坑 14 ★★ 路由声明顺序不是全部 —— `undo` 那条根本没有 `GET`

> **本条在施工阶段写对了"症状"，但写错了"原因"，也开错了药方。**
> 实施与验收时被 `test_export_undo_route_not_shadowed` 抓出真因，
> 现按实际情况改写。**原判断/原修法留在下面**，作为"我当时怎么想错的"记录。

**我原本的判断**：FastAPI 按**声明顺序**匹配，把 `{file}` 声明在
`POST /meetings/{id}/export/undo` **之前**就会吃掉 `undo`。
所以"声明在它之后"就没事了。

**实际发生的事**（实测）：

```text
GET /api/v1/meetings/m-t116/export/undo
  → 200 {"ok":false,"code":"E1002",
         "message":"找不到这个导出文件。可能是它已经被撤销或删除，……"}
```

`{file}` **确实**吃掉了 `undo`，但**"声明在之后"根本救不了** ——
因为 `undo` 那条路由**只声明了 `POST`**，而 `{file}` 是 `GET`。
**两者不在同一个"方法空间"里**：`GET .../export/undo` 从来不会
撞上一条只有 `POST` 的路由，它只会一路落到 `{file}`。
所以"顺序"在这里是**伪因** —— 顺序对了，坑还在。

**真因**：`undo` 是个**字面量**路径段，而 `{file}` 是**通配**路径段。
只要 `{file}` 存在，任何"`/export/<字面量>` 的 GET"都会被它接住。
顺序只决定"同方法下谁先匹配"，管不了"这个方法有没有别的候选"。

**修法**：显式补一条 `GET /meetings/{id}/export/undo` **占位路由**，
声明在 `{file}` 之前，把"方法用错"如实报出来。

**为什么必须显式报出来**：`undo` 是用户可能在地址栏手敲的路径。
回 E1002 会让用户去"导出记录"里翻那个不存在的 `undo` 文件；
真因却是"这个地址只支持 POST"。**报错必须能指向真因。**

**★ 修的时候又踩了第二层**：我第一版写
`raise MmwfError(..., http_status=405)` —— 想让 HTTP 状态码变 405。
**静默无效**：`@app.exception_handler(MmwfError)` 是**单一实例**注册的
（`main.py`），它把 `status_code` **写死成 200**；我加的那个
`http_status` 字段**没有任何地方会去读它**。

更关键的是：**信封约定就是"一切响应恒 200 + `ok/code`"**，这是 SAD 定的、
前端按它解析的。为一条占位路由破这个例，是拿**系统级不变量**换
**端点级的小便利**。所以最终**老老实实回 200 + E1001**，
理由写进 `user_message`。

**验收判据也跟着改**：不再断言 `status_code in {404, 405}`
（那是我按"想要的状态码"编出来的），改断言**两条性质**：

1. 不能返回**文件字节流**（`content-type` 必须是 JSON、无下载头）；
2. 不能报 **E1002**（"找不到这个导出文件"）——那是最迷惑人的假象。

判据要落在**这件事的性质**上，而不是一个我顺手挑的数字上。
（另加一条对照：`POST .../export/undo` 仍要能正常撤销 ——
"加占位路由顺手把功能路由遮住"是这类改动的典型翻车方式。）

### 坑 16 ★★ `ExportServiceError` / `ReviewServiceError` 不是 `MmwfError` → 被包成 E9001

**本卡验收期抓到的最有价值的一个真缺陷**，且是**跨模块**的。

排查过程：验收脚本里一条"导出撤销"的对照用例红了，返回
`E9001「程序遇到一个未预期的问题」`。但同样的调用在**独立脚本**里
一切正常 —— 于是把端点函数单独调、再用 `raise_server_exceptions=False`
的 TestClient 调，都还是绿。最后在测试文件里挂了个**临时 loud handler**
把被吞的异常打出来，才看到真因：

```text
mmwf.app.services.export.ExportServiceError:
    没有找到任何记录稿（record/v*.md）。请先运行 review 生成记录稿。
```

**根因**：`ExportServiceError(RuntimeError)` —— **不是 `MmwfError`**。
API 层只注册了两个处理器：

| 处理器 | 接住的异常 | 结果 |
|:---|:---|:---|
| `@app.exception_handler(MmwfError)` | 业务异常 | 按 `code` 渲染成**人话** |
| `@app.exception_handler(Exception)` | 其他一切 | **E9001 + 请把编号告诉技术人员** |

`RuntimeError` 落在第二档 → **E9001**。

**为什么这个坑特别值得记**：

- 它踩中的是**最常见**的路径。"建完会议、还没生成记录稿就点导出"
  是**首次使用的正常操作顺序**，不是异常。用户看到的却是
  「程序遇到一个未预期的问题，请把编号告诉技术人员」——
  用户去报障，而正确答案只是"你还没生成记录稿"。
- **它不是本卡新引入的**，是存量缺陷。`review.py` 的模块文档里
  **早就写过同款后果**（"*抛 `ReviewServiceError`，被包成 E9001 ——
  整条流水线一步都走不动*"），但当时的修法是**绕过它**
  （放宽 `ALLOWED_PREV_STATES` 让那道错的门槛不拦人）——
  根因留在原地。**绕过 ≠ 修好。**
- 同类缺陷还有第二处：`ReviewServiceError(RuntimeError)`，一模一样。

**修法**（两处同款）：

```python
class ExportServiceError(MmwfError):        # 原：RuntimeError
    code = "E1002"

    def __init__(self, detail: str = "", **ctx: Any) -> None:
        # ⚠️ 必须显式写 __init__：MmwfError 是 dataclass，第一个字段
        #    就是 code —— 直接 ExportServiceError("一句话") 会把那句话
        #    **当成错误码**塞进 code，to_dict() 吐出来的 code 成了用户那句话。
        super().__init__(code=type(self).code, detail=detail, context=ctx)
```

**`__init__` 那一段是踩过的**：改了基类之后如果不写 `__init__`，
现有几十处 `raise ExportServiceError("...")`（位置参数）会把消息串
当成 `code`。用 `type(self).code` 取**子类自己的** `code`，
这样 `ExportBlockedError`（`code="E5001"`）继续映射 E5001，不受影响。

**怎么防**：本卡附加 A 里加一条专门的反向验证 ——
"没有记录稿时导出**必须是业务错误**"，并断言 `code != "E9001"`。
更一般的教训：**凡是 `app/services/` 里抛的异常，都必须继承
`MmwfError`**，否则用户看到的一定是 E9001。这条值得进编码规范。

### 坑 17 ★ 验收断言不能"按我以为的文案"写

标准 4 判"文案点明是内置模板"时，我按注释里的词写了找 `"内置"`；
实测产品文案是「这是**软件自带**的模板，不能直接改。如果你只想改
这一场的写法，请改用「另存为新模板」。」—— 找不到"内置"，假红。

**产品文案比我的断言更好**（更口语，还给了出路）。
**断言要跟着产品走，不是产品跟着断言走。** 顺手把断言放宽为
接受两种说法，并**加了一条"文案给了出路"**（含"另存为"或"新建"）——
这是从产品实际文案里学到的、值得固化的好设计：
**拒绝时给替代方案。**

### 坑 18 ★ 用字符串搜代码 = 假红制造机

附加 B 要验"api 层不许 `import sqlite3`"，第一版写的是：

```python
assert "import sqlite3" not in routes_py.read_text()
```

**假红**：`routes.py` 的**注释和 docstring** 里，为了讲清这条禁令，
逐字出现过 `import sqlite3`。文本匹配把"遵守规则的说明"
当成了"违规代码"。

**修法**：用 **AST** 解析，只看真正的 `ast.Import` / `ast.ImportFrom`
节点。顺带在上面那条断言旁边**反向加一条**
`assert "import sqlite3" in 源码文本` —— 证明"这句确实出现在注释里、
而 AST 判据没被它误伤"。**既证明检查有效，也证明它不误报。**

### 坑 19 ★★ `difflib` 会合并相邻的"删+改"，`removed` 会恒为 0

标准 6 第一版构造的是"**删一段 + 改一段 + 尾加一段**"放进**一对**版本里，
结果 `removed` 恒为 0。查下来：

```text
输入：old=[头段, 待删段, 待改段(旧), …]
      new=[         待改段(新), …]
difflib 输出：{'type':'changed', 'old':[头段, 待改段(旧)], 'new':[待改段(新)]}
                                                        ← 合并成一个 replace
```

**这不是产品 bug**：`SequenceMatcher` 按 **opcode** 切块，
"2 行换成 1 行"比"删 1 行 + 改 1 行"**代价更低**，所以它选了前者。
它**无从知道**我的"本意"是删一段又改一段。

**第二版**我在待删段和待改段之间插了一个"不变段"隔开 —— **仍然被合并**，
因为那个不变段比"合并替换"更贵。

**教训（本卡最实用的一条）**：要单独验某一类 diff，
**必须让那一类在整篇里是唯一的变量**。硬塞进一对版本里，
测的是 `difflib` 的合并策略，不是我们的语义。

**修法**：改成**三对独立版本**，每对只变一件事
（只改 / 只删 / 只加），各自断言"恰好 1 处该类、其余为 0"。
顺带确认了干净的单段删除**能**正确析出 `removed`。

**★ 并且补上了最该有的那条反向断言**：
前面所有断言形态都是"**不**在 `unchanged` 里" ——
如果 `unchanged` 是**空的**，它们**全部成立**！
一个"把每段都标 changed"的实现照样能全过。
所以必须加："**4 个真没动的段落全部仍是 `unchanged`**"。

### 坑 20 ★ 折叠会让"5 段"变成"1 块"，别按段数断言

标准 6 里"同一版对比自己"我原本断言 `unchanged == 5`，实测是 **1** ——
因为 `MAX_UNCHANGED_LINES=40` 的**折叠**逻辑（裁决 D3）会把长串未变行
收成**一个** `unchanged` 块，折掉多少记在 `elided` 里。

折叠是**有意**的设计（500 段记录稿的响应体会大到没法用）。
**判据要落在语义上**：`changed/removed/added 全 0` + **内容没丢**
（5 段原文都能在摊平后的 `unchanged` 里找到），而不是"块数等于段数"。

### 坑 21 ★ `Path("\x00").name` 不抛错，白名单**挡不住** NUL

写穿越白名单时我按 `Path(file).name == file` 判，以为这一条就够了。
实测：

```text
Path('\x00').name == '\x00'   → True    ← 白名单放行！
Path('..').name   == '..'     → True    ← 白名单放行！
Path('.').name    == '.'      → False   ← 挡得住
Path('a/b.docx').name == 'a/b.docx' → False  ← 挡得住
```

**`\x00` 和 `..` 都能骗过白名单**。所以端点里**必须**额外显式拦：
空串 / `"."` / `".."` / 含 `\x00` / 含 `%` 编码残留。
本卡端点的判据层 11 例全绿就是靠这几条叠加，不是靠白名单一条。

**另一条实测**：`\x00` **发不出 HTTP 请求** —— httpx 在客户端就抛
`InvalidURL: Invalid non-printable ASCII character in URL`。
所以这一层没有可测对象，它的判据**只能**在"直调端点函数"那层验。
别在 HTTP 层断言它 —— 那会红在客户端，看着像服务端的问题。

### 坑 22 ★ 加审计动作会触发"动作白名单回归锁"，**必须同步改**

本卡给 `infra/audit.ACTIONS` 加了 `export_download`（下载也要留痕：
部署手册 §6.2「导出记录」要能回答"这份纪要**流向了谁**"，
只记"生成过"答不了）。全量回归立刻红了一条：

```text
tests/unit/test_audit.py::test_action_whitelist_exactly_matches_construction_card
AssertionError: Extra items in the left set: 'export_download'
```

**这条红是好事** —— 它是 T1-04 就埋下的"动作白名单回归锁"，
专门防"有人悄悄加了动作没登记"。它留了 `sanctioned_extensions`
这个口子，就是要**逼你写明理由**，而不是让你把断言改松。

**做法**：把 `export_download` 加进 `sanctioned_extensions`，
并写清"为什么它不能并入已有的 `export`"：

| 动作 | 记的是 | 能否互相替代 |
|:---|:---|:---|
| `export`（T1-04 已有） | **生成了**导出文件 | ✗ |
| `export_download`（T1-16 新增） | **有人把文件取走了** | ✗ |

文件静静躺在磁盘上，和被人下载到 U 盘上，在保密审计上是**两件事** ——
后者才是核查项真正关心的那件。

**教训**：**改白名单/枚举这类"中央登记表"时，先去 grep 有没有回归锁**。
这次是测试**主动**告诉我漏了，但如果我先跑端到端、后跑全量，
就会先看到"下载功能正常"的假象。

### 坑 23 ★ 前卡验收里的"端点总数"快照会**永久变红** —— 该删的是断言，不是产品

跑"前卡验收全部仍绿"时，`accept_t1_15.py` 报：

```text
✗ 端点总数 = 25（T1-14 收工时为 21）（实测 31）
```

**这不是产品回归** —— T1-15 交付时总数确实是 25，本卡补完 5 端点后变成 31。
红的是那条**快照断言** `len(actual) == 25`。

**判断过程（这一步很重要，别急着改产品）**：

1. 先看**其余 10 项**：T1-15 的 2–9、附加 A/B **全绿** —— 说明 T1-15 交付的
   **功能本身**没有回归（分页、截断告知、PATCH 审计、批量接受、追加音频全对）。
2. 只有标准 1 的一条**数字**断言红了，且红的数值**正是本卡该造成的**。
3. 再看 `accept_t1_13`：裸跑 9/10，加 `--skip-3c` 后 **6/6** ——
   它也**不是**回归，标准 3c 需要真网络（本沙箱拦截），一直如此。

**结论**：这是**断言选错了对象**。一张卡该守的是
"**本卡新增的端点存在**"（`new_four` 那条已经守了），
而不是"全局总数永远等于我交付那天的数字"。

**做法**：**删掉那条快照断言**，保留与总数无关的性质断言。
**全局水位**由 `tests/unit/test_api.py::test_protected_endpoint_list_matches_router`
守 —— 它每次从真实路由器反查 + **逐条点名**核对 SAD §9.1，
那才是唯一该有总数断言的地方。

**为什么值得单独记一条**：如果不删，**每张新卡都要去改一遍所有旧卡的脚本**，
那是纯摩擦；而如果为了让它绿，去把总数改回 25 或改成"≥25"，
就等于**把水位检查废掉**（`≥25` 永远成立，等于没查）。
**删断言 + 把水位归口到一处**，是唯一不制造长期负担又不丢检查的做法。

**顺带确认没有第二条**：`grep 'len(actual) ==' tools/accept_t1_*.py` ——
T1-14 及更早用的是"子集包含"判据，不是总数快照，所以只有 T1-15 这一处。

### 坑 15 ★ SAD 只写了 `GET / POST / PUT /templates`，没有路径参数

`PUT /templates` 没有主键就**无法表达"改哪一个"**。本卡补白为
`PUT /templates/{template_id}`，对齐 T1-14 裁决 D1
（`PUT/DELETE /glossary/{entry_id}` 用路径参数）——**理由相同**：
带 body 的 PUT/DELETE 会被中间层丢弃。

**这是"文档不全"而不是"文档写错"**：SAD 那一行是**分组简写**
（`/glossary` 那行也是把 4 个方法并成一行）。补白要**写进施工卡**，
不要悄悄改契约。
