### 2.2 主进程要点（施工文档原文，注意三处补强）

```javascript
// src/desktop/main.js
const { app, BrowserWindow } = require('electron');
const { spawn } = require('child_process');
const path = require('path');
const fs = require('fs');
const os = require('os');

let pyProc = null;

function startBackend() {
  return new Promise((resolve, reject) => {
    // ⚠️ 补强 ①：开发期与打包期路径不同。
    // 打包后是 resourcesPath/python/...，开发期要能指向项目 .venv。
    // 别硬编码 resourcesPath —— 否则本地根本跑不起来，只能等打包才测。
    const py = process.platform === 'win32'
      ? path.join(resourcesRoot(), 'python', 'python.exe')
      : path.join(resourcesRoot(), 'python', 'bin', 'python');

    pyProc = spawn(py, ['-m', 'mmwf.main'], {
      cwd: path.join(resourcesRoot(), 'app'),
      env: { ...process.env, PYTHONUTF8: '1', PYTHONIOENCODING: 'utf-8' },
      stdio: ['ignore', 'pipe', 'pipe'],
    });

    // ⚠️ 补强 ②：后端 stdout/stderr 必须**转发到日志**，不能 ignore。
    // 后端启动失败（缺依赖、端口占用、迁移报错）时，
    // 这是唯一能知道"为什么"的地方 —— 否则前端只能白屏。
    pyProc.stdout.on('data', d => log('backend', d));
    pyProc.stderr.on('data', d => log('backend', d));
    pyProc.on('exit', (code) => onBackendExit(code));   // 见验收第 2 条

    // 路径契约：与 Python 侧 deps.app_dir() 逐段对齐（SAD §11）
    const portFile  = path.join(os.homedir(), 'AppData', 'Local', 'mmwf', 'port');
    const tokenFile = path.join(os.homedir(), 'AppData', 'Local', 'mmwf', 'session.token');

    const deadline = Date.now() + 30000;
    const timer = setInterval(() => {
      if (Date.now() > deadline) { clearInterval(timer); reject(new Error('后端启动超时')); return; }
      if (fs.existsSync(portFile) && fs.existsSync(tokenFile)) {
        clearInterval(timer);
        resolve({
          port: parseInt(fs.readFileSync(portFile, 'utf-8').trim(), 10),
          token: fs.readFileSync(tokenFile, 'utf-8').trim(),
        });
      }
    }, 300);
  });
}
```

**⚠️ 补强 ③：端口文件是"先落文件、后 listen"（T1-11 实测）。**
文件出现 ≠ 能连接。Electron 拿到 port 后**先探一次 TCP**，
连不上就重试 —— 否则第一次请求必吃"连接被拒"（那是竞态，不是缺陷）。
（Python 侧 `mmwf.main` 的写入顺序与此一致，别试图改那边。）

### 2.3 渲染进程 API 客户端（信封解包是核心）

```javascript
// src/desktop/renderer/api-client.js
let BASE = null, TOKEN = null;

export async function init() {
  const info = await window.mmwf.getBackendInfo();
  BASE = `http://127.0.0.1:${info.port}/api/v1`;
  TOKEN = info.token;
}

export async function call(method, path, body) {
  const res = await fetch(`${BASE}${path}`, {
    method,
    headers: { 'Content-Type': 'application/json', 'X-MMWF-Token': TOKEN },
    body: body ? JSON.stringify(body) : undefined,
  });
  const env = await res.json();
  // ★ 后端**永远返回 200**，业务成败看 env.ok（SAD §6.3）。
  // 所以这里绝不能写 `if (!res.ok)` —— 那永远为 false，错误会被静默吞掉。
  if (!env.ok) throw new AppError(env.code, env.message);
  return env.data;
}
```

**⚠️ 关于 `webSecurity`（施工文档"常见坑"第三条）**
先**不要**加 `webPreferences: { webSecurity: false }`。本机回环通常不受 CORS 限制，
真报错再加，且**必须**在代码注释里写死"仅本机回环专用"。
默认把这条**留空**，等真的撞上再由报错驱动（安全默认值优先）。

### 关于"文案快照测试"怎么落地（本卡最关键的一条）

Electron 界面**没法用 pytest 直接测**，但契约是"**界面文案不得含工程词**"。
可行做法（按成本从低到高）：

1. **静态扫描（首选）**：把所有 `renderer/**` 里的**面向用户字符串**
   抽出来，对黑名单 `检查点/schema/幂等/HITL/checkpoint/中间产物/溯源`
   做全量 `grep`。零依赖、确定性强、能进 CI。
   → **本卡默认用这个**，`accept_t1_12.py` 实现为纯静态检查。
2. 运行时快照（可选，二期）：起 Electron 后用 DOM 快照比对。
   成本高、依赖图形环境，本卡**不做**。

## 四、常见坑（施工卡原文 + T1-11 实战补充）

| # | 坑 | 处置 |
|:---|:---|:---|
| 1 | Electron 打包 Python 运行时体积大（含 torch 数 GB） | **一期不打包 Python**，改为引导安装 + 首次运行下载离线包；二期优化。`requirements.lock` 必须随包分发 |
| 2 | Windows `spawn` 子进程中文乱码 | 必须设 `PYTHONUTF8=1`（铁律 1 的运行时版本） |
| 3 | fetch 到 `127.0.0.1` 报跨域 | **先别加 `webSecurity: false`**；真报错再加，且注释写明"仅本机回环专用" |
| 4 | **端口文件先落、listen 后到**（T1-11 实测） | 拿到 port 后先探 TCP，连不上重试 |
| 5 | 后端 stdout/stderr 被 `ignore` | **必须转发到日志**，否则启动失败只能白屏 |
| 6 | 用 `res.ok` 判成功 | 后端**永远 200**；判 `env.ok`。写成 `res.ok` 错误会被静默吞掉 |
| 7 | 硬编码打包路径 | 开发期/打包期路径要分支，别等到打包才第一次跑 |
| 8 | 终端用户重开会话后旧令牌失效 | 前端要处理 `E6001`：重读一次 token 文件重试，不行就提示"请重启程序"（T1-11 已定契约） |
