# 会议纪要工作台使用说明

适用对象：办公室、文秘人员及负责安装维护的 IT 人员。按当前仓库实现编写（2026-10-15）。第一次使用先读第 1～3 节；安装、接口和故障排查交给 IT。设计文档描述的是目标，本文只说明已实现入口；自动测试通过不等于目标机验收通过。

## 1. 这个程序能做什么、不能做什么

程序在本机整理会议材料：已有录音 → 转写与复核 → 记录稿 → 确认议题 → 起草纪要 → 审定 → 导出和归档。也能直接使用已有文字记录稿，跳过转写。两次主要人工确认分别是 **“待确认议题”（G2）** 和 **“待审定纪要”（G3）**；低置信转写仍需另行核对。

- 全程离线，本地模型须事先安装；不能调用云端 AI，也不能靠联网补齐缺少的模型。
- 每条结论必须有记录稿原文依据。系统找不到依据时会停止成文；人工编辑也要重新检查依据。
- 不负责录音、视频处理、语音合成、自动定密，也没有可用的自动说话人分离功能。姓名、数字、机构、责任人和期限都要核实。
- 当前桌面只支持粘贴文字记录稿；音频投递和逐段修改已有后端接口，需要 IT 辅助。没有桌面选音频文件、回听播放器、完整逐段复核或模板管理页面，不能照设计稿寻找这些按钮。
- 当前默认采用朴素内容抽取，不代表已经启用大模型。系统生成的材料仍需人审定，不能代替领导审批或本单位的保密手续。

## 2. 安装与启动

### 2.1 Windows 目标机：优先用免安装交付目录

1. 由 IT 从受控介质交付完整目录，并核对交付哈希清单。仓库打包位置为 `dist/mmwf-portable/win-unpacked/`；不能只复制一个可执行文件。具体检查见 [T1-18 交付目录手工检查指引](T1-18-交付目录手工检查指引.md)。
2. 把目录放在允许写入的受控位置。双击其中的 `mmwf.exe`，不需要另装 Python、Node 或联网安装。
3. 在“开始使用”填写操作人，点“进入工作台”。此姓名用于操作留痕，并非密码账号。
4. 不用时关闭窗口；再次打开前确认上一会话已退出。同机只允许一个会话，第二次打开会提示占用并切回已有窗口。不要同时另起手工后端。

IT 须按所用功能预装：音频处理的 ffmpeg / ffprobe、FunASR 本地模型；启用大模型抽取所需的 Ollama 与本地模型；转换 .doc 或 PDF 所需的 LibreOffice，以及有授权的公文字体。桌面能打开并不证明这些条件齐备。首次启动会自动建库/升级；无需操作人员手工建表。

交付目录的 `resources/config/` 是配置，`resources/python/` 是运行时，`resources/app/` 是后端和工具，`resources/data/` 是首次运行创建的业务数据。升级前停机备份，由 IT 按交付说明替换程序，**保留 `resources/data/`**。交付物未签名的情况及 Windows 沙箱兼容取舍见 T1-18 指引。

### 2.2 IT 用源码启动

以下从仓库根目录执行。源码环境要求 Python 3.11～3.13，桌面另需 Node.js 18+。依赖、模型和外部工具须由 IT 预先准备；下面的安装命令用于准备环境，不是让受控目标机联网安装。

```sh
python -m venv .venv
```

Windows 激活虚拟环境后，`python` 应来自本项目 `.venv`：

```bat
.venv\Scripts\activate
pip install -e ".[dev,infra]"
pip install -e ".[api]"
pip install -e ".[graph]"
pip install -e ".[docx]"
pip install -e ".[keystore]"
python tools/migrate.py
python -m mmwf.main
```

需要真实语音引擎时，另准备 `pip install -e ".[asr]"` 对应的依赖及模型。首次建库用 `tools/migrate.py`，以后运行会升级到最新迁移；已有库先备份。它不负责把历史明文业务数据重新加密。

桌面与手工后端是两种启动方式。**先停止手工后端**，再启动桌面；桌面会自动拉起后端，不会附着到手工服务：

```sh
cd src/desktop
npm install
npm start
```

macOS / Linux 仅作开发说明，不能据此认定 Windows 或信创目标机已通过验收。激活和手工启动示例：

```sh
source .venv/bin/activate
.venv/bin/python tools/migrate.py
PYTHONPATH=src .venv/bin/python -m mmwf.main
```

### 2.3 端口、令牌与启动故障

默认 `config/app.yaml` 的 `app.host` 为 `127.0.0.1`、`app.port` 为 `0`，实际端口随机分配。启动文件为：

| 系统 | 端口文件 | 令牌文件 |
|---|---|---|
| Windows | `%LOCALAPPDATA%\mmwf\port` | `%LOCALAPPDATA%\mmwf\session.token` |
| 其它系统通常位置 | `~/mmwf/port` | `~/mmwf/session.token` |

Python 若设置了 `LOCALAPPDATA`，会优先使用它；桌面 Windows 使用用户主目录下的 `AppData/Local/mmwf/`，其它系统使用 `~/mmwf/`。自定义或重定向用户目录时 IT 要核对两侧一致；开发 Mac/Linux 不要随意设置 `LOCALAPPDATA`。这些启动文件不是业务数据，令牌每次启动更新，不能转发给他人。

启动失败先查看 Windows 的 `%LOCALAPPDATA%\mmwf\logs\backend.log`（其它系统 `~/mmwf/logs/backend.log`），再由 IT 检查目录权限、依赖、配置和残留会话。不要反复双击或自行删除数据库文件。

## 3. 从新建会议到归档

### 3.1 准备材料、新建会议

**桌面文字稿方式：** 填写“会议名称”“主持人”“参会人（用顿号或逗号分隔）”，把全文粘贴到“会议记录稿”，点“建立会议”。会议名称和文字稿不能为空；程序随即开始处理。

每句尽量保留真实时间码和说话人，例如 `[00:00:12] 张三：今天研究季度工作安排。`。没有时间码的文字可以整理，但不能当作真实音频跳转依据。空稿、只有标题或不完整正文应先补齐。会议时间、地点、模板、密级等当前桌面投递页未提供的字段，由 IT 在建会接口填写，或在后续允许的结构化编辑中核实补充；不要靠模型猜测。

**音频方式（IT 辅助）：** 建会时提交本机 `audio_paths`，检查每个文件的接入结果后启动处理，接口见附录。支持 wav、mp3、m4a、wma、amr、flac、aac、ogg。保留原始录音至处理完成，核对批量接入的成功、失败和警告；请求成功不等于全部文件成功。

追加音频接口仅接收文件，**不会自动转写，也不会合并到已有稿件**。当前流程不能保证追加后重新启动就纳入全部录音；要处理新增录音，宜用完整音频列表新建会议。

### 3.2 转写、复核和记录稿

音频处理会出现“正在检查音频”“正在转写”；随后整理记录稿。桌面的“文稿”页展示记录稿及可用进度，可点“刷新”。状态“文稿待核对”并不表示所有文字已被人工确认。

1. 优先核对低置信、静音异常、多人重叠及人名、数字、单位名。默认低置信阈值是 `config/thresholds.yaml` 的 `thresholds.asr.low_confidence: 0.70`；置信度只是辅助，分数高也可能识别错。
2. 当前桌面没有逐段改字/接受界面，由 IT 读取转写分段、协助修改；批量接受只会通过分数达标且无异常标记的段落。不要把阈值降到零来跳过复核。
3. 阅读记录稿并核对缺失信息。现有处理链会生成带待核对提示的记录稿并继续梳理议题，**不会自动停下来等逐段复核完成**；G2 之前必须把关键事实核清。

逐段 API 修改不等于已经重建当前记录稿、议题和纪要。若需要修正来源，先整理出完整正确的文字记录稿，再以该稿新建会议重新处理；不能只改一个分段就批准旧纪要。

### 3.3 G2：“待确认议题”

逐条看“原始内容”“系统抽取结果”“风险评级”“抽取依据”。点击“抽取依据”下的段号和时间码，会定位并展示原文片段；来源置信不足时重点检查。文案表中的“查看原文出处”描述这一用途，当前页面的实际入口是段号和时间码，不能当作已经实现录音回听。

“只显示待确认项”默认开启。勾选“已核对（未提交）”只是本页草稿，尚未提交；刷新会丢失未提交的编辑和勾选，需要重新核对。关掉过滤可再看全部议题。提交前可点“查看差异：系统生成版 / 人工修改版”查看段落差异。

| 按钮（界面原文） | 何时用 | 结果 |
|---|---|---|
| 确认无误，继续 | 原样正确、无需改动 | 使用系统稿，继续起草纪要 |
| 改完继续 | 已在表单修正内容 | 提交修改稿，从后续步骤继续，不重转写、不重抽取 |
| 退回重做 | 议题抽取整体有问题 | 重新抽取议题，再次等待确认；不重新转写 |

**改了内容应点“改完继续”**，点“确认无误，继续”不会提交本页编辑。来源不能通过改写引用来伪造；若原稿有错，先按 3.2 修正来源。

默认等待 **72 小时**未提交会自动退回，而非自动同意；G2 重新抽取，G3 重新组装。后台运行时约每分钟巡检，关闭期间不会处理，重启后再检查已到期事项。连续超时需要安排人员处理；旧页面可能已失效，应重新载入当前待确认内容，不要反复提交旧稿。超时设置为 `thresholds.gate.approval_timeout_hours`。

### 3.4 生成纪要、G3：“待审定纪要”

G2 通过后，程序依次“正在起草纪要”“正在自检”“正在成文”，到“待审定纪要”再停下。

1. 逐项核对标题、会议时间地点、主持人、参会人员，以及每个议题的讨论、议定事项、责任人、期限和需决策事项。
2. **使用结构化表单编辑。** 当前部分字段名仍显示英文：`title` 是标题，`meeting_time` 是时间，`location` 是地点，`host` 是主持人，`attendees` 是参会人员；议题的 `name`、`discussion`、`readings` 分别为名称、讨论、领读语，事项的 `content`、`owner`、`deadline` 分别为内容、责任人、期限。多人或多条领读语按行填写。来源只读。
3. 查看差异预览和问题清单，核对修改后的正文及依据。不能直接提交任意修改的 Markdown 正文来绕过结构化校验。
4. 原稿正确点“审定通过”；表单改好后点“改完继续”；需要重新组装则点“退回修改”。“退回修改”只重新组装当前纪要，不重新抽取议题，也不会自动修正错误来源。

缺责任人时系统可标“暂无”，缺少要素可标“待补充”；这些不是事实已齐备。必须查证，不能凭空补负责人或期限。人名、金额等一致性警告通常不自动阻止审定，仍须人工处理。

### 3.5 导出 DOCX、.doc、PDF，以及归档与撤销

G3 通过并复检成功后，程序自动导出、归档，状态显示“已完成”；**无需再找一个“归档”按钮**。归档保存处理材料和交付登记，不代表已向领导发送或移交档案部门。

1. 桌面导出页选择“会议纪要”或“记录稿”，选择“DOCX”或“PDF（普通 PDF）”，点“导出为文档”，成功后点“下载文档”。
2. **PDF 只支持已审定纪要**，记录稿禁选 PDF。它由同源 DOCX 经 LibreOffice 转换，是普通 PDF，不承诺 PDF/A；转换失败没有可用 PDF 链接。查看字体警告，并人工打开核对分页、字体、表格、页码和缺字。
3. 需要旧版 `.doc` 时请 IT 检查 `config/models.yaml` 的 `export.enable_doc_export` 和 `export.soffice_path`，通过 DOCX 导出同时转换。桌面没有独立 `.doc` 格式选项；主下载入口对应所选 DOCX/PDF，额外 `.doc` 须由 IT 检查返回的转换状态并取文件。缺 LibreOffice 时 `.doc` 可能跳过，不能把 DOCX 成功当作 .doc 已生成。
4. 相同内容重复导出通常复用已有文件。误导出可点“撤销导出”，删除当前选中文件及相应登记；PDF 同时撤销其来源登记。已下载到其它位置、已打印或已转交的副本不会被收回，须按单位流程处理。撤销不撤回 G3 审定，也不删除会议和审计记录；DOCX、.doc、PDF 是不同文件，须分别核查。

### 3.6 查看和下载问题清单

在 G3 看每条问题的级别、位置和说明，点“下载问题清单”得到 UTF-8 文本；差异预览还能显示编辑后的检查结果。**预览不保存，下载读取的是服务器已保存清单**，未提交修改的预览结果不能当作已经提交。

“处理失败”的会议同样可由 IT 读取、下载问题清单（附录接口）；当前失败页没有该下载按钮。看到“历史检查未完成”不能理解为“没有问题”。清单含会议信息，按原会议密级管理。

## 4. 模板与公文语体

内置四类模板，当前文件中的 `meta.version` 均为 `2`（模板 ID 末尾的 v1 不等于当前版本号）：

| 模板名称 | YAML 文件（位于 `config/templates/`） | 模板 ID |
|---|---|---|
| 党组会议纪要 | `party-group.yaml` | `tpl-party-group-v1` |
| 专题会议纪要 | `special-topic.yaml` | `tpl-special-topic-v1` |
| 协调会议纪要 | `coordination.yaml` | `tpl-coordination-v1` |
| 工作例会议纪要 | `regular-meeting.yaml` | `tpl-regular-meeting-v1` |

共同必填：标题（4～30 字符）、会议时间、地点、主持人、参会人员、至少一个议题。工作例会要求至少一名参会人；其它三类至少两名参会人并至少一条议定事项。记录人等其它事实也应按实际补齐。

四类均禁用“大家觉得、差不多、可能吧、应该是、反正、搞定、弄一下、有点问题”。常用领读语为“会议认为、会议指出、会议强调、会议要求”；各模板另有不同允许项，如党组会的“会议听取、会议审议”、协调会的“经协调、会议明确”。领读语必须符合实际意思，不能把一般讨论提升成会议决定。

**维护由 IT 完成，当前无桌面模板编辑页：**

- 内置模板来自 `config/templates/*.yaml`，读取时重新读文件。调整 `required_elements`、`section_order`、`style.readings_allowed`、`style.readings_forbidden`；章节名称调整时同步 `style.section_bindings`，保留正确内容绑定。修改前备份，使用 UTF-8，递增 `meta.version` 并保留旧文件与变更记录。内置历史不自动存入数据库。
- 自建模板通过模板 API 创建和修改，数据库 `version_no` 由服务端递增，可查询完整历史。API 不能直接修改内置模板；自建时换一个 `template_id`，避免与内置同名而被屏蔽。
- 建会通过 `template_id` 选择模板；未指定时默认工作例会。当前桌面投递页无模板选择器，由 IT 协助。每次成文会固定模板快照；改 YAML 不会把已经送审的稿件自动换成新版。先用公开或合成材料试用新模板，再用于正式材料。

启用本地大模型抽取需 IT 将 `config/extraction.yaml` 的 `extraction.engine` 从 `naive` 改为 `llm`，并核对 `config/models.yaml` 的 `llm.base_url`、`llm.model`、`llm.timeout_seconds`；模型服务须在本机。配置调整后重启并验证，不能把换开关当成真模型质量验收。

## 5. “处理失败”和 E3002 怎么办

E3002 有两种含义，先看完整提示：

- **过程警告：**“纪要结构自检未通过，已自动重试。若反复出现，请核对文稿是否完整。”程序可能仍在自动重试，先等待并观察状态。
- **停止成文：**“纪要中有内容找不到原文依据，已停止成文。请核对问题清单并修正来源后重试。”这是依据不足，不能批准或通过旧文件绕过去。

停止成文时：记录会议编号和错误提示 → 请 IT 下载问题清单 → 按问题位置检查原文是否缺失、引用是否错段、编辑是否增加了原文没有的事实 → 补齐真实来源或去掉无依据结论。若来源需要修改，使用修正后的完整记录稿新建会议处理。若源文完整仍反复失败，交 IT 检查模型与来源绑定，保留问题清单和编号，不反复点导出来尝试放行。

| 问题清单级别 | 操作人员如何处理 |
|---|---|
| `error` | 优先检查；原文缺失、引用无效或不匹配等阻断问题会停止成文 |
| `warning` | 必须人工核对；如要素缺失、人名数字差异、禁用语、原文字词近似匹配，通常不会自动挡住流程 |
| `info` | 了解处理说明，核对是否影响本次会议含义 |

级别不等于是否阻断，接口另有 `blocking`。只有特定原文依据错误作为硬阻断；不要把“能继续”当作“内容正确”。问题清单的 error/warning/info 与错误码的 warning/error/fatal 是两套标记。

## 6. 常见错误码与处理

下表抄录 `src/mmwf/domain/errors.py` 的登记文案；具体场景可能给出更精确提示，以界面完整消息为准。报障时提供会议编号、错误码、`trace_id` 和操作时间，正文及日志仅在授权范围内交接。

| 错误码 | 代码中的使用者文案 | 建议处理 |
|---|---|---|
| E1001 | 这个音频文件的格式不支持。请转成 wav、mp3、m4a、wma、amr、flac、aac 或 ogg 后再试。 | 改成支持格式；若是填写错误，按具体字段提示修改。 |
| E1002 | 找不到要处理的文件。请确认文件没有被移动或删除。 | 检查本机文件路径；会议或导出链接失效时重新打开当前记录。 |
| E1003 | 这个音频文件读不出来，可能已经损坏。请换一份完整的录音后重试。 | 换完整录音；若提示内置模板不可修改，改建自建模板。 |

## 7. 安全与保密

- 服务只监听本机 `127.0.0.1`，API 需要每次启动生成的令牌，桌面和后端均有单实例保护。不要开放远程代理、共享令牌或把监听地址改为对外地址。没有密码账号和多人权限管理，操作人姓名不能当身份认证。
- 材料仅在获准设备和范围内使用，不上传云盘、云端 AI、邮件或外网故障平台。模型、依赖和更新由 IT 通过受控流程提前准备。软件离线不能代替整机保密检测。
- 由 IT 调用 `/system/selfcheck`（完整路径见附录）。看 `data.network_probe.outbound_connections` 是否为 0、监听是否仅回环，并同时看各项 `verdict` 和整体 `overall`；`degraded` 表示有项未验证，不是全部正常。自检只看后端本进程，不证明整机或独立模型进程无外发，目标机仍需断网与连接检查。
- 审计记录关键操作，只增不改并用链式哈希检查。IT 定期用 `tools/verify_audit_chain.py` 校验实际业务库；返回 0 表示链完好，1 表示完整性异常，2 表示用法/环境错误。完整性异常应停止使用、封存并按单位流程上报，不自行修复审计记录。报告接口返回 JSON，当前桌面没有审计报告管理页。
- 音频、文稿及数据库敏感字段采用 AES-256-GCM 加密；这不是整个 SQLite 文件都加密。导出目录和文件清单为明文，下载文件也是明文，仍须按密级保存。旧版本历史明文能读但没有自动重加密，升级前须按[目标机清单](目标机与人工核对清单.md)处理。
- 主密钥优先用 `keyring` 托管到系统凭据管理器，Windows 还可用原生凭据管理器；不可用时可能降级到 `data/.master.key` 明文文件，并生成 `KEY_STORAGE_UNHARDENED.txt`。出现此提示交 IT 加固，不要自行删除或替换密钥，已有材料可能再也读不出来。备份和恢复须同时保全正确密钥；跨电脑只复制数据目录不保证能解密。
- 停机后备份整个业务数据目录及恢复所需密钥，限制访问并加密保管。升级保留数据，恢复后校验审计链。不要把令牌、明文密钥、会议正文或未脱敏日志作为普通报障附件外发。

桌面为兼容部分 Windows 办公机，默认关闭 GPU 子进程和渲染层沙箱；IT 可在确认能正常运行的机器上用 `MMWF_STRICT_SANDBOX=1` 恢复严格模式。此取舍须纳入目标机部署检查，详见 T1-18 指引。

## 8. 已知限制与尚未完成的真实验证

完整待办见[目标机与人工核对清单](目标机与人工核对清单.md)，操作取证方法见[人工验证指引](人工验证指引.md)。开发 Mac 上文字稿 API 流程及 DOCX 内容检查，只证明该环境的链路，不代表 Windows 目标机、真实模型或正式版式验收。

| 项目 | 当前证据边界 |
|---|---|
| 真实 ASR | 目标机两小时录音、真实时间戳/标点/术语效果、低置信准确率及端到端仍待验证；替身测试不能证明识别质量 |
| 真实 LLM | 默认 `naive`；真实模型召回率、长文耗时、纯寒暄不编造及公文文风尚未完成目标机验证 |
| Electron | G2/G3 实际三按钮、表单报错、过滤/刷新/差异、来源跳转、问题清单下载和 PDF 操作仍须真实点击核对，源码合同不能替代 |
| Word / WPS / LibreOffice | 正式公文二十项版式、真实 Word 占用文件后的恢复待验；LibreOffice 预览也不等于 Word 渲染 |
| PDF / .doc | 功能已实现，但真实 LibreOffice 转换、同源正文和字体分页、PDF 人工验版仍待目标机；F5.9 真实目标机通过计数为 0，stub 不是转换验收 |
| 硬件、安全、真实会议 | 目标机性能、长时待机、连续任务稳定性、物理断网、跨机拒绝、整机无外发及历史明文处理仍有待办 |
| 放开使用 | 至少 20 场真实会议影子运行、第三方评分及质量红线仍待验，真实计入 0；自动工具通过不会自动授权投入正式使用 |

来源展示不保证有真实时间码；没有原文依据时不能靠人工强行放行。模板缺项、数字人名及语体警告需要人查，软件不能保证事实正确。已归档旧稿缺少新版配对历史时，不会伪造历史重新导出；由 IT 核查已有归档文件。

### 9.3 API 端点速查

下表路径统一加前缀 **`/api/v1`**，实际地址为本机随机端口。所有接口（包括握手、下载）都要求请求头 **`X-MMWF-Token`**。`{meeting_id}`、`{segment_id}`、`{template_id}`、`{version_no}`、`{file}` 是实际编号或文件名的占位符，`{gate}` 为 `G2` / `G3`。

JSON 请求使用 `Content-Type: application/json`。业务响应通常 HTTP 200，须检查 `ok`、`code`、`message`、`data`、`trace_id`，不能只看 HTTP 状态码；成功的文件下载和文本清单直接返回字节。接口文档页关闭，无需寻找在线接口文档。

| 方法 | 路径 | 常用字段/用途 |
|---|---|---|
| POST | `/system/handshake` | 验证当前令牌、返回版本 |
| GET | `/system/selfcheck` | 网络、识别质量、字体、审计链与整体自检 |
| GET | `/system/fonts` | 公文字体预检 |
| POST | `/meetings` | `title`；输入 `audio_paths` 或 `record_markdown`；可填 `meeting_time`、`location`、`host`、`attendees`、`absentees`、`recorder`、`classification`、`template_id`、`operator`；返回 `meeting_id` |
| GET | `/meetings` | 列表，可用 `status`、`limit`；当前没有日期筛选或分页偏移参数 |
| GET | `/meetings/{meeting_id}` | 当前状态及 `data.run.pending_gate.checkpoint_id` |
| POST | `/meetings/{meeting_id}/start` | 启动处理，同步运行至下一待确认点或结束 |
| POST | `/meetings/{meeting_id}/audio` | `audio_paths`；只接入、不自动转写，见 3.1 |
| GET | `/meetings/{meeting_id}/transcript` | `limit`、`offset`、`min_seq`、`max_seq`、`only_review_needed`；看 `page.has_more`、`truncated`，不能漏后续页 |
| PATCH | `/segments/{segment_id}` | `text`、`operator`，可选 `flags`；不传标记表示保留，空数组表示清空 |

| GET | `/meetings/{meeting_id}/topics` | G2 议题及出处展示 |

| GET | `/meetings/{meeting_id}/diff` | 记录稿版本差异：`base`、`compare` |

| GET | `/meetings/{meeting_id}/export/{file:path}` | 接受文件名或导出响应中的 `export/文件名`；拒绝嵌套目录、盘符及穿越，非法路径返回 400 + E1001 |

建会的 `classification` 允许 `public`、`internal`、`work_secret`、`state_secret`，默认 `internal`；只是记录字段，不代替定密授权。建会建议明确选 `template_id`，不要使用设计示例中仓库不存在的模板 ID。

G2 编辑以当前待确认载荷为基准保留 `topics`、`resolutions`、`action_items`；G3 编辑使用 `payload.minutes` 的结构化内容，不伪造来源字段。每轮取最新 `checkpoint_id`，旧编号会被拒绝。`approve` / `edit` 返回 `rerun_nodes=[]`；`reject` 在 G2 重跑 `extract`、在 G3 重跑 `assemble`。不要把 `/start` 当作任意阶段的“重做”接口，也不要直接改数据库或磁盘上的加密文稿来修正内容。

深入安装、备份与事故处置参考[部署运维与保密合规手册](设计文档/04-部署运维与保密合规手册.md)；遇到设计示例与当前接口不一致时，以本仓库实际路由和本文速查为准。
