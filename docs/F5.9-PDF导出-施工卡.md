## 2. 契约（逐条可对照）

### 2.1 输入、审定与转换顺序

PDF 服务入口显式接收 artifact、version、minutes_state、approved 与图侧可用的 minutes_snapshot，沿 `MinutesService.deliver` 校验，不能公开一个接受任意文件路径即可交付 PDF 的旁路。底层转换 helper 只是内部进程接缝，不是交付服务/API。

1. 验证 format 和组合；复用工作流决定默认 artifact；pdf+record 拒绝，禁止因 minutes 失败回退 record。
2. 在既有会议锁内复检当前工作稿（含 grounding、结构与 Markdown 配对、模板/源上下文）；G3 未通过 E4001，硬阻断沿 T2-04 的 ERROR E3002，缺版本 E1002；历史非 final E4001。即使请求历史 final 或已存在 PDF，也先检查当前稿，不能靠缓存逃逸。
3. 复检所选 final，版本号只在 minutes 内解释。用同一配对 Markdown、模板和字体策略走现有 DOCX 渲染；fail 字体策略沿现有 E5001，warning 沿 E5002，不开 disable_hard。不得把记录稿 DOCX 作为纪要输入。
4. 对这份实际 DOCX 转 PDF，命令参数数组为 `[soffice, '--headless', '--convert-to', 'pdf', '--outdir', <隔离工作目录>, <同源docx>]`，capture_output、UTF-8 replace、timeout=180，禁 shell=True。共享 DOC 转换接缝不改变其可选软失败语义。
5. 只有进程成功且本次输出非空、头为 `%PDF-` 才可登记；文件头仅证明基本格式，不证明版式正确。成功后写正式 PDF、来源登记、留档清单和审计，再返回成功。转换失败不登记伪 PDF，不删除原 DOCX/final。

隔离工作目录位于该会议 export 明文区内，唯一命名，finally 清理；复制的 DOCX 字节必须与来源哈希一致。不得在通用系统临时目录遗留明文，不得误认上次遗留的同名 PDF 为新转换成功；会议锁覆盖转换及登记，避免同会并发覆盖。无云端、无网络、无新 Python 依赖。

### 2.2 HTTP 请求与响应

既有地址 `POST /api/v1/meetings/{id}/export`：

```json
{"artifact":"minutes","version":3,"format":"pdf","convert_doc":false}
```

`format` 缺省为 docx，非字符串、未知值或 null 为 E1001；artifact 缺省沿原默认选择，version 沿原校验与版本语义。pdf 时 convert_doc 缺省/false 均不启动可选 DOC，true 或非布尔值报 E1001，避免显式意图被忽略；docx 分支保持旧请求及 doc 字段行为。错误沿既有全局业务信封（HTTP 200 + ok=false/code/trace_id），不能返回 PDF 字节冒充错误或新增局部信封。

DOCX 旧响应键值语义不变。PDF 成功沿同一 ExportResult 序列化合同，`path/sha256/size_bytes/encrypted=false/reused/idempotency_key` 指向 **PDF 主结果**；增加 `format="pdf"`、`source_docx={path,sha256}`、`pdf={status:"ok",path,reason:""}`，保留 meeting_id/version/warnings/font_warnings/warning_codes/doc。pdf 分支 doc.status 为 skipped，reason 明示本请求未要求 DOC。`reused` 只描述本次主 PDF，不借用 DOCX reused。

下载仍用 `GET /api/v1/meetings/{id}/export/{file}`，PDF 回 application/pdf、中文 RFC 5987 文件名、attachment；沿现有路径白名单、check_download 与下载审计。`MinutesService.require_final` / `check_download` 增加 PDF 后缀及来源绑定检查，未知/伪名 PDF 不因“一期记录稿兼容”放行。非法路径 E1001、文件缺失/损坏 E1002、无 final 或来源配对不符 E4001；当前稿阻断仍 E3002。旧已归档文件不追溯删除，但不放宽当前交付检查。

### 2.3 失败、错误码与 UI 状态

| 条件 | 内部转换诊断 | 对显式 PDF 请求的外部结果 |
|:---|:---|:---|
| soffice 未配置且 PATH 无程序，或配置路径不存在 | skipped + 可定位原因 | E5003，提示安装/配置既有 LibreOffice 后重试；无 PDF 链接 |
| 调用 OSError、180 秒超时、非零退出、无输出、空文件、非 PDF 头 | failed + 简短原因 | E5003；不把旧 PDF 或本次 DOCX 当成功结果 |
| 正式文件/登记无法写入 | failed | 沿 _write_export：占用/PermissionError E5004，其余 E5003，ENOSPC 交统一 E9002 |
| 转换成功但来源/归档登记失败 | failed | 同上；不得返回已留档成功；重试核对文件和登记，不能只命中文件缓存 |

新增 PDF 路径的这些情况应落既有导出审计失败事件；只记格式、版本、来源/产物指纹、状态和必要原因，不记录正文或无过滤的 soffice 输出。业务错误语义复用 01 §9.3，不新增编号；内部 skipped 是缺环境诊断，**不是 HTTP 成功，也不是验收 PASS**。现有 `.doc` 的 skipped/failed 继续作为附加转换结果，不倒改其兼容合同。

Electron `renderExport` 增加 DOCX/PDF 选择；选 record 时只允许 DOCX，服务端仍独立拒绝绕过请求。用响应主 path 展示/下载/撤销 PDF；失败交现有 showError，禁止显示“已生成”或可点击旧链接，提示 PDF 真实状态和字体警告。保留按会议密级管理的提示；不宣称 PDF/A 或“已通过留档合规”。

### 2.4 留档、来源登记与撤销

正式 PDF 固定 `export/{meeting_id}-纪要-v{version}.pdf`，与同 stem DOCX 一一配对；不引入标题路径拼接。调用 FileStore.write(stage="export")，纳入既有 manifest 的路径/大小/明文哈希，保持 export 是唯一明文区的既有边界。仅最终交付物和内部短时转换文件可在此出现。

用已有 FileStore JSON 存储能力，在加密 archive 区新增内部 `archive/pdf-exports.json` 工具性登记文件（不是 SQL schema）：`format_version=1, meeting_id, entries`；entries 以 PDF 相对路径为键，值固定 `version,pair_fingerprint,source_docx_path,source_docx_sha256,pdf_sha256,size_bytes`。不存正文。登记文件本身也经 FileStore 管理，不手改底层 manifest 格式；它只证明派生绑定，不能替代 G3 final。

- 未归档：只登记成功 PDF 及来源，不改变 stage/审批。既有 make_archive 在复检 final 后合并有效 PDF 到 archive/manifest.json 的 export_paths 内 `pdf` 映射（路径→上述来源值），保留 docx/doc 和既有字段。
- 已归档：HTTP 导出页通常在归档后使用，因此成功 PDF 在同一会议锁内直接补登记到现有 archive/manifest.json；保持 archived_at 和阶段，记录补登记审计。未找到归档清单不能伪造历史“已归档成功”，返回 E5003 并列恢复原因。旧归档无配对历史沿 MinutesService.deliver 原拒绝，不重建 final。
- 归档集合指纹包含排序后的实际产物路径/哈希及 PDF 来源；扩 archive 幂等输入和缓存有效性检查，新增/移除 PDF 后不能复用旧集合快照。仍用已有 IdempotencyStore，不加状态键；归档复检先于缓存。
- 撤销沿原 POST /export/undo，删除选中 PDF 与 manifest 条目，并移除来源登记及归档 export_paths 的对应项；不撤销同源 DOCX/final，不暗中级联。失败可重试且不显示完整撤销。直接删除/损坏造成的旧登记在重试/归档时核对并修复，不伪称有效。

跨文件/DB/checkpoint 的完整事务仍是 T2-04 已知边界。允许失败后存在已写文件，但不能登记成功或返回成功链接；重试按实际哈希/来源核对并完成缺失登记。PDF 不会因进入 archive 清单自动加密或改变密级；04 的保留、流转与销毁要求继续由单位执行。

### 2.5 幂等与复用

派生缓存键固定包含 `meeting_id,artifact=minutes,version,pair_fingerprint,source_docx_sha256,format=pdf` 的规范化输入哈希，沿既有副作用键机制；docx/doc/pdf 不共用结果引用。现有 graph 默认仍只产 DOCX/配置要求的 DOC，不自动转换 PDF，不增加格式状态键。

命中须同时满足当前硬检/G3、所选 final、来源登记、源 DOCX 实际哈希、PDF 实际存在/非空/格式头/哈希、FileStore manifest，以及已归档时清单登记一致。两次相同请求返回同一路径/哈希，第二次 reused=true、转换器调用零次，无 `-1/-2` 副本或重复登记。来源改变/缺文件/损坏不得返回旧缓存；重转成功才更新绑定，失败不发旧链接。PDF 元数据可能含时间，**不要求跨机或强制重转后字节相同**；SOFFICE/字体升级后需要显式失效已有派生登记再转换，本卡不自动探测运行环境版本变化。

## 4. 验收标准（逐项编号）

1. **同源转换与范围**：审定纪要 DOCX 字节作为唯一输入；stub 捕获参数和来源哈希，最终 PDF 名称/头/登记正确；record、草稿、无 G3、非法 format/组合明确拒绝，转换调用为零。普通 PDF 声明明确，无新依赖/端点/SQL schema/配置开关。
2. **全出口硬阻断**：HTTP、直接交付服务、当前坏稿+历史 final、预置缓存、PDF 下载、归档补登记均执行 T2-04 硬检；E3002/E4001/E1002 按情形可复核。失败不回退记录稿，不输出新可交付 PDF，不更新成功来源/归档项。
3. **失败语义**：缺 soffice、超时/非零/空/缺/坏输出、遗留输出、占用/满盘/登记失败分别验证；显式 PDF 不以 skipped/failed 返回成功，E5003/E5004/E9002 正确；旧可选 DOC 软失败和 DOCX 仍兼容，失败审计无正文，隔离目录清理。
4. **幂等与恢复**：同一 final 同一来源两次请求路径/哈希稳定、只调用转换一次，第二次 reused=true；换版本/来源、坏文件/登记/manifest 不复用；docx/doc/pdf 隔离；并发单会串行，登记失败重试可完成；无副本/伪成功，不以 PDF 重转字节确定性作为验收条件。
5. **留档与撤销**：归档前 PDF 纳入后续 archive；归档后请求同步补清单，不重跑图/审批/通知，不改 archived_at；来源、实际哈希、manifest 和集合键一致；撤销只移除选中 PDF 及关联登记，重复/中途失败恢复有证据，不能把旧 archive 缓存当新集合。
6. **API 与桌面联证**：老请求兼容；PDF 主 path/sha/size/reused 指 PDF，下载 application/pdf/中文文件名、安全路径与当前硬检生效；Electron 请求正确、record 禁 PDF、失败无成功提示/旧下载链接，撤销选中 PDF。代码合同自动验，实际桌面操作仍列目标机待验。
7. **真实转换（目标机项）**：在装有 soffice 和公文字体的目标机运行固定 test_pdf_soffice.py，记录命令、版本、字体、输入 DOCX/PDF 哈希、计数；人工打开 PDF 核对同源正文、标题/字体/缩进、表格边框与零缩进、跨页/页码/无缺字，按 03 §5.2 留记录并签字。用合成样例验证即可，不将 M6 DOC 历史证据冒充 PDF。本机无程序记 SKIPPED/PENDING，**该项不能 PASS**。
8. **可信验收脚本**：逐项打印精确 argv、完整 stdout 与 executed/passed/failed/error/skipped；任何自动项失败、错误、零执行或 skip 均不可 PASS。反例实际破坏硬检/缓存及计数须导致失败。--only 不宣称全八项；不调用 pytest 根目录/全套。标准 7 独立门控，skip 不增加通过数，自动标准 1～6/8 全过时只可写 TOOLING_PASS（7/7），同时写“真实转换/人工版式 PENDING，目标机通过 0”，退出 0 仅代表工具逻辑；不能显示 8/8/RELEASE_PASS。真转换已运行失败则脚本非零，真转换通过但人工未签仍不能称整卡完成。

脚本的自动标准不得包含门控测试而暗吞 skip；单独运行标准 7 为 skip 时输出 PENDING 并非零退出。完整运行可按上面的工具退出约定保留 0，但总表必须显示 7 PASS + 1 PENDING，而非 8 PASS。人工签字不能由 pytest 或脚本自动生成。

## 7. 常见坑

1. 把 exporter 占位目录当已实现 converter：实际 soffice 在 app/services/export.py，先复用再做小幅提取。
2. PDF 从 Markdown 另起渲染或从 record DOCX 偷换输入：破坏同源版式和 T2-04 配对；只用本次校验后的纪要 DOCX。
3. 缓存先返回再硬检，或只扩 require_final 的后缀：当前坏稿、伪名 PDF、历史 final 都要联证；文件存在不是授权。
4. 把 DOC 的可选 skipped 复制成显式 PDF 的“成功”：PDF 未生成必须 E5003，无成功下载链接；旧 DOC 行为另保留。
5. soffice 返回 0 就认成功，或捡到上次旧文件：隔离输出并检查本次文件、非空、PDF 头；基础格式检查仍不证明视觉正确。
6. 只登记 FileStore 就说已归档，或复用旧 archive 集合键：归档前后分别处理，新增 PDF 要补实际清单和集合指纹。
7. 用 DOCX 的 reused/sha 填 PDF 结果，或每次强转比较 PDF 字节：主结果字段必须指 PDF，来源与产物双哈希，合法缓存不再调用转换。
8. 从 archive 文件里直接写明文 JSON或留系统临时文件：走 FileStore 加密区接口，临时转换只在受管 export 区并清理，审计不写正文。
9. 跑到 pytest.skip 就把标准 7 勾通过，或者借 M6 历史证据补数：本机目标机分账，skip 永不 PASS，人工未签仍 PENDING。
