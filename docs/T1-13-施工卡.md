## 1. 目标与范围

**一句话**：给一个端点，让保密检查人员点一下就能看到
"**本程序没有对外发过任何连接**"，而且这个结论是**主动探测**出来的、
**经得起反向验证**的。

### 1.1 必须覆盖的四项检查（施工卡原文）

| # | 检查 | 数据来源 | 判定依据 |
|---|---|---|---|
| ① | **网络行为** | `psutil.Process().net_connections()` | 本进程是否有非回环出站连接 |
| ② | **ASR 质量** | `transcript_segment.confidence` 最近样本 | 平均置信度 / 低置信占比 |
| ③ | **字体可用性** | 注册表（复用 T1-09 `font_check`） | 必需字体是否齐、回退链是否耗尽 |
| ④ | **审计链完整性** | `audit_log` 逐行重算哈希 | 链是否完好 |

```json
{
  "ok": true, "code": "OK", "message": "自检完成",
  "data": {
```

## 2. 关键设计决策

### 2.1 ★★ 判定只认**本进程**（本轮最要紧的一条）

**第一版踩的坑**：把"全机器所有进程的连接"也算进 `outbound_connections`。
实测本机（开着浏览器/更新器）有 **52 条**到 443 的连接 →
`outbound_connections = 52`、`verdict = fail`，而验收要求 `== 0`。

**为什么这比"数字大"更严重** —— 它**语义就错了**：

> 本项目的合规主张是"**我这个程序**不发外部请求"。
> 别进程（浏览器、系统更新）连不连外网，与本程序**毫无关系**。

把它们算进来，等于"装了浏览器"就会让合规自检变红 ——
这种自检在真实机器上**永远过不了**，检查人员一眼就会判定它是摆设。

**修正后的字段分工**：

| 字段 | 是否参与判定 | 说明 |
|---|---|---|
| `outbound_connections` | ✅ **判定字段** | 只统计本进程；这是"我没外发"的直接证据 |
| `listening_ports` | ✅ 判定字段 | 只来自本进程（端口是**我们服务**监听的） |
| `outbound_detail` | ✅ 同上 | 本进程外发明细 |
| `machine_outbound_processes` | ❌ **仅信息** | 全机器上**别的进程**的对外连接，作现场信息 |
| `scope` | —— | 自报 `own_process`，是"证明的是我自己"的凭据 |

### 2.2 `dns_queries_attempted` **如实报不支持**

施工卡"常见坑"第 3 条原文：

> 一期可简化为"报告不支持此项并说明原因"，但要在文档中明确标注为
> 已知限制，**不能假装有**。

本项返回 `None`（= 不支持），**不是 0**。

**为什么"试一把 patch 就报个数"更糟**：
打桩 `socket.getaddrinfo` 必须在进程启动**极早期**装上；端点被调用时
早期解析早过去了，数出来必然是 0 ——
**一个恒为 0 的数字比 None 更危险**：它看起来像"已验证没有 DNS 查询"，
实际只是"没数到"。

→ 见 `system._count_dns_attempts()` 的完整说明。

### 2.3 三档结论，`unsupported` 与 `fail` 必须分开

| verdict | 含义 |
|---|---|
| `pass` | 探测通过 |
| `fail` | 探测通过且**判定不合格**（如真有外发） |
| `unsupported` | **探测本身跑不了**（缺依赖 / 没权限 / 数据不足） |

把"测不了"混进 `fail` → 每台没装 psutil 的机器都报红；
混进 `pass` → 自检失去意义（测不了 = 通过了？）。
`overall` 因此还有第三档 **`degraded`**（有 unsupported 但无 fail）。

### 2.4 容错：任何单项探测失败都不能让自检崩

自检的价值在"报出哪里坏了"。探测自己把自检搞崩，检查人员看到的就是
"自检程序报错"而不是"哪一项不合格"。所以每节自己兜异常并把失败
**翻译成结论**，与 `adapters/asr/__init__.health_of_all` 同一取舍。

### 2.5 自检自身要留痕（AUD-08）

部署手册 §6.2 把 `selfcheck` 列为 8 类最小核查项之一 ——
"谁来查过、什么时候查的"本身也是要留痕的。端点写一条审计记录；
**写失败不阻断自检**（否则等于把工具自己废了）。

### 2.6 一个刻意保留的取舍：审计链只校验**全量**

`probe_audit_chain` 复用 `verify_chain()`（**只读**打开）。
常量 `AUDIT_TAIL_ROWS` 目前**未被使用** —— 它是为"库很大时只查尾部"
预留的，但一期库规模（万行级）全量重算仍是毫秒量级，
先简单直接；等真有性能问题再启用。
完整校验始终走 `tools/verify_audit_chain.py`（离线巡检，不怕慢）。

## 3. 验收标准（施工卡原文）

- [ ] 物理断网后全流程可用（V9）
- [ ] `/system/selfcheck` 返回 `outbound_connections: 0`
- [ ] 故意在代码里加一句 `httpx.get("https://example.com")`
      → 自检能检出（**验证检查本身有效**，不是摆设）
- [ ] `listening_ports` 只有一条，且 IP 为 `127.0.0.1`
- [ ] 启动时若检测到 `HTTP_PROXY` 环境变量指向外网 → 告警

### 验收脚本如何落地（`tools/accept_t1_13.py`）

| 标准 | 落地方式 | 可自动？ |
|---|---|---|
| 1 物理断网 | **无法自动验** → 列「需人工复核」 | ❌ |
| 2 `== 0` | 独立会话调端点断言 | ✅ |
| 3 检出真外发 | **三重重反验证**（见下） | ✅ |
| 4 单条回环 | 进程内（TestClient 不 bind）→ 人工；真后端侧已实测 | ⚠️ |
| 5 代理告警 | `check_environment` 三种情形 + 脱敏 | ✅ |

**第 3 条为什么做成三重** —— 这张卡最容易"假绿"：
一个 `return {"outbound_connections": 0}` 同样能过前两条。所以：

- **③-a 单元层**：假进程注入一条真外发连接 → `probe_network` 必须 `fail`
- **③-b 集成层**：服务进程内造一条**真 socket 连接** → 自检必须数到
  （★ 硬证据：证明 `0` 是**探测得出的**而非**写死的**）
- **③-c 端到端**：真发一次请求（保持连接）→ 自检必须检出

## 4. 常见坑（施工卡原文 + 本轮实测新增）

| # | 坑 | 处置 |
|---|---|---|
| 1 | Windows 上 `psutil.net_connections()`（全系统）可能要管理员权限 | 判定**只用本进程**（不需权限）；系统级仅作信息，无权限时降级标注 |
| 2 | 自检必须是**主动探测**，不能"读配置说没联网" | 四项全部真去问 OS / 真算哈希 / 真读注册表 |
| 3 | `_count_dns_attempts` 无跨平台标准实现 | **如实报不支持（None）**，文档标注为已知限制，不假装有 |
| **4** | **NEW**：全系统连接会把别进程的算成自己的（实测 52 条） | 判定只认本进程，全机器概况另放字段不参与判定（§2.1） |
| **5** | **NEW**：`httpx.get()` **完成**后连接已被池回收，探测不到 | 判据改成"连接**存活期间**探测"；`connect_ex` 后立即查询即可见。**采样式探测抓的是"正在发生的"外发** —— 要抓"历史上发过"得靠抓包/长期日志（SEC-03 的活） |
| **6** | **NEW**：`is_loopback()` 若把通配地址当回环，最严重情况反而静默 | 通配地址（IPv4 四个零 / IPv6 `::`）明确算**非回环** |
| **7** | **NEW**：注释里写 `0.0.0.0` 会被 `check_layers.py` 的 API 层文本黑名单误判 | 该文件里用文字描述代替字面量（guard 是纯文本扫，故意的） |

## 6. 依赖

新引 **1 个**运行期依赖：`psutil>=6.0,<8`（`pyproject.toml` 的 `system` extra）。

**与"离线运行"红线不冲突**：psutil 是**纯本地**系统信息库，
只读内核/OS 暴露的进程与网络元数据，自身不发网络请求、不带遥测。
放它进来恰恰是为了**证明**本进程无外发 ——
它是"检查工具"，不是"被检查对象"。

分层：psutil 只允许出现在 `api/system.py`；领域层已加入
`check_layers.py` 的 `FORBIDDEN_IN_DOMAIN`。
验证：`python tools/check_layers.py && python tools/check_deps.py`

安装：`pip install -e ".[system]"`
未安装时：网络自检**降级**为 `unsupported` + 说明，其余三项不受影响。
