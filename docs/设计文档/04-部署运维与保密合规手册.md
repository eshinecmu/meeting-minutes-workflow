## 0. 使用前必须读的三段话

**第一段——关于"不联网"。**
本系统设计为全程离线。但"不联网"只是合规的必要条件，**不是充分条件**。若处理的信息构成国家秘密，系统还须实行涉密信息系统分级保护、按最高密级定级、经检查合格后使用，设备须为合规涉密设备。**"一台不联网的普通电脑跑本地模型"处理涉密内容仍然违法。**

**第二段——关于测试数据。**
本手册中所有示例路径、示例音频均为**公开素材或自录素材**。**严禁**为了调试方便把真实会议数据复制到开发机、测试机或个人设备。真实数据测试必须在受控环境内进行。

**第三段——关于商业字体。**
公文体要求的方正小标宋简体、仿宋_GB2312、方正楷体_GBK 均为**商业字体，受版权保护**，本项目不得随包分发，模板只引用字体名。目标机缺失时系统会回退并在导出前提示。党政机关办公机通常已装齐，这也是本方案在体制内环境的天然优势。

## 1. 部署形态与前置确认

### 1.1 两种部署形态

| 形态 | 适用 | 网络 | 前置条件 |
|:---|:---|:---|:---|
| **A. 单机离线**（一期） | 个人文秘岗、单人使用 | 物理断网或策略组封锁 | 无特殊前置 |
| **B. 内网单机**（二期可选） | 一个科室 3—5 人 | 内网可达、外网不可达 | 需完成账号体系与传输加密 |

> **涉密场景只能选 A**，且须按涉密信息系统要求定级。

### 1.2 部署前置确认清单（必须逐条确认，不可跳过）

| # | 确认项 | 确认方式 | 责任人 |
|:---|:---|:---|:---|
| 1 | 本机将处理的会议内容**最高密级** | 由使用单位按定密程序确定 | 单位定密责任人 |
| 2 | 本机是否为**合规信息设备** | 涉密须为涉密信息设备，非涉密须满足等保要求 | 单位信息化部门 |
| 3 | 是否已**切断外网** | 物理断网或策略组明确封禁；部署后须抓包复核 | 运维 |
| 4 | 实施方是否具备**相应保密资质**（涉密场景） | 查验资质证书 | 单位保密机构 |
| 5 | 是否已与保密机构**对齐审计核查项** | 见 §6.2 最小核查项集 | 单位保密机构 |
| 6 | 是否已明确**使用人台账** | 谁用、何时用、用于什么 | 单位保密机构 |
| 7 | 目标机**是否已装公文商业字体** | 见 §2.2 字体清单 | 运维 |
| 8 | 目标机**硬件是否满足** | 见 §2.1 硬件要求 | 运维 |

> **第 1 项是定密责任，系统不做也不代替。** 系统的所有合规提示都只是提示。

### 1.3 硬件要求

| 项 | 最低配置 | 推荐配置 | 说明 |
|:---|:---|:---|:---|
| CPU | 4 核 | 8 核 | 转写是 CPU 密集型 |
| 内存 | 16 GB | 32 GB | 跑 14B 量化模型建议 32GB |
| 磁盘 | 50 GB 可用 | 100 GB SSD | 模型权重 + 音频归档 |
| 显卡 | 无（可用 CPU） | ≥ 6GB 显存 | 无独显转写 2 小时音频约需 2 小时；有独显约 30 分钟 |
| 操作系统 | Windows 10 1809+ | Windows 10/11 或信创 OS | |

**档位与质量取舍（必须向使用者明示，R5）**

| 档位 | 模型 | 硬件需求 | 生成质量 | 适用 |
|:---|:---|:---|:---|:---|
| 轻 | Qwen2.5 7B Q5 | 8GB 内存 | 可用，语体一般 | 低配机 |
| 中 | Qwen2.5 14B Q5 | 16GB 内存 | 良好 | 主流配置 |
| 高 | Qwen2.5 32B Q4 | 24GB 内存 / 有独显 | 最佳 | 高配机 |

> **一句话原则**：硬件不够就选低档位，**不要**为了"效果好"在低配机上强行跑大模型——跑不动比跑得一般更糟。

### 2.2 字体清单（目标机需预先安装）

| 字体名 | 用途 | 是否为商业字体 | 缺失后果 |
|:---|:---|:---|:---|
| 方正小标宋简体 | 公文标题 | 是 | 标题回退为宋体，版式不合规 |
| 仿宋_GB2312 | 正文 | 是（部分随 Office 分发） | 正文字形不符规范 |

| 宋体 | 页码 | 否 | 一般不缺 |

**预检命令**（部署后立即执行）

```bash
# Windows PowerShell：列出已装字体
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts' |
  Select-Object -Property PSChildName
```

若缺失，两条路：① 由单位采购并安装正版字体（合规路径）；② 通过系统接口把字体打包成离线安装包在目标机安装。**不得**把字体文件直接随本系统分发。

### 2.3 构建离线 wheel 仓库（在有网机器上做，一次即可）

```bash
# 在有网机器上
mkdir wheels && cd mmwf
pip download -d ../wheels \
    --only-binary=:all: \
    --platform win_amd64 --python-version 311 --implementation cp \
    -r requirements.lock

# 校验完整性
pip install --no-index --find-links=../wheels --require-hashes -r requirements.lock --dry-run

# 打包（连同哈希清单）
cd .. && sha256sum wheels/* > wheels.SHA256SUMS
```

### 2.4 模型离线准备（在有网机器上做）

```bash
# ASR 模型（FunASR）
# 从 ModelScope 下载 paraformer-zh / fsmn-vad / ct-punc 到 models/funasr/
# 然后打包
tar -czf models-funasr-v1.0.tar.gz models/funasr/
sha256sum models-funasr-v1.0.tar.gz

# LLM 模型（Ollama）
ollama pull qwen2.5:14b-instruct-q5_K_M
# Ollama 模型存放在 %USERPROFILE%\.ollama\models
# 直接打包该目录
tar -czf models-ollama-qwen14b.tar.gz "%USERPROFILE%/.ollama/models"
sha256sum models-ollama-qwen14b.tar.gz
```

> **模型权重文件通常 > 5GB**，介质传输时务必分卷并校验哈希。**不要**在目标机上尝试在线拉取（离线环境必失败，且违反交付前提）。

## 3. 安装步骤

### 3.1 安装流程图

```
① 校验交付包完整性（SHA256）
        ↓
② 安装 Python 运行时（解压式，免安装）
        ↓
③ 从本地 wheel 仓库装依赖
        ↓
④ 导入 ASR 模型
        ↓
⑤ 安装并导入 Ollama + LLM 权重
        ↓
⑥ 部署应用代码 + 桌面壳
        ↓
⑦ 放置配置（模型路径、模板、术语库）
        ↓
⑧ 初始化数据库（建表 + 触发器）
        ↓
⑨ 字体预检
        ↓
⑩ 启动自检 + 断网验证
        ↓
⑪ 冒烟测试（跑一个 5 分钟音频）
        ↓
⑫ 封存与台账登记
```

### 3.2 逐步骤命令

**① 校验完整性**

```bash
# 逐个比对交付包 SHA256
sha256sum -c delivery.SHA256SUMS
# 必须全部 OK；任何一条 FAIL 即停止部署，重新获取介质
```

**② 安装 Python 运行时**

```bash
mkdir -p C:/mmwf/runtime
cd C:/mmwf/runtime
unzip python-3.11.9-embed-amd64.zip
# 启用 site-packages（embed 版默认禁用）
sed -i 's/#import site/import site/' python311._pth
```

**③ 装依赖（离线）**

```bash
C:/mmwf/runtime/python.exe -m pip install \
    --no-index --find-links=C:/mmwf/delivery/wheels \
    --require-hashes \
    -r C:/mmwf/app/requirements.lock
```

> `--require-hashes` 与 `--no-index` 是**强制项**：前者防篡改，后者防偷偷联网。

**④ 导入 ASR 模型**

```bash
mkdir -p C:/mmwf/models
tar -xzf models-funasr-v1.0.tar.gz -C C:/mmwf/models/
# 校验
sha256sum -c models-funasr.SHA256SUMS
```

**⑤ Ollama 与 LLM**

```bash
# 安装 Ollama（离线包）
# 解压 ollama-windows-amd64.zip 得到 ollama.exe，放到 C:/mmwf/ollama/
# 设置模型目录到受控位置
export OLLAMA_MODELS="C:/mmwf/models/ollama"
C:/mmwf/ollama/ollama.exe serve &
# 导入模型
tar -xzf models-ollama-qwen14b.tar.gz -C C:/mmwf/models/ollama/
C:/mmwf/ollama/ollama.exe list    # 应能看到 qwen2.5:14b-instruct-q5_K_M
```

**⑥ 部署应用**

```bash
mkdir -p C:/mmwf/app
unzip mmwf-app-v1.0.0.zip -d C:/mmwf/app
unzip mmwf-desktop-1.0.0-win-x64.zip -d C:/mmwf/desktop
```

**⑦ 放置配置**

```bash
cp -r C:/mmwf/app/config C:/mmwf/config
# 然后按目标机实际情况修改 config/models.yaml 中的模型路径
# 见 §4 配置项说明
```

**⑧ 初始化数据库**

```bash
cd C:/mmwf/app
C:/mmwf/runtime/python.exe -m mmwf.infra.migrations.runner --db C:/mmwf/data/mmwf.db
# 验证：13 张表齐全 + 触发器存在
C:/mmwf/runtime/python.exe -c "
import sqlite3
c = sqlite3.connect('C:/mmwf/data/mmwf.db')
tables = [r[0] for r in c.execute(\"SELECT name FROM sqlite_master WHERE type='table'\")]
triggers = [r[0] for r in c.execute(\"SELECT name FROM sqlite_master WHERE type='trigger'\")]
print('tables:', len(tables)); print('triggers:', triggers)
assert 'audit_log_no_update' in triggers and 'audit_log_no_delete' in triggers
print('OK')
"
```

**⑨ 字体预检**

```bash
C:/mmwf/runtime/python.exe -m mmwf.tools.font_check --config C:/mmwf/config
# 输出缺失清单；有缺失则按 §2.2 处理
```

**⑩ 启动自检 + 断网验证**

```bash
# 启动服务
C:/mmwf/runtime/python.exe -m mmwf.main --config C:/mmwf/config &
# 等端口文件生成后
TOKEN=$(cat "$LOCALAPPDATA/mmwf/session.token")
PORT=$(cat "$LOCALAPPDATA/mmwf/port")
curl -s -H "X-MMWF-Token: $TOKEN" "http://127.0.0.1:$PORT/api/v1/system/selfcheck" | python -m json.tool
# 必须看到 outbound_connections: 0
```

**⑪ 冒烟测试**

```bash
# 用公开素材或自录音频，绝不用真实会议数据
C:/mmwf/runtime/python.exe -m mmwf.tools.transcribe_cli \
    C:/mmwf/samples/sample_5min.wav \
    --glossary C:/mmwf/config/glossary.csv \
    --out C:/mmwf/data/smoke.json
# 检查 smoke.json 有内容、时间戳单调
```

**⑫ 封存与台账登记**

- 记录安装日期、版本号、各组件 SHA256
- 记录使用人、使用范围、密级
- 归档安装日志
- 按 §6.4 建立操作台账

## 4. 配置项说明

### 4.1 必须按目标机调整的配置

| 配置项 | 文件 | 默认值 | 调整说明 |
|:---|:---|:---|:---|
| `asr.model_dir` | `config/models.yaml` | `./models/funasr/paraformer-zh` | 改为实际部署路径（建议绝对路径） |
| `asr.device` | 同上 | `auto` | 无独显机建议显式设 `cpu` |
| `llm.model` | 同上 | `qwen2.5:14b-instruct-q5_K_M` | 按 §1.3 档位表选择 |
| `export.soffice_path` | 同上 | `C:/Program Files/LibreOffice/...` | 未装 LibreOffice 时设为空并关闭 .doc 导出 |
| `data_dir` / `log_dir` | `config/app.yaml` | `./data` | 建议改为绝对路径 |
| `thresholds.asr.low_confidence` | `config/thresholds.yaml` | `0.70` | 复核量过大时下调，复核量过小时上调 |
| `gate.approval_timeout_hours` | 同上 | `72` | 按单位审批节奏调整 |

### 4.2 不允许修改的配置（硬约束）

| 配置项 | 值 | 原因 |
|:---|:---|:---|
| `app.host` | `127.0.0.1` | 一旦改为 `0.0.0.0` 即违反离线要求，且暴露风险（SAD C11） |
| `app.port` | `0`（随机） | 固定端口会形成可被探测的固定特征 |
| `asr.disable_update` | `true` | 关闭后 FunASR 会尝试联网检查更新，破坏离线 |

> 若确需修改这三项，须走变更流程并**重新做保密技术检测**。

### 4.3 术语库维护

```csv
# config/glossary.csv
category,canonical,aliases,note
org,中共中央办公厅,中办,常用简称
person,张建国,张建军|张建国同志,注意易错写法
term,优化营商环境条例,营商条例,业务术语
codename,绿洲工程,绿州工程|绿洲项目,项目代号
```

**维护要点**
- `aliases` 用 `|` 分隔多个易错写法
- 条目总数建议 **< 2000**（超出会被截断并告警，见施工卡 T1-07）
- 含文件号、编号类的术语**不要**设别名，避免破坏文件号格式
- 每次修改**必须**登记到台账（系统会自动写审计日志）

### 4.4 模板维护

模板位于 `config/templates/*.yaml`，四类内置：`party-group`（党组会）、`special-topic`（专题会）、`coordination`（协调会）、`regular-meeting`（工作例会）。

**自定义模板的最小可改项**：`section_order`（章节顺序）、`readings_allowed`（允许的领读语）、`required_elements`（必填要素）。

**不要**在模板里写死本单位专有的机构名——那会让模板无法在同类单位间复用。

## 5. 日常运维

### 5.1 启停操作

**启动**（建议做成快捷方式，使用者双击即可）

```bash
C:/mmwf/desktop/mmwf.exe
# 桌面壳会自动拉起后端服务
```

**停止**

```
界面 → 退出
# 桌面壳会优雅关闭后端；若后端僵死，用任务管理器结束 python.exe
```

**查看服务状态**

```bash
netstat -ano | findstr LISTENING | findstr 127.0.0.1
```

### 5.2 数据备份

**备份范围**

| 内容 | 路径 | 频率建议 |
|:---|:---|:---|
| 业务数据库 | `data/mmwf.db`（含 `-wal`/`-shm`） | 每日 |
| 文件仓储 | `data/store/` | 每周（增量） |
| 配置与术语库 | `config/` | 每次修改后 |
| 审计日志 | `data/logs/audit/`（如独立存储） | 每日，**且需异地留存** |

**备份命令（必须在服务停止后执行，或使用 SQLite 在线备份）**

```bash
# 在线备份（服务运行中也可，推荐）
C:/mmwf/runtime/python.exe -c "
import sqlite3
src = sqlite3.connect('C:/mmwf/data/mmwf.db')
dst = sqlite3.connect('D:/backup/mmwf_20260927.db')
src.backup(dst)
dst.close(); src.close()
print('backup done')
"
```

> **不要**直接复制 `mmwf.db` 文件——WAL 模式下未 checkpoint 的数据不在主文件里，直接拷贝会丢数据。

**审计日志备份的特殊要求**：审计日志需按单位档案管理要求留存，且**备份介质本身也须符合密级要求**。备份完成后**必须校验链式哈希**：

```bash
python tools/verify_audit_chain.py --db D:/backup/mmwf_20260927.db
```

### 5.3 日志管理

| 日志 | 路径 | 保留 | 说明 |
|:---|:---|:---|:---|
| 应用日志 | `data/logs/app.log` | 30 天，按天轮转 | 排查问题用；**不含转写稿原文** |
| 审计日志 | 数据库 `audit_log` 表 | 1095 天（可配） | 保密检查用；只 INSERT |
| 安装日志 | `data/logs/install.log` | 永久 | 部署凭证 |

**日志中绝不出现的内容**（保密要求）：转写稿原文、纪要正文、人名清册。

### 5.4 磁盘空间管理

```bash
# 检查占用
du -sh C:/mmwf/data/*

# 归档策略建议：
# - data/store/{meeting_id}/audio/chunks/   处理完成后可删（原件保留）
# - data/store/{meeting_id}/export/         长期保留（交付物）
# - data/store/{meeting_id}/transcript/raw.json  可压缩归档
```

> **删除任何数据前必须确认密级与归档要求**。涉密数据的销毁须按涉密载体销毁规定执行，**不得**用普通删除。

### 5.5 性能调优

| 症状 | 可能原因 | 调整 |
|:---|:---|:---|
| 转写过慢 | 用了 CPU 且块太大 | 调小 `asr.chunk_seconds`；确认 `device` 设置 |
| 生成过慢 | 并行度不足 | 调大抽取并行度（注意显存） |
| 内存溢出 | 音频过大一次性读入 | 分段读取（需改代码，登记为改进项） |
| 复核段落过多 | 阈值过严 | 下调 `low_confidence` |
| 导出慢 | 表格过多 | 正常，GB 版式表格处理较慢 |

## 7. 故障排查手册

### 7.1 故障速查表

| 现象 | 可能原因 | 排查步骤 | 处置 |
|:---|:---|:---|:---|
| 程序启动后白屏 | 后端未起来 | 看 `data/logs/app.log`；`netstat` 看端口 | 见 7.2 |
| 提示"会话已失效" | 令牌文件不匹配 | 检查 `%LOCALAPPDATA%/mmwf/session.token` | 重启程序 |
| 音频投递后无反应 | 格式不支持 / 文件损坏 | 看返回错误码 | E1001 转格式；E1003 换文件 |
| 转写极慢 | 在用 CPU | 看日志中的 device | 无独显属正常；有独显则改配置 |
| 转写结果乱码 | 编码问题 | 检查 `PYTHONUTF8=1` | 补环境变量重启 |
| 转写结果时间戳错乱 | **上游静默失效** | 看自检报告 | 见 7.3 |
| 专有名词识别错误 | 热词未生效 | 看自检"热词零命中"告警 | 见 7.3 |
| 生成失败 E3002 | 模型输出不合模式 | 看重试次数与报错字段 | 见 7.4 |
| 导出后版式不对 | 字体缺失 | `font_check` | 见 7.5 |
| 表格缩进不对 | 补丁未生效 | 解压 docx 看 `w:ind` | 见 7.5 |
| 导出文件被占用 E5004 | Word 打开了同名文件 | — | 关闭文件后重试 |
| .doc 导出失败 | 未装 LibreOffice | 检查 `soffice_path` | 安装或关闭该功能 |
| 磁盘不足 E9002 | 空间不够 | `du -sh data/*` | 按 §5.4 归档 |
| 数据库被锁 | 多进程访问 | 检查是否有残留进程 | 结束残留进程 |
| 第二实例被拒 | 已有会话 | — | 正常行为（F8.3） |

### 7.2 后端启动失败排查

```bash
# ① 手动前台启动，看完整报错
cd C:/mmwf/app
C:/mmwf/runtime/python.exe -m mmwf.main --config C:/mmwf/config

# ② 常见原因
# - 依赖缺失        → 重跑 §3.2 步骤③
# - 模型路径错      → 检查 config/models.yaml 的 model_dir
# - 数据库锁        → 删除 data/mmwf.db-wal 与 -shm 后重试
# - 端口冲突        → 正常不会（用 0 随机），若报端口错误说明配置被改
# - 权限不足        → 以授权账号运行
```

### 7.3 上游静默失效处置（重点，R2）

**症状**：转写"成功"但质量实际下降——不报错，只是结果悄悄变差。

**三类症状与判定**

| 症状 | 判定方法 | 处置 |
|:---|:---|:---|
| 时间戳与文本长度错位 | 自检报告 `timestamp/text length mismatch` | ① 复核模型版本；② 抽样人工核对；③ 必要时降级到备用识别档位 |
| 热词零命中 | 术语库非空但转写结果中无一条术语 | ① 检查 FunASR 版本与热词参数名匹配；② 检查术语数是否超限被截断 |
| 置信度全空 | 自检报 `engine returned no confidence` | ① 复核引擎是否支持置信度输出；② 该情况下复核闸口退化，需提高人工抽检比例 |

**通用处置流程**

```
① 立即停止将该批结果用于正式交付
② 运行 /system/selfcheck，固定证据（截图 + JSON）
③ 按症状对照上表处置
④ 该批次转写稿做 10% 抽样人工核对
⑤ 修复后重跑受影响的任务
⑥ 记录到运维日志，上报技术负责人
```

> **不要**因为"看起来结果还行"就跳过处置。静默失效的危害正在于它不报警。

### 7.4 生成质量问题处置

| 问题 | 排查 | 处置 |
|:---|:---|:---|
| schema 反复不合规 | 看报错字段路径 | ① 改提示词；② 检查模板 schema 是否与模型能力匹配 |
| 议定事项漏抽 | 抽样比对原文 | ① 调小块大小（信息密度高时）；② 补充少样本示例 |
| 编造内容 | 校验清单命中 | **立即停止交付**；检查 grounding 是否被绕过 |
| 语体不符公文 | 人工阅读 | 补充 `readings_allowed`；增加示例库条数 |
| 责任人多为空 | 看问题清单 | 检查粒度规则是否生效 |

**处置原则**：**优先改提示词与示例，不要轻易上微调**（调研 §4.5：微调不注入新知识、事实会随权重固化而过时、有合规风险）。

### 7.5 版式问题处置

```bash
# 第一步：解压 docx 看 XML（所有版式问题的基本手段）
python -c "
import zipfile
zipfile.ZipFile('输出.docx').extractall('unzipped')
"
# 用文本编辑器打开 unzipped/word/document.xml

# 第二步：跑自动对照检查
python tools/verify_docx_style.py 输出.docx
```

| 症状 | XML 中的表现 | 处置 |
|:---|:---|:---|
| 中文显示为宋体 | `w:rFonts` 缺 `w:eastAsia` | 检查 `set_cjk_font` 是否被调用 |
| **表格缩进不对** | 表格内 `w:ind` 有非 0 值 | 检查 `fix_table_indent_penetration` 是否执行 |
| 行距不对 | `w:spacing@lineRule` 非 `exact` | 检查 `set_fixed_line_spacing` |
| 标题不居中 | `w:jc` 非 `center` | 检查标题样式映射 |
| 页码缺失 | 页脚无 `PAGE` 域 | 检查页脚渲染 |
| 字体回退 | 日志有 `font missing` | 安装字体（§2.2） |

### 7.6 数据恢复

| 场景 | 恢复方式 |
|:---|:---|
| 数据库损坏 | 从最近备份恢复；用 `PRAGMA integrity_check` 先确认损坏范围 |
| 审计日志损坏 | **立即上报**，不得自行修复；这涉及审计有效性 |
| 某个任务状态异常 | 用 `mmwf.tools.task_cli reset <meeting_id>` 重置到上游状态重跑 |
| 中间文稿误删 | 从 `manifest.json` 找到路径，尝试从导出文件反推（有限） |
| 导出文件丢失 | 重新导出（幂等键保证不产生重复） |

### 7.7 紧急情况处置

| 紧急情况 | 立即动作 | 后续 |
|:---|:---|:---|
| 发现数据外发 | 立即断网、停止服务、封存设备 | 按单位保密应急预案上报 |
| 发现审计日志被篡改 | 立即停止使用、封存 | 上报保密机构；不得自行修复 |
| 设备丢失/被盗 | 按涉密载体丢失流程上报 | — |
| 发现系统被非授权访问 | 停止服务、保留现场 | 上报信息化部门与保密机构 |

> **紧急处置的第一原则**：**保留现场，不要自行"修复"**。自行修复往往破坏证据，反而加重责任。

```

        ↓
```

| 场景 | 步骤 | 注意 |
