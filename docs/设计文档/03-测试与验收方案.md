## 0. 测试总原则

**四条不可动摇的原则：**

1. **红线项一票否决。** PRD §9.3 列出的 5 条红线，任一不通过，**整体不交付**，不允许"先上线后整改"。
2. **验证行为，不验证声明。** 不允许用"配置里写了离线"来证明离线；必须**主动探测**并给出可复核的证据。
3. **质量指标必须用真实数据。** 不得用构造样例替代真实会议录音与真实历史纪要做质量验收。
4. **上游不信任。** 所有第三方组件（ASR、LLM、转换器、字体）的行为都要有独立自检，不假设其"应该正常"。

## 3. 契约测试（适配器一致性）

**目的**：新增任何识别引擎、大模型后端、导出器，都必须自动满足同一套接口契约，**不靠人肉遵守**。

```python
# tests/contract/test_asr_contract.py
import pytest
from mmwf.adapters.asr import _REGISTRY

@pytest.fixture(params=list(_REGISTRY.keys()))
def provider(request):
    return _REGISTRY[request.param]()

def test_available_returns_bool(provider):
    assert isinstance(provider.available(), bool)

@pytest.mark.skipif(not _ALL_AVAILABLE, reason="引擎未安装")
def test_transcribe_returns_contract(provider, sample_audio):
    r = provider.transcribe(sample_audio, hotwords=["测试词"])
    assert isinstance(r, TranscriptResult)
    assert r.segments, "分段不得为空"
    assert all(s.start_ms <= s.end_ms for s in r.segments)
    assert [s.seq for s in r.segments] == sorted(s.seq for s in r.segments)

def test_timestamps_monotonic(provider, sample_audio):
    """时间戳必须单调不减 —— 上游时间戳错位是已知静默失效症状。"""
    r = provider.transcribe(sample_audio)
    starts = [s.start_ms for s in r.segments]
    assert starts == sorted(starts), "时间戳非单调，疑似上游时间戳错位"

def test_health_check_schema(provider):
    h = provider.health_check()
    assert {"available", "model", "device", "hotword_supported"} <= set(h)
```

**必须存在的三组契约测试**：`test_asr_contract.py`、`test_llm_contract.py`、`test_exporter_contract.py`。

**契约测试数量**：每接口 6 个用例 × 3 接口 = 18 个；按 provider 参数化后约 30—40 条。

## 5. 版式验收（docx 对照）

### 5.1 验收方法

**方法**：解压 docx → 解析 XML → 逐项比对；配合**人工目视**双确认。

自动校验只保证"属性值对"，不保证"看起来好看"。故每项均需**自动 + 人工**双通过。

### 5.3 版式自动校验脚本

```python
# tools/verify_docx_style.py  （扩展版）
import zipfile, sys
from lxml import etree

W = "http://schemas.openxmlformats.org/wordprocessingml/2006/main"
def q(tag): return f"{{{W}}}{tag}"

CHECKS = []

def check(name):
    def deco(fn):
        CHECKS.append((name, fn))
        return fn
    return deco


@check("P01 标题字体")
def p01(tree):
    errs = []
    for p in tree.iter(q("p")):
        text = "".join(t.text or "" for t in p.iter(q("t")))
        if not text or len(text) > 30:
            continue
        sz = _first_val(p, "sz")
        if sz and int(sz) >= 40:            # 大字号视为标题
            f = _first_val(p, "eastAsia", tag="rFonts")
            if f and f != "方正小标宋简体":
                errs.append(f"标题「{text[:15]}」字体为 {f}，应为 方正小标宋简体")
    return errs


@check("P10 表格零缩进")
def p10(tree):
    errs = []
    for tbl in tree.iter(q("tbl")):
        for ind in tbl.iter(q("ind")):
            for attr in ("firstLineChars", "firstLine", "leftChars", "left",
                         "hangingChars", "hanging"):
                v = ind.get(q(attr))
                if v and v != "0":
                    errs.append(f"表格内段落 {attr}={v}，应为 0（表格零缩进）")
    return errs


@check("P09 行距")
def p09(tree):
    errs = []
    for p in tree.iter(q("p")):
        text = "".join(t.text or "" for t in p.iter(q("t")))
        if len(text) < 40:                  # 只看正文段
            continue
        spacing = p.find(f".//{q('spacing')}")
        if spacing is None:
            errs.append(f"正文段「{text[:15]}」缺行距设置")
            continue
        if spacing.get(q("lineRule")) != "exact":
            errs.append(f"正文段行距规则非 exact（实际 {spacing.get(q('lineRule'))}）")
    return errs


def main(path: str) -> int:
    with zipfile.ZipFile(path) as z:
        tree = etree.fromstring(z.read("word/document.xml"))
    total = 0
    for name, fn in CHECKS:
        errs = fn(tree)
        if errs:
            print(f"✗ {name}")
            for e in errs[:10]:
                print(f"    {e}")
            total += len(errs)
        else:
            print(f"✓ {name}")
    print(f"\n{'✓ 全部通过' if total == 0 else f'✗ 共 {total} 处不符'}")
    return 0 if total == 0 else 1


if __name__ == "__main__":
    sys.exit(main(sys.argv[1]))
```

**用法**：`python tools/verify_docx_style.py <导出的docx>` —— 输出的每一项与 §5.2 表一一对应，把该表打印出来逐行打勾即可。

## 6. 影子模式验收（二期上线门槛）

### 6.1 验收流程

```
① 取 20 份真实历史会议（覆盖四类会议、含长会与短会）
        ↓
② 系统全流程跑一遍，生成纪要稿（不交付）
        ↓
③ 人工照常撰写纪要（不看系统稿，避免锚定）
        ↓
④ 第三方比对（不参与撰写的人）逐份打分
        ↓
⑤ 汇总五维指标，判定是否达标
```

### 6.2 五维指标与阈值

| 维度 | 定义 | 阈值 | 计算方式 |
|:---|:---|:---|:---|
| 要素齐备率 | 系统稿含全部必填要素 | ≥ 95% | 齐备份数 / 总份数 |
| 议题召回率 | 人工稿议题被系统提及的比例 | ≥ 90% | Σ(交集) / Σ(人工稿议题数) |
| 议定事项召回率 | 人工稿议定事项被系统抽取的比例 | ≥ 85% | Σ(交集) / Σ(人工稿议定数) |
| **无依据陈述率** | 系统稿中有原文无依据的陈述 | **= 0** | 命中条数 / 总条数 |
| 结构合规率 | 系统稿结构符合模板 | 100% | 合规份数 / 总份数 |

### 6.3 分歧分类（决定是否放开自主权）

| 分歧类型 | 说明 | 期望占比 |
|:---|:---|:---|
| 系统更保守 | 系统未写人工写了的（漏抽） | 允许存在 |
| 系统更激进 | 系统写了人工没写的（多抽/编造） | **必须为 0** |
| 系统错误 | 系统写的内容与事实不符 | **必须为 0** |

**放开判据**：五维全达标 **且** "更激进"与"错误"两类均为 0 **且** 分歧以"更保守"为主 → 可进入阶段 2（半自动）。
