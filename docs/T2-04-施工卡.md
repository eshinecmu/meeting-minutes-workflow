## 2. 契约（逐条可对照）

### 2.1 最小 PipelineState 与节点读写

新增键均为 `total=False` 的可选键、JSON 可序列化值，不存 Pydantic 实例。**不新增** template_id、schema_version、blocked、gate_history 等顶层键。模板 / 源版本等上下文放在 minutes 的内部命名空间 `_context`，不塞进 MinutesSchema 模型；送模型和 `validate_minutes` 时只取 schema 字段。

- `minutes`：丰富原料快照。含 MinutesSchema 的七顶层字段及 schema_version，保留 pending_decisions、source_quote 等；扩展元数据置 `_context`，包括模板 id/version/完整内容指纹及快照、源记录稿版本 / 指纹、稳定路径映射、粒度修正记录。**不是最终稿别名**。G2 后生成必须以最新三列表更新其对应字段，不能让旧嵌套事项覆盖人工编辑；pending_decisions 仅从丰富原料保留，按稳定 topic 路径关联，无法关联就报问题，不能丢弃。
- `minutes_structured`：既有键，权威工作稿，保留 canonical 字段、refs 扩展和 apply_template 生成的 sections；渲染前总是由 canonical 重建 sections，禁止双份正文各改各的。模型 schema 本身不增加 source_refs 字段；refs 存在图工作稿扩展中，避免 Pydantic extra=ignore 丢证据。
- `issues`：统一全阶段清单，含 extraction/template/grounding/granularity/consistency/edit 来源；覆盖写去重后的结果，**不加 append reducer**。`validation_issues` 保留为本次 validate 的兼容投影，不把历史问题当重试条件。

### 2.3 Grounding 算法与硬阻断位置

**绑定顺序固定**：完整原文精确匹配优先；复用 normalize_punct 后子串匹配次之；最后模糊滑窗。源优先使用与记录稿版本对应的权威分段（保留真实 start/end），只有 Markdown 时用 segmentize，时间有损必须 issue 标注。禁止用模型返回的 quote/text/timestamp 当“源”。

**模糊匹配的确定算法（U-GR-03）：** 在同一段归一化文本滑动所有起点，窗口长度为 `len(q)-2 ... len(q)+2` 的正整数，比较单位代价 Levenshtein 距离（插入 / 删除 / 替换，动态规划，超过 2 即剪枝）。q 长度至少 5；接受 `1 <= distance <= 2` 且 `distance/max(len(q),len(window)) <= 0.20`。因此 5 字可差 1 字、10 字可差 2 字；少于 5 字只允许精确 / 归一化，避免短人名误绑。排序键为距离、差异比例、段序号、起点、窗口长度；完全相同窗口可保留最早者并报多候选提示。无随机性、无网络、无新依赖。confidence=`min(0.90,1-distance/max_length)`，始终低于 normalized 0.95；exact=1.0；失败=0。保留提交 quote 和真实命中窗口，两者不可混写。

**多段引用（U-GR-05/06）：** 每个显式 source_refs / quote 元素独立验证；单个 quote 可在相邻最多 3 段的拼接窗口精确 / 归一化命中，返回涉及的全部段（不跨段 fuzzy，防无关拼接）。任一引用伪造 / 不匹配均产生 error，不采用“有一个好 ref 就掩盖坏 ref”。段时间直接回填，null 保留并告警，不猜末段 end。refs 并集键为 `(segment_id, quote, start_ms, end_ms)`，稳定保序；同段不同 quote 不能丢。无时间时仍能定位段落，UI 显示“暂无时间信息”，不能宣称已验证音频跳转。

**硬检查范围：** 全部议题 discussion / 被作为结论呈现的标题，以及 resolutions、action_items、pending_decisions，空 refs、ungrounded、伪造段 id、quote 不匹配、缺源都返回 `level=error, blocking=true`。纯导航标题可继承经验证的议题 discussion refs；不能拿无关模板标题要求逐字匹配。非空 refs 不等于已 grounding。fuzzy 命中必须在清单和来源展示中标“原文有字词差异，待核对”，不能把它当金额 / 人名正确的证明。

**精确的图阻断合同：** validate 先计算 / 返回全部 issues，将错误写入既有 errors，并在 hard error 时置 `stage="validation_blocked"`；`route_after_validate` 首先检查 hard error，返回新增路由值 `blocked`，该边指向 **END**，复用 status=failed、界面“处理失败”。该分支优先于 gen_retry，MAX_VALIDATE_RETRY 再大也不得进入 assemble/G3/export。runner 的 `_derive_status` / 持久状态同步识别 stage 标记，重建 runner 后仍为 failed；`_invoke` 在图完成并已持久化该诊断后检查标记、同步 task_state / meeting 状态，再抛 GroundingBlockedError 给调用 API（不是在条件边抛异常而丢掉本轮状态）；保留问题和原料可供下载。无需新增图节点或状态名。

E3002 阻断提示固定为：“纪要中有内容找不到原文依据，已停止成文。请核对问题清单并修正来源后重试。”API 沿统一错误信封；禁止沿用“已自动重试”文案。`GroundingBlockedError` 序列化必须返回 severity=error，SchemaViolationError 的既有 warning 回归照旧。流程的阻断判据是 blocking，不靠 ERROR 色彩决定是否继续。

**不可旁路：** assemble 入口防御复检；G3 approve/edit 在 GateService 登记决定之前预检候选稿，失败保持原 G3/checkpoint，既不登记成功决定也不推进；图 export 和纪要 ExportService 在缓存命中判断之前独立复检。直接 runner.resume / 重放已登记决策也在 export 停下，异常出口持久记 failed；不能复用“先前已通过”布尔标志。编辑不能设置 refs、blocking、issues、is_final；reject 只能返工，不能标成通过。无依据时无纪要 DOCX、无 final 行、无 archive；候选 Markdown 仅作为待修正草稿可读。普通模板 / 数字 / 人名问题不触发 blocked，也不触发无意义的 generate 重试；旧注入 validator 未带 blocking 的历史结果仍可沿原重试合同运行。

### 2.4 粒度规则（U-MN-01～06）

先补 owner，再拆分、降级、时限标注、同组去重；每次变更产 info/warning，输入深拷贝、重复运行结果幂等。运行于 G2 后 generate 的 canonical 适配阶段，validate 再检查不变量；自动修正不能伪造证据。

| 规则 | 精确触发 / 处理 | 理由 / 边界 |
|:---|:---|:---|
| owner | 每类事项缺键 / null / 去空白为空 → 显式 `owner="暂无"`，info OWNER_DEFAULTED，序列化永不省略 | C05；若 schema 默认已填，占位事实从原始输入记录，勿重复报 |
| 多事项 | 去首尾空白的 content 长度 **>60 Unicode 字符**，含“并 / 以及 / 同时”；按这些连接词从左至右最长词优先切，去连接词及两侧标点空白，至少两段非空才拆。每个子项继承 owner/deadline/全部 refs，保留 parent 路径与原文，子 id=`原id~序号` | 按 SAD 枚举规则，不猜语法；60 字边界不拆，不能用更短阈值“优化”验收；连词误拆风险进 §5 |
| 待办降级 | content 不含任一动词 `完成/提交/落实/推进/负责/牵头/配合/报送/审核/制定/整改/跟进/组织/开展`，**或** content+deadline 不含时间词 → 移入同议题 pending_decisions，decision_maker 默认“暂无”，warning ACTION_DOWNGRADED | SAD 的“或”优先于 U-MN-04 示例“均无”；无动词但有日期、只有动词无时限均测试，不删除原文 |
| 时间词 | 识别 `尽快/近期/及时/适时/择期/年内/月底/年底/本周/下周/本月/下月/今日/明日/今天/明天`，以及阿拉伯或中文数字的 `年/月/日/号/天/周`、ISO YYYY-MM-DD。单字“前 / 于”不算 | 固定规则避免“前景”等误判；相对日期不推算绝对时间 |
| 模糊时限 | deadline 去空白后包含 `尽快/近期/及时/适时/择期/抓紧/稍后` 任一词 → 原字段保持，warning DEADLINE_VAGUE，message “时限待明确” | “尽快”算时间词但不等于明确期限；待办不因模糊时限被改成日期 |
| 事项重复 | 同议题同类型、非空 content 复用 bigram Jaccard **>0.90**；owner/deadline 的非空非占位值无冲突，数字规范值及显式人名无冲突时合并。按原序与组首比较，不做传递链聚类；正文取最长、同长取最早；refs 全并，空字段取另一方非空，info DUPLICATE_MERGED | 不修改 T2-01 块间 merge 的 ≥阈值+重叠行为。最终去重不要求区间重叠；冲突则保留两条并 warning DUPLICATE_CONFLICT，防吞掉不同预算 / 责任人 |

### 2.5 数字、人名与统一问题清单

**数字只报问题，不改值：** 对 canonical 正文和 G3 候选的所有可见业务字段（不扫描编号、时间戳、refs 元数据、清单本身）提取金额 / 人数 / 日期。NFKC、去数值内部空格及千位逗号；用 Decimal 处理阿拉伯数、小数，中文支持 零〇一二两三四五六七八九十百千万亿、点、小数逐位；金额元/万元/亿元统一为元，数字后“万”无币种时可与同局部引用中的金额按元比较。人数 人/名/位 统一为人；日期 YYYY-MM-DD、YYYY年M月D日 统一年月日，无年份 M月D日 保留缺年，不能臆填会议年份。百分比独立单位，不能与金额混比。未支持表达（范围、约数、分数等）报 NUMERIC_UNPARSED，不静默视为匹配。

优先在条目已验证 refs 的真实原文比较同类别数值集合；无 refs 时退到全记录稿比较并报 NUMERIC_SCOPE_FALLBACK（grounding 独立硬挡）。纪要每个规范 token 必须能在范围中找到；同类有值但不等 → NUMERIC_MISMATCH，无同类 → NUMERIC_UNSUPPORTED。`300 万元=3000000 元` 对 `三十万=300000 元` 必须告警，`30万元` 对 `三十万元` 不告警。源同时出现两个金额时，不声称能分清对应业务，列为语义边界。

**人名只报问题，不纠错：** 候选仅来自 host/recorder/attendees、事项 owner/decision_maker、以及正文 `由/请/让 + 2～4汉字 + 同志/先生/女士/负责/牵头` 的有界模式；“暂无 / 待补充”排除；单位责任主体按 enabled org 术语 canonical/aliases 精确命中，或以 `处/科/局/办公室/部门/工作组/公司` 结尾排除，正文有界模式同样过滤。原文同样提取说话人和这些模式，加上明确列名；另读 enabled 的 person 术语 canonical/aliases 建精确别名表。候选规范名在局部真实 refs（元信息可查全文）中出现视为一致；别名匹配报 info PERSON_ALIAS；只在术语库存在但全文无依据报 PERSON_UNSUPPORTED，术语库不能证明参会。原文有名而术语库未登记不报错；两个 canonical 共用别名报 PERSON_AMBIGUOUS，不猜相近字。未知候选报 warning PERSON_UNSUPPORTED。DR-05 的“拦截”按较窄解释为命中清单并醒目提醒，不自动改名；是否 hard block 仍由独立 grounding 判断，不能把一致性检查升级为阻断。

**唯一 Issue 形状：**

```json
{"code":"NUMERIC_MISMATCH","level":"warning","blocking":false,"source":"consistency","target":"topics[0].resolutions[0].content","message":"金额可能与原文不一致，请核对","evidence":{"actual":"300 万元","expected":["三十万"],"segment_ids":["seg-2"]},"suggestion":"核对引用原文","rule":"numeric_mismatch","detail":"金额可能与原文不一致，请核对"}
```

code/level/blocking/source/target/message/evidence/suggestion 均存在；rule/detail 是现有 renderer 兼容投影，与 code/message 一致，不维护第二份清单。level 取 error/warning/info；**仅 grounding 无依据类 error 才 blocking=true**。模板 required_* 为 warning（UI 标红但可继续），forbidden_expression / reading_level_* 等为 warning，unknown/ambiguous 也为 warning；修正事实 info；抽取块失败 / chunk_meta_missing / no_timecode 等保留 warning 与 chunk/keys 证据。不要把模型异常堆栈、原始输出直接当用户 message。

聚合 `extraction issues + check_template（三类全调用）+ T2-04 checks`。规范化旧 rule/field/detail 到新 shape；去重键 `(source,code,target,canonical_json(evidence))`，不按 message 文案去重；同键合并取最高 level、blocking 取或、建议稳定并集。排序 error→warning→info，再 source、target、code、evidence JSON；索引基于修正后 canonical，修正记录保留原路径。不因多次 validate 重复加清单；warning 可以进入待审草稿 / 定稿，blocking 不可以。

文本格式固定 UTF-8、LF：会议标识、源版本 / 指纹、完整性标记、各级计数，逐行 `[级别] CODE 路径：说明；依据：…；建议：…`；无问题也输出“当前清单无问题”，unknown 另标“历史检查未完成”。GET issues 返回 `{meeting_id, issues, counts, complete, source_fingerprint}`；`GET issues?format=text` 返回 `text/plain; charset=utf-8`、attachment `issues-{meeting_id}.txt`。沿用令牌 / 会议存在性检查，不落明文临时文件，不写审计正文。失败时也可下载；文本导出与 JSON 一一对应。

### 2.6 生产模板与 G3 编辑

Runtime 每次开始 / 恢复会议需获取模板时，经应用服务复用 T2-02 的 `TemplateStore.select(template_id, meeting_kind)` 合同，template_id 取 meeting.template_id：显式 id 优先于 kind，不存在或已停用报 E1001（TemplateFormatError），不静默换模板；无显式 id 但显式提供 meeting_kind 时，须恰好匹配一份启用模板，零份 / 多份均报 E1001（TemplateFormatError）要求指定 id；两者均未指定时固定选 `tpl-regular-meeting-v1`，该模板不存在或已停用同样报 E1001（TemplateFormatError），不从会议标题猜类型。保存实际 id/version/内容快照与指纹。一次生成、校验、成文及 G3 编辑使用同一模板快照；恢复沿该快照，不受模板热改影响；旧 checkpoint 无快照才补取当前模板并 info LEGACY_TEMPLATE_ADOPTED。新一轮显式返工可采用当前版本并重新固定。会议元信息取丰富抽取非空字段优先、会议资料补空；冲突保留两值报 META_CONFLICT，不让标题“会议纪要”等兜底掩盖缺失。

naive 和 llm 都走适配→粒度→apply_template→check_template+validate_hard+一致性→render。naive 不要求本地模型就绪；llm 的 ExtractResult.to_graph_dict 必须显式透传 minutes/issues。保留既有 `Callable[[str],dict]` extractor、`Callable[[dict],dict]` generator、`Callable[[dict],list]` validator 和 assembler 签名；新增上下文可通过 Deps.extra 的可选工厂注入。直接 make_* 的既有 seam 单测继续使用原返回合同，生产 wrapper 才组装新上下文与完整检查；**wrapper 不得提供 disable_hard 开关**，所有纪要出口仍强制复检。新增状态键在生产 graph factory 声明，不能从依赖闭包偷偷持有每会议问题。

**G3 新合同：** 在原 decide/diff 请求 payload 增加可选 `minutes`（只准 canonical 的可编辑业务字段，稳定结构 / 条目身份不变；refs、quote、_context 为只读，继承基线）。服务从候选 canonical 重建 sections、minutes_markdown，检查和更新 issues；若同时给 minutes_markdown，必须与服务端渲染结果在 CRLF→LF 后一致，否则 E4001。纯旧 minutes_markdown 请求只允许与基线去空白后相同的排版修改；保留 canonical 并存配对 Markdown，业务变更明确 E4001 提示使用结构化编辑，不从任意文本反推结论。缺源候选 E3002，且保留草稿给用户修改。

G2 编辑仍只改三列表，不能上传新 refs；generate 用稳定身份回写丰富数据并重绑。G3 编辑不重跑 transcribe/extract/generate/assemble；服务内部调用纯 render/check 不计图节点重跑，rerun_nodes=[]，reject 仍仅 assemble。Electron G3 提供字段编辑 / 预览和只读来源，展示全部 issue level 与 fuzzy 标记；禁止靠隐藏按钮实现安全。审计 diff 扩展结构字段路径，仍仅指纹 / 引用、不写正文。存储的规范化决策必须含同步后的内部增量，使 T2-03 已登记未 resume 恢复走同样复检。既有 diff 无副作用，结构化草稿和最终提交使用同一候选构造器。

**测试兼容边界：** 原 callable seam、默认无模型、记录稿接口与三态分流计数不变。原 G3 测试若以任意 Markdown 业务改写作为成功向量，D5a 必须明确迁移为有依据的结构化 payload，并补旧 Markdown 排版成功 / 业务修改拒绝反例；这是 D07 的合同收紧，不能删测试、跳过或仅改预期使无依据文本“通过”。原精确键集断言仅在确实新增状态输出的生产测试按 D01 更新，保留直接 seam 返回键断言。

### 2.7 minutes_version 与实际交付

启用 `001_init.sql:minutes_version`，**无新 schema 迁移**。图 generate 不写半成品配对版本：assemble 完成才经应用版本服务保存 `structured_json + markdown` 草稿（is_final=0，created_by=system，note 带源 / 模板指纹、issues 快照及内容对指纹）；G3 edit 同步后保存新草稿，created_by 为实际操作者。版本号在单会议锁 + SQLite 事务内 max+1，唯一键兜底；相同配对指纹复用原行。G3 approve/edit 完成硬检，export 写入前把该配对版本标 is_final=1；不能把“通过 G2”当 final。非阻断 warning 清单随版本保留，不挪进正文冒充结论。

幂等键含 meeting_id、node_id、源 / 模板 / 结构 / Markdown 指纹，沿既有 IdempotencyStore；原稿内容未变的节点重放不重复版本。使用既有 infra.crypto 在基础设施层加密结构快照、正文及 note 中敏感清单，再以 JSON 信封 / 字符串存既有 TEXT 列，读取只能经版本服务解密；领域不 import crypto 或 DB。旧表为空正常，历史结构不从 Markdown 假造。无新历史查询路由，本卡消费方是校验 / 交付服务，后续若需服务器历史 UI 另开卡。

纪要导出显式接收这个最终配对快照，而非 record/vN.md；POST /export 可选 `artifact="record"|"minutes"`，省略时有纪要工作流产物 / checkpoint 就选 minutes，否则沿一期 record 行为。record 导出在文件名 / UI 标“记录稿”，不能设置 minutes_version final，不能让 failed 纪要通过默认导出回退 record。已有 version 参数在所选 artifact 内解释，缺版本报不存在，不能跨类型兜底。GET /minutes 继续读当前草稿、返回既有键并可追加 issues/complete；既有 /diff 继续比记录稿，不假冒纪要历史。

图 export 与 HTTP 导出都必须使用同一纪要校验服务：先校验，再命中缓存，最后写文件 / archive。即使旧缓存存在，当前无依据稿不得返回纪要下载链接；旧已归档文件不追溯删除。下载端点针对本次被阻断的非 final 纪要也不得泄露可交付文件。沿 C07/C12 留既有审计，文件 / DB / checkpoint 的跨资源完整事务仍不承诺；崩溃恢复重算配对指纹，不把无 final 的草稿当归档成功。

## 5. 已知缺口（本卡不承诺越界解决）

- 当前以上均待实施；旧图可带无依据内容成文、实际导出仍用记录稿，不能因合同完成而视为修复。

- T2-01 真模型 / 目标机性能、T2-02 复杂语体准确率、T2-03 Electron 人工视觉项继续开放；本卡只接收明确延期到 T2-04 / D 的实现缺口。

## 7. 常见坑

1. refs 非空就放行，或用模型 quote 当原文：必须对权威源重绑；任何坏引用不能被一个好引用遮住。
2. hard error 仍走 retry/give_up：blocked 判定必须在最前，assemble、G3、export/cache 都要有防线。
3. E3002 默认仍是“已自动重试”且 WARNING：阻断类型单独覆盖文案与 severity，并保住原 SchemaViolation 行为。
4. TypedDict 没声明 minutes/issues，或 NODE_OUTPUTS 漏产物：LangGraph 会丢值，返工也会留下旧稿；真实 checkpoint 联证。
5. 旧 G3 一升级就删库 / 重抽取，或预检 update_state 导致 checkpoint_id 失配：副本适配，经原 resume 增量合并。
6. 只给 llm 接模板，naive 没有 required checks；或每节点热读模板导致一稿多版本：Runtime 双路径、复用 T2-02 `TemplateStore.select(template_id, meeting_kind)`（默认 `tpl-regular-meeting-v1`，缺失 / 停用或 kind 无唯一启用匹配报 E1001 TemplateFormatError，显式 id 优先）、固定内容快照。
7. 金额只搜阿拉伯数字，或看到术语库有名就证明参会：统一数值单位、范围匹配，术语不是来源证据；一致性只报问题。
8. 最终消重误复用块间 ≥0.9+重叠规则；拆分忘 refs 或把 pending_decisions 丢出三列表：按 §2.4 的边界与丰富状态双表示测试。
9. 清单无限追加、修好仍报旧错、按 message 文案去重，或把敏感正文 / 堆栈写审计：每阶段替换、结构键去重、用户消息独立。
10. G3 只改 Markdown、版本表存旧结构；或图幂等键用纪要但 DOCX 实际读 record：配对快照校验后显式传给导出服务。
11. 有旧缓存就免校验、failed 默认回退记录稿假装纪要、先标 final 再检查：所有纪要出口先硬检，且不得默认降级类型。
12. 把定向基线、静态 UI 检查或验收脚本存在当作 V3/V4/R-5 完成：自动、人工、影子证据分别记录；本轮只完成文档。
