## 2. 契约（逐条可对照）

以下确定性细则为**本卡补充裁决**，不是声称上游已经写出了算法。遵守 SAD §14 C01/C03/C05/C06/C10：领域不读盘、不碰 DB/网络、不改原文溯源、不让模型决定中断。

### 2.1 输入、输出与现有 validate seam

```python
# domain/minutes/template_checks.py；只依赖领域对象和标准库
def check_required_elements(minutes: Mapping, template: MinutesTemplate) -> list[dict]: ...
def check_forbidden_expressions(minutes: Mapping, template: MinutesTemplate) -> list[dict]: ...
def check_reading_levels(minutes: Mapping, template: MinutesTemplate) -> list[dict]: ...
def check_template(minutes: Mapping, template: MinutesTemplate) -> list[dict]: ...

# domain/minutes/template_application.py
def apply_template(minutes: Mapping, template: MinutesTemplate) -> dict: ...
def from_graph_payload(payload: Mapping, *, meeting_meta: Mapping) -> dict: ...
def render_template_markdown(structured: Mapping, issues: Sequence[dict]) -> str: ...
```

- `minutes` 的语义形状为 SAD §10.2 `MinutesSchema.model_dump()`；也接受缺键 / 空值的 mapping 以诊断 U-MN-07，**不能先强制 model_validate 而把缺键变成异常**。正常抽取仍遵守 T2-01 的模式校验链。
- issue 最小字段固定为 `{"rule": str, "field": str, "detail": str}`；可加 `expected/actual/matched`，不加阻断级别或路由字段。路径用 `topics[0].discussion` 这种稳定索引；中文 detail 供既有组装器显示。
- rule 固定：`missing_required_element`、`required_min_count`、`required_pattern`、`required_type`、`forbidden_expression`、`reading_not_allowed`、`reading_level_mismatch`、`reading_ambiguous`、`reading_missing`。配置错误用既有 `TemplateFormatError(E1001)`，不当成纪要问题。
- 各函数不修改 minutes/template，不调用模型；同输入同顺序。聚合按 required → forbidden → readings，按配置顺序 / 字段遍历顺序输出，重复调用不累积旧清单。

**直接调用**：`check_template(result.minutes, tpl)` 返回规则 issues；调用者另持有 `result.issues`，不冒充两者已经汇总。`apply_template` 只组织章节，不吞掉检查结果。

**现有 seam 的确切调用法（后续集成测试照此写）**：

```python
# meeting_meta、tpl 是调用方已读取的快照，闭包不访问文件 / DB。
generate = make_generate(generator=lambda payload: apply_template(
    from_graph_payload(payload, meeting_meta=meeting_meta), tpl))
validate = make_validate(validator=lambda structured: check_template(structured, tpl))
assemble = make_assemble(assembler=render_template_markdown)
# validate 的返回仍是 {"validation_issues": [...]}，无需增加 state 字段。
```

`apply_template` 保留 canonical 元信息及 topics，并添加既有 dict 内的 `sections`；不是新增 PipelineState 字段。`from_graph_payload` 将 title→name、text→content，按事项 `topic` 精确等于议题 title 归组，保留 readings/discussion；元信息仅来自显式 meeting_meta，缺的留空。无匹配事项不得丢弃：附入名为「待补充」的末尾议题；不能编造 source_quote/时间戳，缺失保持缺失，交 T2-04 处理。本适配结果只供规则及成文，**不声称是可重新通过严格 schema 的完整抽取结果**。G2 后的新三列表是权威输入，不能拿旧 extraction.minutes 覆盖人工编辑。

本卡不改 `state.py`、`NODE_REQUIRES/NODE_OUTPUTS`、路由或检查点。现有 validate 有问题时仍按既有重试 / give_up 逻辑运行；不新增硬阻断，不保证 naive_validate 的检查等同完整后置校验。T2-04 再组合各类检查与抽取 issues，避免重复和冲突。

### 2.2 必填要素（U-MN-07）

**遍历所选模板每个 required_elements，缺键也必须检查，不能 `if key in minutes` 才检查。**

| 要素 | 从 MinutesSchema 取值 | 有效 / 缺失判据 |
|:---|:---|:---|
| title/meeting_time/location/host/recorder | 顶层同名字符串 | strip 后非空，且不含「待补充」才有效 |
| attendees | 顶层 list[str] | 只计非空且不含「待补充」的字符串；空 / 占位条目不计数 |
| topics | 顶层议题数组 | 只计 name 非空且不含「待补充」的对象；discussion 为空不使议题本身消失 |
| resolutions | **展平 `topics[*].resolutions`** | 只计 content 非空且不含「待补充」的对象；不是取 `minutes.get("resolutions")` |
| action_items / pending_decisions | 分别展平 topics 下同名数组 | 同 resolutions；允许自建模板声明，不修改 schema |

未列出的 key 是模板配置错误（E1001，指出 key），不得静默忽略。非预期类型报 `required_type`；缺键、None、空串、空数组、仅占位条目报一条 `missing_required_element`，例如 **`参会人员缺失`**（label + 缺失）。空值不再重复报 min_count / pattern。

存在有效值时：数组有效项数 `< min_count` 报 `required_min_count`，**等于阈值通过**；未配 min_count 仍须至少一项，`min_count=0` 不取消 required 的存在约束。标量字符串配 min_count 是配置错误，不能按字数猜测。数组中畸形项报对应索引的 type issue，其他项照常计数。

`pattern` 使用 Python `re.search`（无隐式 flags），对 strip 后的标量或每个有效数组项的文本逐一检查：topic 用 name，事项用 content。不得把整个列表 str() 后匹配；`^.{4,30}$` 的锚点由 YAML 控制。失败报 `required_pattern`，含具体路径。非法正则沿用 `domain/template.py:_parse_required_elements` 的解析报错。

> ★ T2-01 的「待补充」是显式缺失，不是已齐备；这里按**包含该标记**判缺失，避免 `会议时间：待补充` 混过检查。`owner="暂无"` 则是合法占位，本卡不重判责任人规则。

### 2.3 禁用表述（U-MN-08）

- 词表来自**所选模板** `style.readings_forbidden`；缺省 `[]`，已配置时必须是非空字符串数组（空白词报配置错），规范化后去重并保序。
- 规则固定为**规范化后的字面子串匹配**：两侧都做 Unicode NFKC → casefold → 去全部 Unicode 空白。不删标点，不做同义词 / 拼音 / 正则 / 模糊匹配。因此「差 不 多」命中「差不多」，「差、不、多」不命中；英文不区分大小写。
- 扫描最终拟输出的 canonical 文本：title、meeting_time、location、host、attendees[*]、recorder、topics[*].name/discussion/readings[*]，以及三类嵌套事项的 content/owner/deadline、pending_decisions.decision_maker。None 跳过；**不扫 source_quote、source_refs/refs、时间戳、issues/detail 或模板标题**，原始引文必须忠实保留。sections 是这些字段的派生展示，不重复扫描。
- 每个 `(字段路径, 规范化禁词)` 一条 issue，同一字段重复出现同词仍一条，不截断其他词。`大家觉得这个方案差不多可以` 在 discussion 中产生两条（大家觉得、差不多）；原文不替换、不删句。若只出现在 source_quote 中为 0 条。

### 2.4 领读语层级（U-MN-09；**规则兜底，不凭模型感觉**）

SAD 只有 `TopicSchema.readings: list[str]`，没有逐句 tag 对应关系。本卡约定：**一个议题的 readings 是 discussion 的领读语标签集合**，不按数组下标配句，也不套到该议题的每条 resolution。渲染为去重后的领读语前缀 + discussion，原 discussion 不改写。

先从 discussion 句首剥离一个配置允许的领读语及紧随的 `，,:：` / 空白，按 `。！？；\n` 分句。关键词做 NFKC，按字面子串命中；以下规则与词表是固定、可测试的最小规则，不是中文语义识别器：

| 优先级 | 分类 | 具体命中词 | 允许层级标签 |
|:--|:---|:---|:---|
| 1 | 决定层 | 决定、议定、审议通过、同意 | 会议决定 / 会议议定 / 会议审议通过 / 会议同意 |
| 2 | 要求层（imperative） | 必须、务必、应当、不得、严禁、抓紧、确保、落实、推进、完成；或去前缀后以「请」「要」开头 | 会议要求 |
| 3 | 强调层 | 重要性、重要意义、基本原则、底线意识 | 会议强调 |
| 4 | 认知层（cognitive） | 是、属于、表明、说明、呈现、总体、形势、可行 | 会议认为 / 会议指出 |
| 5 | unknown | 以上均未命中 | 不推断层级，不强制选语 |

同句多类命中取最高优先级：`形势总体稳定，必须落实责任` 是要求层。多个句子形成不同已知层级则报 `reading_ambiguous`，不自动拆分 / 升格；这不是 SAD §10.4 的事项拆分。

检查顺序固定：

1. readings 中每个标签先查 `style.readings_allowed` **精确字符串白名单**；未列入报 `reading_not_allowed`，不因全局表列了就自动许可（如某模板没有“会议审议通过”）。空白标签按未允许处理。
2. discussion 非空、分类为单一已知层级时，readings 为空报 `reading_missing`；每个有已知层级的标签不在该类允许集合就报 `reading_level_mismatch`。例如 `请完成材料报送` + 会议认为 → mismatch；+ 会议要求 → 通过。
3. `总体形势是稳定的` + 会议认为 / 会议指出 → 通过；+ 会议要求 → mismatch。不能仅因句中含“会议要求”而自证要求层，必须先剥前缀。
4. 白名单中的其他领读语（如会议听取 / 会议研究 / 经协调 / 会议明确 / 会议部署 / 会议审议）不臆造层级：已知内容搭这种标签报 `reading_ambiguous` 请人工确认；unknown 内容只检查白名单，不强报 mismatch。空 discussion 不推断、不补标签。

仅返回 issues / 建议 expected，不自动把“认为”改成“要求”，不让规则提高决议效力。不扩展为责任人、时限、数字、人名一致性检查。

### 2.5 模板选择与 section_order 生效（F3.1 / N5.2）

**选模板的调用合同**：应用调用方读取 meeting 行的 template_id。显式 id 用 `TemplateStore.get`，不存在或 disabled 报 E1001，不能静默换模板；未指定时：调用方若显式提供 meeting_kind，则从 enabled 模板中按 kind 筛选，**恰好一份才自动选择**，零份 / 多份报 E1001 要求指定 id。现有 meeting 没有可靠 kind 输入时，默认固定选 `tpl-regular-meeting-v1`，不从会议标题猜类型。显式 id 优先于 kind，不更改 meeting 表。一次应用只选择一次 tpl 快照，检查 / 章节 / Markdown 使用同一份；下次应用再热读。已保存成稿不因改 YAML 被追改。

**顺序不是只在 API 响应里变**：`apply_template` 必须产出 `sections`，heading 顺序逐项等于 YAML 的 `section_order`；`render_template_markdown` 必须按此输出 `minutes_markdown` 的二级标题。问题清单放在所有模板章节之后。DOCX 继续走现有导出链与版式映射，本卡验收直接断言结构化 sections 和 Markdown；不承诺即时重排已导出的 DOCX。

**标题不能用位置猜内容**。在四 YAML 的既有 `style` 下补外置映射 `section_bindings: {章节标题: 源类型}`（本卡补充），与 section_order 标题一一对应；不把中文标题硬编码在 Python：

| 源类型 | 渲染内容（输入顺序保留） |
|:---|:---|
| meeting_meta | 时间、地点、主持、参会人员、记录人，缺值显示「待补充」 |
| discussions | 按议题 name 建子标题，展示 readings + discussion |
| resolutions | 按议题展示议定 content、owner、deadline；不改引文与 refs |
| actions | 按议题展示 action_items、pending_decisions（明确标“待决策”，不得当决议） |

四类模板各自原有四节依次绑定上述四类；以后**只交换 section_order 两行**，内容跟随标题走。映射缺失 / 多余、重复标题、未知源类型报配置 E1001，不能回退写死顺序。空章节保留标题并显示“待补充”，不伪造事项。新增映射是后续施工对四 YAML 的必要补充，**本次不改配置**；仅保留旧三端点 / parse_template 能读旧模板，应用缺映射的自建模板则清楚报配置错。

U-MN-10 **归本卡**：它属于模板应用的层级结构。`sections` 每节有 `number="1"`，议题子项有 `number="1.1"`，事项有 `number="1.1.1"`；各层从 1 递增、父项变化子计数归 1，最大三级。三级数字编号在**结构化输出**验收。Markdown 用 `## / ###` 配无编号标题、事项用普通编号列表，不造第四级，也不把结构 number 拼进标题文字。DOCX 的 `一、/（一）/1.` 仍由 `domain/docx/style_mapper.py` 的既有编号逻辑负责，避免重复叠加，不要求现有剥编号器识别多段数字前缀。

### 2.6 版本与历史（F7.2）

**保留两来源模型**：DB 自建模板仍 POST 创建 v1、PUT 服务端 +1，忽略客户端版本；builtin 仍禁止 PUT（E1003），由管理员编辑 YAML 并将 `meta.version` +1。不把 builtin 当前值灌进 template 表，不重写 T1-16 CRUD。

补 `002_template_revision.sql`，表 `template_revision` 主键 `(source, template_id, version_no)`，列 `snapshot_json TEXT NOT NULL`、`captured_at TEXT NOT NULL`。快照为完整 `MinutesTemplate.to_dict()`，不是只有名字；历史仅插入 / 查询，禁止覆盖同版正文。`TemplateStore` 增加 `list_versions/get_version`，排序版本升序。DB create/update 与快照写入**同一事务**，更新前补存旧版、更新后存新版；失败整体回滚。迁移为现存 DB 模板保存当前版，已丢失的旧版不可恢复，不伪造 v1。

builtin 每次成功加载时登记尚未登记的当前快照；热读返回仍以 YAML 为准。首次见到只存当前版；同 id 同版本但内容变更 / 版本回退视为配置错，进入既有 load_builtin problems，并使显式选中该模板失败。比较时排除 captured_at 等观测时间，内容必须一致。合法外改先在应用运行中观察旧版，再修改内容和 meta.version 后观察新版，即可查两份。应用未观察到的离线中间版本**无法追溯**，见 §5；这与“不改 Python 即生效”不冲突，但不允许偷改内容不升版本。

历史查询端点补 `GET /templates/{template_id}/versions` 与 `GET /templates/{template_id}/versions/{version_no}`，参数 `source=builtin|db`（缺省按当前 get 的来源；显式 source 可查被屏蔽的 DB 历史），响应沿用信封，分别为 `data.versions` 与 `data.template`；不存在报 E1001。版本必须正整数、source 非法报 E1001；复用既有鉴权，不新增写历史端点。并发写用 DB 事务内读取当前版本再递增，避免两个 PUT 都生成同一新版。相关 IO 均在 infra，领域只校验 / 比较快照内容。

## 7. 常见坑

1. **缺失就跳过**：迭代输入现有键会漏掉 attendees；必须遍历模板 required_elements。把「待补充」算成非空齐备同样是假通过。
2. **重复造 T1-16**：四 YAML、模板 parser、合并读取、三端点、自增都已有；补应用和历史缺口，不能另建 loader / DB 当前值镜像破坏热读。
3. **认错 resolutions 位置**：MinutesSchema 挂在 topics 下，图内才是平铺；必须在显式适配边界转换，不能同一检查函数偷偷猜两种形状。
4. **有词表就叫完成语体对齐**：readings_allowed 只管许可；cognitive / imperative 还须按 §2.4 兜底，模型选错也得返回问题，不自动升格语气。
5. **把抽取日志当问题清单**：ExtractionResult.issues 与 validation_issues 不是同一条传输链。阶段 B 不能往 PipelineState 添 minutes/issues/template 字段来“方便接线”。
6. **只断言 API 顺序就说 N5.2 通过**：调序必须带着内容进入 sections 和 Markdown；按槽位硬绑会出现“标题换了、正文没换”。
7. **version_no 增了就说历史可查**：UPDATE 已覆盖旧正文，审计只存版本号也救不回来。历史必须完整快照、写入原子，不能给旧版 GET 返回当前正文。
8. **禁词扫描破坏证据**：只检查拟成文文本，不改 source_quote，不把原文中的口语当成自动生成的措辞；匹配规则须固定，不能测试用子串、生产用正则。
9. **模板写死本单位名称**：四类模板只含结构 / 通用语体，单位名应来自会议数据。可移植约束不能扩成未经授权的导入导出项目。
10. **用默认图冒充接线成功**：make_generate / make_validate / make_assemble 接关键字参数；Deps 暂无这些属性。seam 测试通过与生产流水线全面接入必须分别陈述。
